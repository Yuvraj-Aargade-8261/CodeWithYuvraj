🚀 Advanced Lens — Part 1

C++ is used to build: game engines (Unreal), browsers (Chrome, Firefox), operating systems (Windows), databases (MySQL, MongoDB), compilers (Clang), financial trading systems, embedded firmware, and AI frameworks (TensorFlow, PyTorch backends). The key philosophy is "zero-cost abstractions" — you don't pay runtime cost for features you don't use. Unlike C, C++ gives you RAII (automatic resource cleanup via destructors), type-safe generics (templates), and value semantics with move — making it both safer and faster than manual C patterns.

Hindi mein samjhoC++ se bante hain: game engines (Unreal), browsers (Chrome), OS (Windows), databases (MySQL), compilers (Clang), trading systems. Key philosophy hai "zero-cost abstractions" — jo feature use nahi karte uska runtime cost nahi. C se different, C++ me RAII (destructors se automatic cleanup), type-safe generics (templates), aur move semantics milte hain — safer aur faster dono.
1.1

History of C++ — Stroustrup, "C with Classes", and evolution

The birth of C++

Bjarne Stroustrup created C++ at Bell Labs in 1979, originally called "C with Classes". His goal: add object-oriented features to C without sacrificing performance. The name "C++" was coined in 1983 (the ++ operator means "increment" — C incremented). C++ has evolved through ISO standards: C++98, C++03, C++11, C++14, C++17, C++20, and C++23.

Hindi mein samjhoBjarne Stroustrup ne 1979 me Bell Labs me C++ banaya, pehle iska naam tha "C with Classes". Goal tha: C me OOP features add karo bina performance sacrifice kiye. "C++" naam 1983 me aaya (++ operator ka matlab hai "increment" — C ka increment). ISO standards: C++98, C++03, C++11, C++14, C++17, C++20, C++23.

C++ vs C — What C++ adds, and why it matters

C++ is a superset of C (mostly)

C++ adds OOP (classes, inheritance, polymorphism), generic programming (templates), RAII (automatic resource management), exceptions, references, namespaces, and a massive standard library (STL). Most valid C code compiles as C++, but C++ encourages safer, more expressive patterns.

Hindi mein samjhoC++ me C se zyada milta hai: OOP (classes, inheritance, polymorphism), generic programming (templates), RAII (automatic resource management), exceptions, references, namespaces, aur massive standard library (STL). Zyada tar valid C code C++ me compile hota hai, par C++ safer aur expressive patterns encourage karta hai.

💻 C vs C++ — Same task, different world
// C way — manual, error-prone
char *name = malloc(100);
strcpy(name, "Yuvraj");
printf("Hello %s\n", name);
free(name);  // Must remember!

// C++ way — safe, automatic
std::string name = "Yuvraj";
std::cout << "Hello " << name << "\n";
// No free needed — string destructor handles it (RAII)
When to use C vs C++? Use C for: bare-metal embedded, OS kernels, tiny microcontrollers. Use C++ for: game engines, desktop apps, servers, anything needing OOP/STL/abstractions with C-level performance.

Setting up GCC/Clang/MSVC & VS Code for C++

Install a C++ compiler

You need a C++ compiler: GCC (g++) on Linux, Clang on macOS, or MSVC on Windows. For cross-platform, install MinGW-w64 on Windows to get g++. Then use VS Code with the C/C++ extension for editing and debugging.

1.4

Structure of a C++ program — namespaces, headers, std::

Anatomy of a C++ program

Every C++ program has: #include directives for headers, an optional using namespace declaration, and a main() function. The std:: prefix means "from the standard library namespace." Using std:: explicitly is best practice in production code.

Hindi mein samjhoHar C++ program me hota hai: headers ke liye #include, optional using namespace, aur main() function. std:: prefix ka matlab hai "standard library namespace se." Production code me explicit std:: use karna best practice hai.
💻 C++ — Program anatomy
// C++ headers — NO .h extension!
#include <iostream>   // cout, cin, cerr
#include <string>     // std::string
#include <vector>     // std::vector
#include <cstdio>     // C's stdio.h in C++ (note the 'c' prefix)

// ❌ Avoid in production — pollutes global namespace
using namespace std;

// ✅ Better — selective using
using std::cout;
using std::string;

// ✅ Best — always use std:: prefix
int main() {
    std::string name = "Yuvraj";
    std::cout << "Hello, " << name << "\n";
    return 0;
}
C headerC++ equivalentExample
stdio.h<cstdio>printf, scanf
stdlib.h<cstdlib>malloc, exit
string.h<cstring>strlen, strcpy
math.h<cmath>sqrt, pow
—<iostream>cout, cin (C++ only)
—<string>std::string (C++ only)
—<vector>std::vector (C++ only)
Never use using namespace std; in header files! It forces every file that includes your header to have the entire std namespace polluted. Use it only in small .cpp files for learning.

Compilation pipeline — g++, linking, header/source separation

How C++ code becomes an executable

C++ compilation follows the same 4-stage pipeline as C: Preprocessing → Compilation → Assembly → Linking. The key difference: C++ has name mangling (for function overloading) and more complex linking due to templates.

Hindi mein samjhoC++ compilation bhi C jaisa 4-stage pipeline follow karta hai: Preprocessing → Compilation → Assembly → Linking. Key difference: C++ me name mangling hota hai (function overloading ke liye) aur templates ki wajah se linking complex hoti hai.

💻 Terminal — Multi-file C++ project
// math_utils.h — HEADER (declarations only)
#pragma once          // Modern include guard
int add(int a, int b);
int multiply(int a, int b);

// math_utils.cpp — SOURCE (definitions)
#include "math_utils.h"
int add(int a, int b) { return a + b; }
int multiply(int a, int b) { return a * b; }

// main.cpp
#include <iostream>
#include "math_utils.h"
int main() {
    std::cout << add(3, 4) << "\n";   // 7
}

# Compile separately, then link:
$ g++ -std=c++17 -c math_utils.cpp -o math_utils.o
$ g++ -std=c++17 -c main.cpp -o main.o
$ g++ math_utils.o main.o -o app
$ ./app   # 7

# Or all at once:
$ g++ -std=c++17 -Wall main.cpp math_utils.cpp -o app
1.6

Basic I/O — cout, cin, cerr, formatting with <iomanip>

C++ I/O streams

std::cout writes to stdout, std::cin reads from stdin, std::cerr writes to stderr. The << operator is "insertion" (output) and >> is "extraction" (input). Unlike printf, cout is type-safe — no format specifiers needed.

Hindi mein samjhostd::cout stdout pe likhta hai, std::cin stdin se padhta hai, std::cerr stderr pe likhta hai. << operator "insertion" hai (output) aur >> "extraction" (input). Printf se different, cout type-safe hai — format specifiers ki zaroorat nahi.
💻 C++ — I/O operations
#include <iostream>
#include <iomanip>    // Formatting manipulators
#include <string>

int main() {
    // Output — chaining with <<
    std::cout << "Name: " << "Yuvraj" << ", Age: " << 21 << "\n";

    // Input
    std::string name;
    int age;
    std::cout << "Enter name and age: ";
    std::cin >> name >> age;    // Space-delimited

    // Read full line (including spaces)
    std::cin.ignore();           // Clear leftover newline
    std::string line;
    std::getline(std::cin, line);

    // Error output
    std::cerr << "Error: file not found\n";

    // Formatting with <iomanip>
    double pi = 3.14159265;
    std::cout << std::fixed << std::setprecision(2) << pi << "\n";  // 3.14
    std::cout << std::setw(10) << std::right << 42 << "\n";          //         42
    std::cout << std::hex << 255 << "\n";                          // ff
    std::cout << std::dec << 255 << "\n";                          // 255
    std::cout << std::boolalpha << true << "\n";                   // true
}
ManipulatorEffectHeader

"\n"Newline (faster, no flush)—

std::setprecision(n)Decimal places<iomanip>

Performance tip: Use "\n" instead of std::endl. endl forces a buffer flush which is slow in loops. For competitive programming, add std::ios::sync_with_stdio(false); at the start.
1.7

Data types, auto, type inference, const & constexpr

C++ type system

C++ inherits C's types and adds: bool, std::string, auto (compiler deduces type), const (immutable), and constexpr (computed at compile time). Modern C++ encourages "Almost Always Auto" (AAA) style for cleaner code.

Hindi mein samjhoC++ me C ke types hain plus: bool, std::string, auto (compiler type guess karta hai), const (change nahi hoga), constexpr (compile time pe calculate). Modern C++ me "Almost Always Auto" style use hota hai.
💻 C++ — Types, auto, const, constexpr
// Fundamental types (same as C)
int x = 42;
double pi = 3.14;
char ch = 'A';
bool flag = true;         // C++ native bool (not int!)

// std::string — safe, dynamic string
std::string name = "Yuvraj";
std::string greeting = "Hello, " + name;  // Concatenation with +
std::cout << name.length() << "\n";      // 6

// auto — compiler deduces type (C++11)
auto a = 42;              // int
auto b = 3.14;            // double
auto c = "hello";         // const char* (NOT std::string!)
auto d = std::string("hello");  // std::string
auto e = true;            // bool

// const — immutable after initialization
const int MAX = 100;      // Cannot be changed
const auto PI = 3.14159; // auto + const

// constexpr — COMPILE-TIME constant (C++11)
constexpr int square(int x) { return x * x; }
constexpr int val = square(5);  // 25 — computed at compile time!
int arr[square(3)];             // Array of size 9 — works!

// Uniform initialization (C++11) — prefer braces {}
int x1 = 42;       // Copy init
int x2(42);        // Direct init
int x3{42};        // Uniform init ✅ (prevents narrowing)
// int x4{3.14};   // ❌ ERROR — narrowing conversion blocked!
KeywordWhen evaluatedUse case
constRuntime or compile-timeValues that shouldn't change after init
constexprCompile-time guaranteedArray sizes, template args, zero-cost computation
consteval (C++20)MUST be compile-timeEnforce compile-time only functions
constinit (C++20)Static init at compile-timeAvoid static init order fiasco
Rule: Use const by default. Use constexpr when the value CAN be computed at compile time. Use auto when the type is obvious from the right side. Never use auto when the type isn't clear.
✏️ Practice Exercises — Part 1 (Difficulty Graded)

🟢 Easy (Do these first)

  1. Write a C++ program that prints "Hello, C++ World!" using std::cout. Compile with g++ -std=c++17 -Wall -Wextra.
  2. Create a program that reads a name and age from the user using std::cin, then prints a greeting using std::string concatenation.
  3. Compare C vs C++ I/O: write the same program using both printf/scanf and std::cout/std::cin. Note the type-safety difference.
  4. Declare variables using auto, const, and constexpr. Print their types using typeid(x).name(). Explain why auto c = "hello" is const char* not std::string.

🟡 Medium (Apply your knowledge)

  1. Create a multi-file project (main.cpp, utils.h, utils.cpp). Use #pragma once. Compile and link them separately with g++.
  2. Use <iomanip> to print a multiplication table (1–12) with aligned columns using std::setw.
  3. Write a constexpr function that calculates factorial. Verify it works as an array size at compile time. Compare with a non-constexpr version.
  4. Demonstrate uniform initialization: show how int x{3.14} prevents narrowing while int x = 3.14 silently truncates.

🔴 Hard (Challenge yourself)

  1. Write a program that uses all 4 C++ initialization syntaxes (copy, direct, uniform, list). Explain when each is preferred and which prevents narrowing.
  2. Create a custom namespace (mylib) with 3 utility functions. Use both mylib::func() and using mylib::func patterns. Explain why using namespace in headers is dangerous.
  3. Benchmark std::endl vs "\n": print 1 million lines to a file with each. Measure time with std::chrono. Calculate the performance difference.
  4. Write a program that demonstrates the C++ compilation pipeline: use g++ -E, g++ -S, g++ -c, and g++ to see preprocessed, assembly, object, and final output for a simple file.
