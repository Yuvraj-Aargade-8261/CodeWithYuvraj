4.1

Inheritance — single, multilevel, access specifiers

Reusing code through inheritance

Inheritance lets a derived class reuse and extend a base class. The derived class inherits all members and can add new ones or override existing behavior. Access specifiers (public/protected/private) control what the derived class can see.

Hindi mein samjhoInheritance se derived class base class ka code reuse aur extend kar sakti hai. Derived class saare members inherit karti hai aur naye add ya existing override kar sakti hai. Access specifiers control karte hain ki derived class kya dekh sakti hai.
💻 C++ — Inheritance basics
class Animal {
protected:
    std::string name_;
    int age_;
public:
    Animal(std::string name, int age)
        : name_(std::move(name)), age_(age) {}

    void info() const {
        std::cout << name_ << ", age " << age_ << "\n";
    }
};

// Public inheritance — "is-a" relationship
class Dog : public Animal {
private:
    std::string breed_;
public:
    Dog(std::string name, int age, std::string breed)
        : Animal(std::move(name), age), breed_(std::move(breed)) {}

    void bark() const {
        std::cout << name_ << " says Woof!\n";  // Can access protected
    }
};

// Multilevel inheritance
class GuideDog : public Dog {
public:
    using Dog::Dog;  // Inherit constructors
    void guide() const {
        std::cout << name_ << " is guiding\n";
    }
};

Dog d("Rex", 3, "Labrador");
d.info();   // Inherited from Animal
d.bark();   // Own method

4.2

Virtual functions & vtable — dynamic dispatch

Runtime polymorphism

A virtual function enables dynamic dispatch — the correct function is called based on the actual object type at runtime, not the pointer/reference type. This is implemented via a vtable (virtual function table). Always use override in derived classes.

Hindi mein samjhovirtual function dynamic dispatch enable karta hai — sahi function runtime pe actual object type ke basis pe call hota hai, pointer type ke basis pe nahi. Ye vtable ke through implement hota hai. Derived classes me hamesha override use karo.
💻 C++ — Virtual functions
class Shape {
public:
    virtual double area() const { return 0; }
    virtual void draw() const {
        std::cout << "Drawing shape\n";
    }
    virtual ~Shape() = default;  // ALWAYS virtual destructor!
};

class Circle : public Shape {
    double radius_;
public:
    explicit Circle(double r) : radius_(r) {}

    double area() const override {   // override = compiler checks!
        return 3.14159 * radius_ * radius_;
    }
    void draw() const override {
        std::cout << "Drawing circle r=" << radius_ << "\n";
    }
};

class Rectangle : public Shape {
    double w_, h_;
public:
    Rectangle(double w, double h) : w_(w), h_(h) {}
    double area() const override { return w_ * h_; }
    void draw() const override {
        std::cout << "Drawing rect " << w_ << "x" << h_ << "\n";
    }
};

// Polymorphism in action — base pointer, derived behavior
std::vector<std::unique_ptr<Shape>> shapes;
shapes.push_back(std::make_unique<Circle>(5));
shapes.push_back(std::make_unique<Rectangle>(3, 4));

for (const auto& s : shapes) {
    s->draw();   // Calls correct draw() at runtime!
    std::cout << "Area: " << s->area() << "\n";
}
Always make base class destructors virtual! Without it, delete basePtr only calls the base destructor — derived resources leak. Rule: if a class has ANY virtual function, its destructor must be virtual.
4.3

Abstract classes & pure virtual — interfaces in C++

Defining contracts with pure virtual functions

A pure virtual function (= 0) has no implementation in the base class. A class with any pure virtual function is abstract — you can't instantiate it. Derived classes MUST override all pure virtual functions. This is how C++ implements interfaces.

Hindi mein samjhoPure virtual function (= 0) ka base class me koi implementation nahi hota. Agar class me koi bhi pure virtual function hai to wo abstract hai — uska object nahi ban sakta. Derived classes ko saare pure virtual functions override karne hi padenge. C++ me interfaces aise bante hain.
💻 C++ — Abstract classes & interfaces
// Interface — all pure virtual
class ISerializable {
public:
    virtual std::string serialize() const = 0;     // Pure virtual
    virtual void deserialize(const std::string&) = 0;
    virtual ~ISerializable() = default;
};

// Abstract base with some implementation
class Shape {
public:
    virtual double area() const = 0;   // Must override
    virtual void draw() const = 0;     // Must override

    // Concrete method — shared by all derived
    void describe() const {
        std::cout << "Shape with area " << area() << "\n";
    }
    virtual ~Shape() = default;
};

// Shape s;  // ❌ ERROR — abstract, can't instantiate!

class Triangle : public Shape {
    double base_, height_;
public:
    Triangle(double b, double h) : base_(b), height_(h) {}
    double area() const override { return 0.5 * base_ * height_; }
    void draw() const override { std::cout << "△\n"; }
};

Triangle t(10, 5);
t.describe();  // "Shape with area 25" — uses concrete base method

4.4

Multiple inheritance — diamond problem, virtual inheritance

Inheriting from multiple bases

C++ allows a class to inherit from multiple base classes. The diamond problem occurs when two bases share a common grandparent — the derived class gets two copies. Solve with virtual inheritance.

Hindi mein samjhoC++ me ek class multiple base classes se inherit kar sakti hai. Diamond problem tab hota hai jab do bases ka ek common grandparent ho — derived class ko do copies milti hain. Virtual inheritance se solve karo.
💻 C++ — Diamond problem & virtual inheritance
// Diamond problem
class Animal {
public:
    std::string name_;
    Animal(std::string n) : name_(std::move(n)) {}
};

// Virtual inheritance — only ONE Animal subobject
class Mammal : virtual public Animal {
public:
    Mammal(std::string n) : Animal(std::move(n)) {}
    void breathe() { std::cout << "Breathing\n"; }
};

class WingedAnimal : virtual public Animal {
public:
    WingedAnimal(std::string n) : Animal(std::move(n)) {}
    void fly() { std::cout << "Flying\n"; }
};

// Bat inherits both — only ONE copy of Animal
class Bat : public Mammal, public WingedAnimal {
public:
    // Must initialize virtual base directly!
    Bat(std::string n)
        : Animal(std::move(n)), Mammal(""), WingedAnimal("") {}
};

Bat b("Bruce");
b.breathe();           // From Mammal
b.fly();               // From WingedAnimal
std::cout << b.name_;  // ONE name_ — no ambiguity!

Industry advice: Avoid multiple inheritance of concrete classes. Use it mainly for mixing in interfaces (abstract classes with = 0 methods). Prefer composition over complex inheritance hierarchies.
4.5

CRTP — Curiously Recurring Template Pattern

Static polymorphism — zero overhead

CRTP is when a class inherits from a template instantiated with itself: class Dog : Base<Dog>. This enables static polymorphism — the correct function is resolved at compile time with zero vtable overhead. Used in Eigen, ATL, and high-performance libraries.

Hindi mein samjhoCRTP me class apne aap ko template parameter ke roop me pass karti hai: class Dog : Base<Dog>. Ye static polymorphism enable karta hai — sahi function compile time pe resolve hota hai bina vtable overhead ke. Eigen, ATL jaise libraries me use hota hai.
💻 C++ — CRTP pattern
// CRTP base — knows derived type at compile time
template<typename Derived>
class Shape {
public:
    void draw() const {
        // Call derived's implementation — NO virtual!
        static_cast<const Derived*>(this)->draw_impl();
    }

    double area() const {
        return static_cast<const Derived*>(this)->area_impl();
    }
};

class Circle : public Shape<Circle> {
    double r_;
public:
    explicit Circle(double r) : r_(r) {}
    void draw_impl() const { std::cout << "Circle\n"; }
    double area_impl() const { return 3.14159 * r_ * r_; }
};

// Usage — resolved at compile time, zero overhead!
Circle c(5);
c.draw();   // "Circle" — no vtable lookup!

4.6

dynamic_cast, typeid, RTTI — runtime type identification

Inspecting types at runtime

dynamic_cast safely casts base pointers to derived at runtime (returns nullptr on failure). typeid gives the type name. Both require RTTI and at least one virtual function. Use sparingly — prefer virtual dispatch.

Hindi mein samjhodynamic_cast runtime pe base pointer ko safely derived me cast karta hai (fail pe nullptr return). typeid type ka naam deta hai. Dono ke liye RTTI aur kam se kam ek virtual function chahiye. Kam use karo — virtual dispatch prefer karo.
💻 C++ — RTTI & dynamic_cast
class Base {
public:
    virtual ~Base() = default;
};
class Derived : public Base {
public:
    void special() { std::cout << "Special!\n"; }
};

Base* ptr = new Derived();

// dynamic_cast — safe downcasting
if (auto* d = dynamic_cast<Derived*>(ptr)) {
    d->special();  // Safe — only if ptr IS a Derived
} else {
    std::cout << "Not a Derived\n";
}

// typeid — get type info
std::cout << typeid(*ptr).name() << "\n";  // "Derived" (mangled)

// Compare types
if (typeid(*ptr) == typeid(Derived)) {
    std::cout << "It's a Derived!\n";
}
delete ptr;
4.7

Design patterns — Factory, Singleton, Observer in C++

Industry patterns using polymorphism

Design patterns are reusable solutions to common problems. Factory creates objects without exposing creation logic. Singleton ensures one instance. Observer implements publish-subscribe. These are interview favorites.

Hindi mein samjhoDesign patterns common problems ke reusable solutions hain. Factory creation logic hide karke objects banata hai. Singleton ek hi instance ensure karta hai. Observer publish-subscribe implement karta hai. Ye interview favorites hain.
💻 C++ — Factory pattern
// Factory — create objects by type string
class Shape {
public:
    virtual void draw() const = 0;
    virtual ~Shape() = default;

    // Static factory method
    static std::unique_ptr<Shape> create(const std::string& type);
};

class Circle : public Shape {
public:
    void draw() const override { std::cout << "●\n"; }
};
class Square : public Shape {
public:
    void draw() const override { std::cout << "■\n"; }
};

std::unique_ptr<Shape> Shape::create(const std::string& type) {
    if (type == "circle") return std::make_unique<Circle>();
    if (type == "square") return std::make_unique<Square>();
    throw std::invalid_argument("Unknown: " + type);
}

auto s = Shape::create("circle");
s->draw();  // ●
💻 C++ — Meyer's Singleton (thread-safe)
class Logger {
public:
    static Logger& instance() {
        static Logger inst;  // Thread-safe in C++11!
        return inst;
    }

    void log(const std::string& msg) {
        std::cout << "[LOG] " << msg << "\n";
    }

    // Delete copy/move to enforce single instance
    Logger(const Logger&) = delete;
    Logger& operator=(const Logger&) = delete;

private:
    Logger() = default;
};

Logger::instance().log("App started");
