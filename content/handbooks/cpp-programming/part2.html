2.1

Operators, precedence & the spaceship operator <=> (C++20)

C++ operators

C++ inherits all C operators and adds: <=> (three-way comparison, C++20), scope resolution ::, new/delete, typeid, dynamic_cast, and the ability to overload most operators for custom types.

Hindi mein samjhoC++ me C ke saare operators hain plus: <=> (three-way comparison, C++20), scope resolution ::, new/delete, typeid, dynamic_cast, aur custom types ke liye operator overloading.
💻 C++ — Spaceship operator (C++20)
#include <compare>   // C++20
#include <iostream>

struct Point {
    int x, y;
    // One operator generates ==, !=, <, >, <=, >= automatically!
    auto operator<=>(const Point&) const = default;
};

int main() {
    Point a{1, 2}, b{3, 4};
    std::cout << (a < b) << "\n";    // 1 (true)
    std::cout << (a == b) << "\n";   // 0 (false)

    // Three-way comparison result
    auto result = 5 <=> 10;
    if (result < 0) std::cout << "less\n";
    else if (result > 0) std::cout << "greater\n";
    else std::cout << "equal\n";
}

2.2

Conditionals — if/else, switch, if constexpr, init-if

Modern conditional patterns

C++ adds if constexpr (compile-time branching for templates, C++17) and init-if (declare variables inside if statements, C++17). These make code cleaner and reduce scope pollution.

Hindi mein samjhoC++ me if constexpr (compile-time branching templates ke liye, C++17) aur init-if (if statement me variables declare, C++17) add hue. Ye code cleaner banate hain aur scope pollution kam karte hain.
💻 C++ — Conditional patterns
// Standard if/else — same as C
if (x > 0) {
    std::cout << "positive\n";
} else if (x < 0) {
    std::cout << "negative\n";
} else {
    std::cout << "zero\n";
}

// Init-if (C++17) — variable scoped to if block
if (auto it = map.find("key"); it != map.end()) {
    std::cout << it->second << "\n";
}
// 'it' doesn't exist here — no scope leak!

// if constexpr (C++17) — compile-time branching
template<typename T>
void process(T value) {
    if constexpr (std::is_integral_v<T>) {
        std::cout << "Integer: " << value << "\n";
    } else if constexpr (std::is_floating_point_v<T>) {
        std::cout << "Float: " << value << "\n";
    } else {
        std::cout << "Other type\n";
    }
}

// Switch — same as C but prefer enum class
enum class Color { Red, Green, Blue };
Color c = Color::Red;
switch (c) {
    case Color::Red:   std::cout << "Red\n";   break;
    case Color::Green: std::cout << "Green\n"; break;
    case Color::Blue:  std::cout << "Blue\n";  break;
}
2.3

Loops — range-based for, structured bindings, algorithms

Modern C++ loops

C++ adds range-based for (iterate over any container without indices) and structured bindings (C++17, decompose pairs/tuples). In modern C++, prefer range-for over raw index loops, and STL algorithms over manual loops.

Hindi mein samjhoC++ me range-based for (kisi bhi container pe iterate bina index ke) aur structured bindings (C++17, pairs/tuples decompose) add hue. Modern C++ me range-for prefer karo raw index loops se, aur STL algorithms manual loops se.
💻 C++ — Loop patterns
#include <vector>
#include <map>
#include <iostream>

std::vector<int> nums = {1, 2, 3, 4, 5};

// ❌ C-style — verbose, error-prone
for (int i = 0; i < nums.size(); i++) {
    std::cout << nums[i] << " ";
}

// ✅ Range-based for — clean, safe
for (int n : nums) {
    std::cout << n << " ";            // Copy each element
}

// ✅ By const reference — no copy, safe
for (const auto& n : nums) {
    std::cout << n << " ";
}

// ✅ Modify in-place with reference
for (auto& n : nums) {
    n *= 2;                          // Doubles each element
}

// Structured bindings (C++17) — decompose pairs
std::map<std::string, int> ages = {{"Alice", 25}, {"Bob", 30}};
for (const auto& [name, age] : ages) {
    std::cout << name << ": " << age << "\n";
}

// while and do-while — same as C
while (condition) { /* ... */ }
do { /* ... */ } while (condition);
Rule: Use for (const auto& x : container) as your default loop. Use auto& only when modifying. Use index loops only when you need the index.
2.4

Functions — overloading, default arguments, inline

Function overloading

C++ allows multiple functions with the same name but different parameter types or counts. The compiler chooses the correct one at compile time. This is impossible in C (which uses name mangling differently).

Hindi mein samjhoC++ me same naam ke multiple functions ho sakte hain agar parameter types ya count alag ho. Compiler compile time pe sahi function choose karta hai. C me ye possible nahi tha.
💻 C++ — Function overloading
// Same name, different parameters — compiler resolves
int add(int a, int b) { return a + b; }
double add(double a, double b) { return a + b; }
std::string add(std::string a, std::string b) { return a + b; }

add(1, 2);           // Calls int version → 3
add(1.5, 2.5);       // Calls double version → 4.0
add("Hi"s, " World"s); // Calls string version → "Hi World"

// Default arguments — right to left
void greet(std::string name, std::string greeting = "Hello") {
    std::cout << greeting << ", " << name << "!\n";
}
greet("Yuvraj");             // "Hello, Yuvraj!"
greet("Yuvraj", "Namaste"); // "Namaste, Yuvraj!"

// inline — hint to expand at call site (avoid function call overhead)
inline int square(int x) { return x * x; }

// Trailing return type (C++11) — useful with templates
auto multiply(int a, double b) -> double {
    return a * b;
}

// auto return type deduction (C++14)
auto divide(double a, double b) {
    return a / b;  // Compiler deduces → double
}

2.5

References vs pointers — &, const&, rvalue refs &&

References: the safer alternative to pointers

A reference is an alias for an existing variable. Unlike pointers: references can't be null, can't be reassigned, and don't need dereferencing. Use const& to pass large objects without copying. Rvalue references (&&) enable move semantics (Part 3).

Hindi mein samjhoReference ek existing variable ka alias hai. Pointers se different: references null nahi ho sakte, reassign nahi ho sakte, aur dereference ki zaroorat nahi. const& se bade objects bina copy kiye pass karo. Rvalue references (&&) move semantics enable karte hain (Part 3).
💻 C++ — References
// Lvalue reference — alias for existing variable
int x = 42;
int& ref = x;    // ref IS x (not a copy!)
ref = 100;       // x is now 100
std::cout << x;  // 100

// ❌ References MUST be initialized
// int& bad;     // ERROR — no dangling refs!

// Pass by reference — modify original
void doubleIt(int& n) { n *= 2; }
int val = 5;
doubleIt(val);   // val is now 10

// Pass by const reference — read-only, no copy
void print(const std::string& s) {
    std::cout << s << "\n";
    // s[0] = 'X';  // ❌ ERROR — const!
}

// When to use what:
void f1(int x);              // Small types → pass by value
void f2(const std::string& s); // Large types → const ref
void f3(int& out);            // Need to modify → ref
void f4(int* ptr);            // Optional/nullable → pointer

// Rvalue reference (C++11) — binds to temporaries
int&& rref = 42;             // OK — binds to temporary
// int&& bad = x;             // ❌ ERROR — x is lvalue
int&& moved = std::move(x);  // Cast lvalue to rvalue
FeaturePointer (*)Reference (&)
Can be null?✅ Yes❌ No — always valid
Reassignable?✅ Yes❌ No — bound once
Needs deref?✅ *ptr❌ Use directly
Arithmetic?✅ ptr++❌ Not possible
Array decay?✅ Common❌ Preserves type
Use caseOptional params, ownershipAliases, function params
Modern C++ rule: Prefer references over pointers. Use const& for input parameters. Use pointers only when the parameter is optional (could be nullptr) or when you need pointer arithmetic.
2.6

Namespaces — nested, using, anonymous, ADL

Organizing code with namespaces

Namespaces prevent name collisions in large projects. The standard library lives in std::. You can create your own, nest them, and use anonymous namespaces for file-local scope (replaces C's static).

Hindi mein samjhoNamespaces large projects me name collisions rokne ke liye hain. Standard library std:: me rehti hai. Apne namespaces bana sakte ho, nest kar sakte ho, aur anonymous namespaces file-local scope ke liye use karo (C ke static ki jagah).
💻 C++ — Namespaces
// Custom namespace
namespace math {
    double pi() { return 3.14159265; }
    int square(int x) { return x * x; }
}
std::cout << math::pi() << "\n";

// Nested namespaces (C++17 shorthand)
namespace company::project::module {
    void init() { /* ... */ }
}
company::project::module::init();

// Using declaration — bring specific names
using math::pi;
std::cout << pi() << "\n";  // No prefix needed

// Anonymous namespace — file-local (replaces C static)
namespace {
    int internal_counter = 0;  // Only visible in this file
}

// Namespace alias
namespace fs = std::filesystem;
fs::path p = "/home/user";
2.7

Error handling — exceptions, try/catch, noexcept

Exception handling

C++ uses try/catch/throw for error handling. Exceptions separate error-handling code from normal flow. Mark functions that never throw with noexcept — this enables compiler optimizations and is required for move constructors.

Hindi mein samjhoC++ me try/catch/throw error handling ke liye use hota hai. Exceptions error-handling code ko normal flow se separate karte hain. noexcept mark karo un functions pe jo kabhi throw nahi karte — ye compiler optimizations enable karta hai.
💻 C++ — Exception handling
#include <stdexcept>
#include <iostream>

double divide(double a, double b) {
    if (b == 0.0)
        throw std::invalid_argument("Division by zero!");
    return a / b;
}

int main() {
    try {
        std::cout << divide(10, 0) << "\n";
    }
    catch (const std::invalid_argument& e) {
        std::cerr << "Error: " << e.what() << "\n";
    }
    catch (const std::exception& e) {
        std::cerr << "Unexpected: " << e.what() << "\n";
    }
    catch (...) {
        std::cerr << "Unknown error!\n";
    }
}

// noexcept — promise this function never throws
int add(int a, int b) noexcept {
    return a + b;
}

// Custom exception class
class FileError : public std::runtime_error {
public:
    FileError(const std::string& msg)
        : std::runtime_error("File error: " + msg) {}
};
throw FileError("config.txt not found");
Exception classHeaderUse case
std::exception<exception>Base class for all

RAII + exceptions = safety. If you use RAII (smart pointers, std::string, std::vector), exceptions are safe — destructors auto-cleanup during stack unwinding. Without RAII, exceptions leak resources!
