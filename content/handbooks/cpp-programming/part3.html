🚀 Advanced Lens — Part 3

Enterprise-grade C++ object design is ownership-first: constructors establish invariants, copy/move rules are intentional, and RAII controls lifetime deterministically. Under the hood, a class with virtual functions has a vtable pointer (8 bytes overhead). Understanding object layout — data alignment, vtable, and the copy-and-swap idiom — is what separates junior from senior C++ engineers.

Hindi mein samjhoAdvanced C++ OOP ka core ownership aur lifetime management hai. Virtual functions wali class me vtable pointer hota hai (8 bytes overhead). Object layout — data alignment, vtable, aur copy-and-swap idiom samajhna junior aur senior C++ engineers me farak karta hai.

3.1

Classes & objects — constructors, destructors, this pointer

Defining a class

A class bundles data (member variables) and behavior (member functions) together. The constructor initializes objects, the destructor cleans up. Use member initializer lists for efficient construction.

Hindi mein samjhoClass data (member variables) aur behavior (member functions) ko ek saath bundle karta hai. Constructor objects initialize karta hai, destructor cleanup karta hai. Efficient construction ke liye member initializer lists use karo.
💻 C++ — Class fundamentals
class Student {
private:
    std::string name_;
    int age_;
    double gpa_;

public:
    // Default constructor
    Student() : name_("Unknown"), age_(0), gpa_(0.0) {
        std::cout << "Default ctor\n";
    }

    // Parameterized constructor — use initializer list!
    Student(std::string name, int age, double gpa)
        : name_(std::move(name)), age_(age), gpa_(gpa) {
        std::cout << "Param ctor: " << name_ << "\n";
    }

    // Destructor — called when object goes out of scope
    ~Student() {
        std::cout << "Destructor: " << name_ << "\n";
    }

    // Getter
    const std::string& name() const { return name_; }
    int age() const { return age_; }

    // Setter
    void set_gpa(double g) { gpa_ = g; }

    // Method using 'this' pointer
    Student& set_name(const std::string& n) {
        this->name_ = n;
        return *this;  // Return *this for chaining
    }

    void print() const {
        std::cout << name_ << ", " << age_ << ", GPA: " << gpa_ << "\n";
    }
};

// Usage
Student s1;                           // Default ctor
Student s2("Yuvraj", 21, 9.2);       // Param ctor
Student s3{"Alice", 20, 8.5};       // Uniform init ✅
s2.set_name("Yuvraj A").set_gpa(9.5); // Method chaining
Always use member initializer lists (the : name_(n), age_(a) syntax) instead of assignment in the constructor body. It's more efficient — avoids default-construct-then-assign.
3.2

Access control — public, private, protected, friend

Encapsulation

Encapsulation hides internal data and exposes only a controlled interface. private = only this class, protected = this class + derived, public = everyone. friend grants private access to specific functions/classes.

Hindi mein samjhoEncapsulation internal data hide karta hai aur sirf controlled interface expose karta hai. private = sirf ye class, protected = ye class + derived, public = sabke liye. friend specific functions/classes ko private access deta hai.
💻 C++ — Access control & friend
class BankAccount {
private:
    std::string owner_;
    double balance_;   // Only accessible inside class

public:
    BankAccount(std::string owner, double bal)
        : owner_(std::move(owner)), balance_(bal) {}

    void deposit(double amt) {
        if (amt > 0) balance_ += amt;
    }

    bool withdraw(double amt) {
        if (amt > 0 && amt <= balance_) {
            balance_ -= amt;
            return true;
        }
        return false;
    }

    double balance() const { return balance_; }

    // Friend function — can access private members
    friend void audit(const BankAccount& acc);

    // Friend class
    friend class Auditor;
};

void audit(const BankAccount& acc) {
    std::cout << acc.owner_ << ": $" << acc.balance_ << "\n";
    // Direct access to private members! (because friend)
}

3.3

Operator overloading — +, <<, [], (), ==

Making custom types feel native

C++ lets you define how operators work with your classes. This makes custom types feel like built-in types: vec1 + vec2, cout << obj, obj[i]. Overload as member functions or free functions.

Hindi mein samjhoC++ me custom types ke liye operators define kar sakte ho. Isse custom types built-in types jaise lagti hain: vec1 + vec2, cout << obj, obj[i]. Member functions ya free functions se overload karo.
💻 C++ — Operator overloading
class Vec2 {
public:
    double x, y;

    Vec2(double x = 0, double y = 0) : x(x), y(y) {}

    // + operator (member function)
    Vec2 operator+(const Vec2& other) const {
        return {x + other.x, y + other.y};
    }

    // == operator (C++20: auto-generates !=)
    bool operator==(const Vec2& other) const = default;

    // [] operator
    double& operator[](int i) {
        return i == 0 ? x : y;
    }

    // () operator — functor
    double operator()() const {
        return std::sqrt(x*x + y*y);  // Magnitude
    }
};

// << operator — must be free function (cout is left operand)
std::ostream& operator<<(std::ostream& os, const Vec2& v) {
    return os << "(" << v.x << ", " << v.y << ")";
}

// Usage
Vec2 a{1, 2}, b{3, 4};
Vec2 c = a + b;               // (4, 6)
std::cout << c << "\n";       // (4, 6)
std::cout << c() << "\n";     // 7.211 (magnitude)
std::cout << c[0] << "\n";    // 4

3.4

Copy semantics — copy constructor, copy assignment, Rule of 3

How objects get copied

When you copy an object, the copy constructor creates a new one, and copy assignment replaces an existing one. If your class manages a resource (raw pointer, file handle), you MUST define both — otherwise you get double-free bugs. This is the Rule of 3: if you define any of destructor/copy ctor/copy assign, define all three.

Hindi mein samjhoObject copy hone pe copy constructor naya banata hai, copy assignment existing replace karta hai. Agar class resource manage karti hai (raw pointer, file handle), to dono define karna zaroori hai — nahi to double-free bugs aayenge. Rule of 3: destructor/copy ctor/copy assign me se koi ek define karo to teeno define karo.
💻 C++ — Copy semantics & Rule of 3
class Buffer {
private:
    int* data_;
    size_t size_;

public:
    // Constructor
    explicit Buffer(size_t size)
        : data_(new int[size]{}), size_(size) {}

    // Destructor
    ~Buffer() { delete[] data_; }

    // Copy constructor — DEEP copy
    Buffer(const Buffer& other)
        : data_(new int[other.size_]), size_(other.size_) {
        std::copy(other.data_, other.data_ + size_, data_);
    }

    // Copy assignment — copy-and-swap idiom
    Buffer& operator=(Buffer other) {  // Pass by value!
        std::swap(data_, other.data_);
        std::swap(size_, other.size_);
        return *this;
    }  // old data destroyed when 'other' goes out of scope

    size_t size() const { return size_; }
    int& operator[](size_t i) { return data_[i]; }
};

Buffer a(10);
a[0] = 42;
Buffer b = a;       // Copy ctor — b has its own memory
Buffer c(5);
c = a;             // Copy assign — c's old memory freed, new copy
Without custom copy: the default copy does a shallow (memberwise) copy. Two objects point to the same memory → first destructor frees it → second destructor = undefined behavior!
3.5

Move semantics — move constructor, std::move, Rule of 5/0

Stealing resources instead of copying

Move semantics (C++11) let you transfer ownership of resources from one object to another without copying. The move constructor and move assignment "steal" the internals of a temporary. This is a massive performance win for containers and strings.

Hindi mein samjhoMove semantics (C++11) se resources ka ownership ek object se dusre me bina copy kiye transfer hota hai. Move constructor aur move assignment temporary ke internals "chura" lete hain. Containers aur strings ke liye massive performance win hai.
💻 C++ — Move semantics (Rule of 5)
class Buffer {
    int* data_;
    size_t size_;
public:
    // ... (constructor, destructor, copy ctor, copy assign from 3.4)

    // Move constructor — steal resources
    Buffer(Buffer&& other) noexcept
        : data_(other.data_), size_(other.size_) {
        other.data_ = nullptr;  // Leave source in valid state
        other.size_ = 0;
    }

    // Move assignment
    Buffer& operator=(Buffer&& other) noexcept {
        if (this != &other) {
            delete[] data_;           // Free old resource
            data_ = other.data_;      // Steal
            size_ = other.size_;
            other.data_ = nullptr;   // Nullify source
            other.size_ = 0;
        }
        return *this;
    }
};

// std::move — cast lvalue to rvalue reference
Buffer a(1000000);
Buffer b = std::move(a);  // Move ctor — near instant!
// 'a' is now empty (valid but unspecified state)

// Move is automatic for temporaries
Buffer createBuffer() {
    Buffer temp(100);
    return temp;  // Moved (or RVO eliminates copy entirely)
}
RuleWhat to defineWhen
Rule of 0Nothing — use smart ptrs/STLPrefer this! No raw resources
Rule of 3Destructor + Copy ctor + Copy assignC++98 resource management
Rule of 5Rule of 3 + Move ctor + Move assignC++11+ with raw resources
Prefer Rule of 0! Use std::vector, std::string, std::unique_ptr as members. The compiler generates correct copy/move/destruct automatically. Only use Rule of 5 when writing low-level containers.
3.6

Static members, const methods, mutable keyword

Class-level vs instance-level

static members belong to the class, not individual objects. const methods promise not to modify the object. mutable allows modification even in const methods (useful for caching).

Hindi mein samjhostatic members class ke hain, individual objects ke nahi. const methods promise karte hain ki object modify nahi karenge. mutable const methods me bhi modification allow karta hai (caching ke liye useful).
💻 C++ — Static, const, mutable
class Connection {
private:
    static int count_;           // Shared across ALL objects
    std::string host_;
    mutable int access_count_;   // Can change even in const methods

public:
    Connection(std::string host) : host_(std::move(host)), access_count_(0) {
        count_++;
    }
    ~Connection() { count_--; }

    // const method — cannot modify members (except mutable)
    std::string host() const {
        access_count_++;   // OK — mutable!
        return host_;
    }

    // Static method — no 'this', access only static members
    static int active_count() { return count_; }
};
int Connection::count_ = 0;  // Define static outside class

Connection::active_count();  // Call without object
3.7

RAII — Resource Acquisition Is Initialization

The most important C++ idiom

RAII ties resource lifetime to object lifetime. Acquire in the constructor, release in the destructor. When the object goes out of scope, cleanup is automatic and guaranteed — even if exceptions are thrown. This is why C++ doesn't need a garbage collector.

Hindi mein samjhoRAII resource lifetime ko object lifetime se tie karta hai. Constructor me acquire karo, destructor me release karo. Jab object scope se bahar jaata hai, cleanup automatic aur guaranteed hai — exceptions throw hone pe bhi. Isliye C++ ko garbage collector ki zaroorat nahi.
💻 C++ — RAII pattern
// RAII file wrapper
class FileHandle {
private:
    FILE* file_;
public:
    explicit FileHandle(const char* path, const char* mode)
        : file_(fopen(path, mode)) {
        if (!file_) throw std::runtime_error("Cannot open file");
    }
    ~FileHandle() {
        if (file_) fclose(file_);  // Always closed!
    }

    // Delete copy (file handle is unique resource)
    FileHandle(const FileHandle&) = delete;
    FileHandle& operator=(const FileHandle&) = delete;

    // Allow move
    FileHandle(FileHandle&& other) noexcept : file_(other.file_) {
        other.file_ = nullptr;
    }

    FILE* get() { return file_; }
};

// Usage — file is ALWAYS closed, no matter what
void process() {
    FileHandle f("data.txt", "r");
    // ... use f.get() ...
    if (error) throw std::runtime_error("oops");
    // f's destructor STILL runs — file closed!
}
