Zero-Cost Abstractions

5.1

Function templates — deduction, instantiation, specialization

Write once, works for any type

A function template is a blueprint — the compiler generates a concrete function for each type you use. Template argument deduction means you usually don't need to specify types explicitly. This is C++'s answer to Java generics, but with zero overhead — code is generated at compile time.

Hindi mein samjhoFunction template ek blueprint hai — compiler har type ke liye concrete function generate karta hai. Template argument deduction ka matlab hai ki aapko explicitly types specify karne ki zaroorat nahi. Ye Java generics ka C++ answer hai, par zero overhead ke saath — code compile time pe generate hota hai.
💻 C++ — Function templates
// Basic function template
template<typename T>
T maximum(T a, T b) {
    return (a > b) ? a : b;
}

// Compiler generates separate functions:
maximum(3, 7);         // maximum<int>(3, 7) → 7
maximum(3.14, 2.71);   // maximum<double>(3.14, 2.71) → 3.14
maximum('a', 'z');     // maximum<char>('a', 'z') → 'z'

// Explicit type specification
maximum<double>(3, 7.5);  // Force double comparison

// Multiple template parameters
template<typename T, typename U>
auto add(T a, U b) {
    return a + b;  // Return type deduced
}
add(3, 4.5);   // int + double → double (7.5)

// Non-type template parameter
template<typename T, int N>
T sum_array(const T (&arr)[N]) {
    T total{};
    for (int i = 0; i < N; i++) total += arr[i];
    return total;
}
int a[] = {1, 2, 3};
sum_array(a);  // N deduced as 3 → returns 6
Templates are NOT compiled until used. The compiler only generates code when you call maximum<int>. Errors only appear at instantiation. Template definitions must be in header files (or use explicit instantiation).
5.2

Class templates — member functions, friends, static

Generic containers and types

Class templates let you create generic containers like std::vector<T>. The entire class is parameterized by one or more types. Member functions can be defined inline or outside the class.

Hindi mein samjhoClass templates se generic containers bana sakte ho jaise std::vector<T>. Poori class ek ya zyada types se parameterized hoti hai. Member functions inline ya class ke bahar define ho sakte hain.
💻 C++ — Class template
template<typename T>
class Stack {
private:
    std::vector<T> data_;

public:
    void push(const T& val) { data_.push_back(val); }

    void pop() {
        if (data_.empty()) throw std::out_of_range("Empty stack");
        data_.pop_back();
    }

    const T& top() const {
        if (data_.empty()) throw std::out_of_range("Empty stack");
        return data_.back();
    }

    bool empty() const { return data_.empty(); }
    size_t size() const { return data_.size(); }

    // Friend — stream operator for printing
    friend std::ostream& operator<<(std::ostream& os, const Stack& s) {
        for (const auto& elem : s.data_)
            os << elem << " ";
        return os;
    }
};

// Usage — each instantiation is a separate class
Stack<int> intStack;
intStack.push(1);
intStack.push(2);
std::cout << intStack.top() << "\n";  // 2

Stack<std::string> strStack;
strStack.push("Hello");

// C++17 CTAD — class template argument deduction
Stack s2 = intStack;  // Deduces Stack<int>
5.3

Template specialization — full & partial

Custom behavior for specific types

Full specialization provides a completely different implementation for a specific type. Partial specialization (class templates only) specializes for a pattern (e.g., all pointer types). This is how std::vector<bool> is optimized differently.

Hindi mein samjhoFull specialization specific type ke liye completely different implementation deta hai. Partial specialization (sirf class templates) pattern ke liye specialize karta hai (jaise saare pointer types). Aise hi std::vector<bool> alag optimize hota hai.
💻 C++ — Template specialization
// Primary template
template<typename T>
class Formatter {
public:
    static std::string format(const T& val) {
        return std::to_string(val);
    }
};

// Full specialization for std::string
template<>
class Formatter<std::string> {
public:
    static std::string format(const std::string& val) {
        return "\"" + val + "\"";
    }
};

// Partial specialization for pointer types
template<typename T>
class Formatter<T*> {
public:
    static std::string format(const T* val) {
        return val ? Formatter<T>::format(*val) : "nullptr";
    }
};

Formatter<int>::format(42);           // "42"
Formatter<std::string>::format("Hi"); // "\"Hi\""
int x = 10;
Formatter<int*>::format(&x);         // "10"
TypeSyntaxApplies to
Primary templatetemplate<typename T> class X {}All types (default)
Full specializationtemplate<> class X<int> {}One specific type
Partial specializationtemplate<typename T> class X<T*> {}Pattern of types
5.4

Variadic templates & fold expressions (C++17)

Accept any number of arguments, type-safely

Variadic templates accept any number of template parameters using ... (parameter pack). Fold expressions (C++17) apply operators across all arguments in one line. This replaces C's va_args with full type safety and zero overhead.

Hindi mein samjhoVariadic templates ... (parameter pack) se kisi bhi number ke template parameters accept karte hain. Fold expressions (C++17) ek line me saare arguments pe operators apply karte hain. C ke va_args ka type-safe, zero overhead replacement hai.
💻 C++ — Variadic templates & fold expressions
// Fold expression — sum any number of args (C++17)
template<typename... Args>
auto sum(Args... args) {
    return (args + ...);  // Unary right fold
}
sum(1, 2, 3, 4);       // 10
sum(1.5, 2.5);          // 4.0

// Print any number of values
template<typename... Args>
void print(Args... args) {
    ((std::cout << args << " "), ...);  // Comma fold
    std::cout << "\n";
}
print(1, "hello", 3.14);  // 1 hello 3.14

// Count arguments
template<typename... Args>
constexpr size_t count() {
    return sizeof...(Args);
}
count<int, double, char>();  // 3

// Type-safe make_unique implementation sketch
template<typename T, typename... Args>
std::unique_ptr<T> make(Args&&... args) {
    return std::unique_ptr<T>(
        new T(std::forward<Args>(args)...)
    );
}
Fold typeSyntaxExpansion
Unary right(args + ...)a + (b + (c + d))
Unary left(... + args)((a + b) + c) + d
Binary right(args + ... + init)a + (b + (c + init))
Binary left(init + ... + args)((init + a) + b) + c
5.5

constexpr, consteval — compile-time computation

Shift work from runtime to compile time

constexpr functions CAN execute at compile time if given constant arguments. consteval (C++20) MUST execute at compile time. This enables zero-cost computations — the result is baked into the binary.

Hindi mein samjhoconstexpr functions constant arguments milne pe compile time pe execute HO SAKTE hain. consteval (C++20) compile time pe execute HONE CHAHIYE. Ye zero-cost computations enable karta hai — result binary me bake ho jaata hai.
💻 C++ — constexpr programming
// constexpr function — can run at compile OR runtime
constexpr long long factorial(int n) {
    long long result = 1;
    for (int i = 2; i <= n; i++)
        result *= i;
    return result;
}

// Compile-time — result baked into binary
constexpr auto f10 = factorial(10);  // 3628800 at compile time!
static_assert(factorial(5) == 120);   // Compile-time assertion

// Also works at runtime
int n;
std::cin >> n;
std::cout << factorial(n);  // Runtime computation

// constexpr if (C++17) — compile-time branching
template<typename T>
auto process(T value) {
    if constexpr (std::is_integral_v<T>) {
        return value * 2;      // Only compiled for int
    } else {
        return value + 0.5;    // Only compiled for float
    }
}

// consteval (C++20) — MUST be compile-time
consteval int square(int n) {
    return n * n;
}
constexpr int val = square(7);  // OK: 49 at compile time
// int x = 5; square(x);          // ❌ ERROR — not constexpr!

// constexpr containers (C++20)
constexpr std::array<int, 5> arr = {1, 2, 3, 4, 5};
static_assert(arr[2] == 3);  // Compile-time array access!
5.6

Concepts & constraints (C++20)

Readable template error messages

Concepts (C++20) let you specify what a template type must support. Before concepts, wrong types produced walls of incomprehensible errors. With concepts, you get clear messages like "type T does not satisfy Sortable".

Hindi mein samjhoConcepts (C++20) se specify kar sakte ho ki template type ko kya support karna chahiye. Concepts se pehle wrong types pe incomprehensible errors aati thi. Ab clear messages milti hain jaise "type T does not satisfy Sortable".
💻 C++ — Concepts (C++20)
#include <concepts>

// Define a concept
template<typename T>
concept Numeric = std::integral<T> || std::floating_point<T>;

// Use concept as constraint — 3 syntaxes:

// 1. requires clause
template<typename T>
    requires Numeric<T>
T square(T x) { return x * x; }

// 2. Constrained template parameter
template<Numeric T>
T cube(T x) { return x * x * x; }

// 3. Abbreviated function template
auto half(Numeric auto x) { return x / 2; }

square(5);       // OK
square(3.14);    // OK
// square("hi");  // ❌ Clear error: "hi" doesn't satisfy Numeric

// Custom concept with requires expression
template<typename T>
concept Printable = requires(T t) {
    { std::cout << t } -> std::same_as<std::ostream&>;
};
5.7

SFINAE, enable_if, type traits — pre-C++20 constraints

Substitution Failure Is Not An Error

SFINAE is the pre-C++20 way to constrain templates. If substituting a type into a template causes an error, the compiler silently removes that overload. std::enable_if and type traits (<type_traits>) use this mechanism.

Hindi mein samjhoSFINAE C++20 se pehle templates constrain karne ka tarika hai. Agar type substitution me error aaye, compiler silently us overload ko hata deta hai. std::enable_if aur type traits (<type_traits>) ye mechanism use karte hain.
💻 C++ — SFINAE & type traits
#include <type_traits>

// enable_if — only enable for integral types
template<typename T>
std::enable_if_t<std::is_integral_v<T>, T>
double_it(T x) {
    return x * 2;
}

double_it(5);     // OK → 10
// double_it(3.14); // ❌ SFINAE removes this overload

// Common type traits
std::is_integral_v<int>;         // true
std::is_floating_point_v<double>; // true
std::is_pointer_v<int*>;         // true
std::is_same_v<int, int>;       // true
std::is_base_of_v<Base, Der>;    // true if Der inherits Base

// Type transformations
std::remove_const_t<const int>;   // int
std::remove_reference_t<int&>;   // int
std::decay_t<const int&>;        // int
Use Concepts (C++20) when possible. SFINAE/enable_if is the old way — hard to read. Concepts give the same power with readable syntax. Use SFINAE only when targeting C++17 or earlier.
