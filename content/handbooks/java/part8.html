8.1

Multithreading — Thread, Runnable, thread lifecycle

Running code in parallel

Threads allow concurrent execution. Create via extending Thread or implementing Runnable (preferred). Thread states: NEW → RUNNABLE → BLOCKED/WAITING → TERMINATED. Use start() (not run()!). Modern Java prefers ExecutorService over raw threads.

Hindi mein samjhoThreads concurrent execution allow karte hain. Thread extend karke ya Runnable implement karke (preferred) banao. start() use karo (run() nahi!). Modern Java me ExecutorService raw threads se better hai.
💻 Java — Multithreading
// ❌ Extending Thread (not recommended)
class MyThread extends Thread {
    @Override
    public void run() {
        System.out.println(Thread.currentThread().getName() + " running");
    }
}

// ✅ Implementing Runnable (preferred)
Runnable task = () -> {
    for (int i = 0; i < 5; i++) {
        System.out.printf("[%s] Count: %d%n",
            Thread.currentThread().getName(), i);
        try { Thread.sleep(100); }
        catch (InterruptedException e) { Thread.currentThread().interrupt(); }
    }
};

Thread t1 = new Thread(task, "Worker-1");
Thread t2 = new Thread(task, "Worker-2");
t1.start(); // ✅ Starts new thread
t2.start();
// t1.run(); // ❌ Runs on current thread! NOT parallel!

// Wait for threads to finish
t1.join();
t2.join();
System.out.println("Both threads finished!");

// Thread states
System.out.println(t1.getState()); // TERMINATED
System.out.println(t1.isAlive());  // false

// Daemon threads — background, auto-killed when main ends
Thread daemon = new Thread(() -> {
    while (true) { /* background task */ }
});
daemon.setDaemon(true);
daemon.start();

// ✅ Synchronized — thread safety
class Counter {
    private int count = 0;
    public synchronized void increment() { count++; }
    public synchronized int getCount() { return count; }
}
Thread StateMeaningTransition
NEWCreated, not started→ start() → RUNNABLE
RUNNABLERunning or ready→ BLOCKED/WAITING/TERMINATED
BLOCKEDWaiting for monitor lock→ gets lock → RUNNABLE
WAITINGwait(), join()→ notify() → RUNNABLE
TIMED_WAITINGsleep(), join(timeout)→ timeout → RUNNABLE
TERMINATEDFinished executionEnd state
8.2

Concurrency — ExecutorService, CompletableFuture, thread pools

Modern concurrent programming

ExecutorService manages thread pools — never create raw threads in production. CompletableFuture (Java 8+) enables async programming with chaining. Use Executors.newFixedThreadPool() for bounded pools, Executors.newVirtualThreadPerTaskExecutor() (Java 21+) for lightweight threads.

Hindi mein samjhoExecutorService thread pools manage karta hai — production me raw threads mat banao. CompletableFuture (Java 8+) async programming enable karta hai chaining ke saath. Java 21+ me virtual threads aaye hain lightweight tasks ke liye.
💻 Java — Concurrency
import java.util.concurrent.*;

// ✅ ExecutorService — thread pool
ExecutorService pool = Executors.newFixedThreadPool(4);

// Submit tasks
pool.submit(() -> System.out.println("Task 1"));
pool.submit(() -> System.out.println("Task 2"));

// Future — get result from async task
Future<Integer> future = pool.submit(() -> {
    Thread.sleep(1000);
    return 42;
});
Integer result = future.get(); // Blocks until complete

pool.shutdown(); // Always shutdown!

// ✅ CompletableFuture — async chains (no blocking!)
CompletableFuture.supplyAsync(() -> fetchUserFromDB(1))
    .thenApply(user -> user.getName())
    .thenApply(String::toUpperCase)
    .thenAccept(name -> System.out.println("Hello, " + name))
    .exceptionally(ex -> { System.err.println(ex); return null; });

// Combine multiple futures
CompletableFuture<String> userFuture = CompletableFuture.supplyAsync(() -> "Alice");
CompletableFuture<Integer> ageFuture = CompletableFuture.supplyAsync(() -> 25);

userFuture.thenCombine(ageFuture, (name, age) ->
    String.format("%s is %d years old", name, age)
).thenAccept(System.out::println);

// Wait for all futures
CompletableFuture.allOf(userFuture, ageFuture).join();

// ✅ Virtual Threads (Java 21+) — lightweight!
try (var executor = Executors.newVirtualThreadPerTaskExecutor()) {
    for (int i = 0; i < 10_000; i++) {
        executor.submit(() -> {
            Thread.sleep(Duration.ofSeconds(1));
            return 42;
        });
    }
} // 10K concurrent tasks — no problem!

8.3

Design patterns — Singleton, Builder, Factory, Observer

Proven solutions to common problems

Design patterns are reusable solutions to recurring software design problems. Creational: Singleton, Builder, Factory. Behavioral: Observer, Strategy. Structural: Decorator, Adapter. These patterns are essential for writing maintainable enterprise Java code.

Hindi mein samjhoDesign patterns recurring software design problems ke reusable solutions hain. Creational: Singleton, Builder, Factory. Behavioral: Observer, Strategy. Structural: Decorator, Adapter. Enterprise Java me essential hain.
💻 Java — Design Patterns
// ✅ Singleton — one instance only
public class AppConfig {
    private static final AppConfig INSTANCE = new AppConfig();
    private AppConfig() {} // Private constructor
    public static AppConfig getInstance() { return INSTANCE; }
}

// ✅ Builder — complex object construction
public class User {
    private final String name, email;
    private final int age;

    private User(Builder b) {
        this.name = b.name; this.email = b.email; this.age = b.age;
    }

    public static class Builder {
        private String name, email;
        private int age;

        public Builder name(String n) { name = n; return this; }
        public Builder email(String e) { email = e; return this; }
        public Builder age(int a) { age = a; return this; }
        public User build() { return new User(this); }
    }
}
User user = new User.Builder()
    .name("Alice").email("alice@mail.com").age(25).build();

// ✅ Factory Method — create without specifying class
public interface Notification { void send(String msg); }
public class EmailNotification implements Notification { /* ... */ }
public class SMSNotification implements Notification { /* ... */ }

public static Notification create(String type) {
    return switch (type) {
        case "email" -> new EmailNotification();
        case "sms"   -> new SMSNotification();
        default     -> throw new IllegalArgumentException(type);
    };
}

// ✅ Observer — event notification
public interface EventListener { void onEvent(String data); }
public class EventBus {
    private final List<EventListener> listeners = new ArrayList<>();
    public void subscribe(EventListener l) { listeners.add(l); }
    public void publish(String data) {
        listeners.forEach(l -> l.onEvent(data));
    }
}

8.4

Annotations — built-in, custom, reflection

Metadata for code

Annotations are metadata markers on classes, methods, fields. Built-in: @Override, @Deprecated, @FunctionalInterface, @SuppressWarnings. Frameworks use them extensively: Spring's @Autowired, JPA's @Entity. You can create custom annotations processed at compile-time or runtime via reflection.

Hindi mein samjhoAnnotations classes, methods, fields pe metadata markers hain. Built-in: @Override, @Deprecated, @FunctionalInterface. Frameworks inhe extensively use karte hain: Spring ka @Autowired, JPA ka @Entity. Custom annotations bhi bana sakte ho.
💻 Java — Annotations
// Built-in annotations
@Override
public String toString() { return "Custom string"; }

@Deprecated(since = "2.0", forRemoval = true)
public void oldMethod() { }

@SuppressWarnings("unchecked")
public void rawTypes() { List raw = new ArrayList(); }

@FunctionalInterface
public interface Transformer<T, R> {
    R transform(T input);
}

// ✅ Custom annotation
@Retention(RetentionPolicy.RUNTIME)  // Available at runtime
@Target(ElementType.METHOD)          // For methods only
public @interface LogExecution {
    String value() default "INFO";
    boolean timed() default false;
}

// Using custom annotation
public class UserService {
    @LogExecution(value = "DEBUG", timed = true)
    public User findUser(int id) { /* ... */ }
}

// Reading annotations via reflection
Method method = UserService.class.getMethod("findUser", int.class);
if (method.isAnnotationPresent(LogExecution.class)) {
    LogExecution log = method.getAnnotation(LogExecution.class);
    System.out.println("Level: " + log.value());  // "DEBUG"
    System.out.println("Timed: " + log.timed());  // true
}
AnnotationPurposeWhere used
@OverrideVerify method overrideCompile-time safety
@DeprecatedMark obsolete APICompiler warning
@FunctionalInterfaceVerify single abstract methodLambda-ready interfaces
@SuppressWarningsSilence compiler warningsUnchecked, deprecation
@SafeVarargsSuppress heap pollutionGeneric varargs
8.5

Java Platform Module System — module-info, exports, requires

Modular Java (Java 9+)

The Java Platform Module System (JPMS, Java 9+) organizes code into modules with explicit dependencies. module-info.java declares what a module exports and requires. This enables strong encapsulation, reliable configuration, and smaller runtime images with jlink.

Hindi mein samjhoJava Platform Module System (JPMS, Java 9+) code ko modules me organize karta hai explicit dependencies ke saath. module-info.java declare karta hai ki module kya export karta hai aur kya require karta hai. Strong encapsulation aur smaller runtime images enable karta hai.
💻 Java — Module System
// module-info.java — in src root
module com.myapp.core {
    // What this module exposes
    exports com.myapp.core.api;
    exports com.myapp.core.model;

    // What this module needs
    requires java.sql;
    requires java.logging;
    requires transitive com.myapp.utils; // Transitive dep

    // Open for reflection (frameworks like Spring)
    opens com.myapp.core.model to com.fasterxml.jackson;

    // Service provider
    provides com.myapp.core.api.Service
        with com.myapp.core.impl.ServiceImpl;

    // Service consumer
    uses com.myapp.core.api.Plugin;
}

// Module directory structure:
// src/
//   com.myapp.core/
//     module-info.java
//     com/myapp/core/
//       api/Service.java
//       model/User.java
//       impl/ServiceImpl.java

Modern Java — text blocks, switch expressions, pattern matching, var

Java keeps evolving

Java evolves every 6 months. Key modern features: Text blocks (13+) for multi-line strings, var (10+) for local type inference, switch expressions (14+) with arrow syntax, pattern matching (16+) for instanceof, sealed classes (17+), virtual threads (21+).

Hindi mein samjhoJava har 6 months me evolve hota hai. Key modern features: Text blocks (13+) multi-line strings ke liye, var (10+) local type inference, switch expressions (14+) arrow syntax ke saath, pattern matching (16+) instanceof ke liye.
💻 Java — Modern Features
// ✅ Text Blocks (Java 13+)
String json = """
        {
            "name": "Alice",
            "age": 25,
            "city": "Mumbai"
        }
        """;

String html = """
        <html>
            <body>
                <h1>Hello, %s!</h1>
            </body>
        </html>
        """.formatted("World");

// ✅ var — Local Variable Type Inference (Java 10+)
var list = new ArrayList<String>(); // Inferred as ArrayList<String>
var map = Map.of("key", 42);       // Map<String, Integer>
var stream = list.stream();          // Stream<String>

// ✅ Switch Expressions (Java 14+)
String day = "MONDAY";
String type = switch (day) {
    case "SATURDAY", "SUNDAY" -> "Weekend";
    case "MONDAY", "FRIDAY"   -> "Almost weekend";
    default                    -> "Midweek";
};

// Switch with blocks
int numLetters = switch (day) {
    case "MONDAY", "FRIDAY", "SUNDAY" -> 6;
    case "TUESDAY"                   -> 7;
    default -> {
        String trimmed = day.strip();
        yield trimmed.length(); // yield for block expressions
    }
};

// ✅ Pattern Matching instanceof (Java 16+)
Object obj = "Hello";
if (obj instanceof String s && s.length() > 3) {
    System.out.println(s.toUpperCase()); // No cast needed!
}

// ✅ Record Patterns (Java 21+)
record Point(int x, int y) {}
Object obj2 = new Point(3, 4);
if (obj2 instanceof Point(var x, var y)) {
    System.out.println("x=" + x + ", y=" + y); // Destructured!
}

Release workflow (dev to production)

A predictable release workflow reduces failures. The goal is to build once, test thoroughly, and deploy with rollback readiness.

Hindi mein samjhoStable release process se production failures kam hote hain. Build once, test properly, aur rollback-ready deploy karo.
💻 Java release workflow (example)
# 1) Static checks + unit tests
mvn -q -DskipTests=false clean test

# 2) Package immutable artifact
mvn -q clean package

# 3) Security scan (dependency + image)
mvn org.owasp:dependency-check-maven:check

# 4) Run integration tests against staging
mvn -q -Pstaging verify

# 5) Deploy with migration + health checks
kubectl apply -f k8s/deployment.yaml
kubectl rollout status deployment/java-app
curl -fsS https://api.example.com/actuator/health

# 6) Rollback if SLO or health fails
kubectl rollout undo deployment/java-app
