6.1

try-catch-finally — handling exceptions, multi-catch

Graceful error handling

Exceptions are Java's mechanism for handling runtime errors. try wraps risky code, catch handles specific exceptions, finally always runs (cleanup). Java 7+ adds multi-catch (catch (A | B e)) to handle multiple types. Never catch Exception or Throwable in production — be specific!

Hindi mein samjhoExceptions Java ka mechanism hai runtime errors handle karne ka. try risky code wrap karta hai, catch specific exceptions handle karta hai, finally hamesha run hota hai (cleanup). Java 7+ me multi-catch se multiple types ek saath handle karo. Production me Exception ya Throwable kabhi catch mat karo — specific raho!
💻 Java — try-catch-finally
// Basic try-catch
try {
    int result = 10 / 0;  // ArithmeticException!
} catch (ArithmeticException e) {
    System.out.println("Cannot divide by zero: " + e.getMessage());
}

// try-catch-finally
Connection conn = null;
try {
    conn = getConnection();
    conn.executeQuery("SELECT * FROM users");
} catch (SQLException e) {
    System.err.println("DB error: " + e.getMessage());
} finally {
    // Always runs — even if exception thrown!
    if (conn != null) conn.close();
}

// Multi-catch (Java 7+)
try {
    String s = null;
    int n = Integer.parseInt(s);
} catch (NumberFormatException | NullPointerException e) {
    System.out.println("Invalid input: " + e.getClass().getSimpleName());
}

// Multiple catch blocks (order matters — specific first!)
try {
    int[] arr = new int[3];
    arr[5] = 10;
} catch (ArrayIndexOutOfBoundsException e) {
    System.out.println("Index out of bounds");
} catch (RuntimeException e) {
    System.out.println("Runtime error");
} catch (Exception e) {
    System.out.println("General error"); // Broadest last!
}

// throw — manually throw an exception
public void setAge(int age) {
    if (age < 0) {
        throw new IllegalArgumentException("Age cannot be negative: " + age);
    }
    this.age = age;
}

// throws — declare checked exception
public void readFile(String path) throws IOException {
    Files.readString(Path.of(path));
}
KeywordPurposeRequired?
tryWrap risky code✅ Always
catchHandle specific exception✅ At least one catch or finally
finallyAlways runs (cleanup)Optional
throwThrow an exceptionManual trigger
throwsDeclare in method signatureFor checked exceptions
6.2

Exception hierarchy — checked vs unchecked, Error vs Exception

Understanding the exception tree

Checked exceptions (extend Exception) must be handled or declared — compiler enforces it. Unchecked exceptions (extend RuntimeException) are programming bugs — no enforcement. Errors (extend Error) are JVM failures — never catch. This is Java's most distinctive feature vs other languages.

Hindi mein samjhoChecked exceptions (Exception extend karte hain) handle ya declare karna zaroori hai — compiler enforce karta hai. Unchecked exceptions (RuntimeException extend) programming bugs hain — enforcement nahi. Errors (Error extend) JVM failures hain — kabhi catch mat karo.
💻 Java — Exception Hierarchy
// Exception hierarchy:
// Throwable
//   ├── Error (DON'T catch!)
//   │   ├── OutOfMemoryError
//   │   ├── StackOverflowError
//   │   └── VirtualMachineError
//   └── Exception (CATCH these)
//       ├── IOException (checked)
//       ├── SQLException (checked)
//       ├── ClassNotFoundException (checked)
//       └── RuntimeException (unchecked)
//           ├── NullPointerException
//           ├── IllegalArgumentException
//           ├── IndexOutOfBoundsException
//           ├── ClassCastException
//           └── ArithmeticException

// ✅ Checked — MUST handle or declare
public String readFile() throws IOException { // Must declare!
    return Files.readString(Path.of("data.txt"));
}

// Calling code MUST handle it
try {
    String data = readFile();
} catch (IOException e) {
    e.printStackTrace();
}

// ✅ Unchecked — no enforcement, but should fix
String name = null;
// name.length(); // NullPointerException — fix your code!

// ❌ NEVER catch Error
// try { ... } catch (OutOfMemoryError e) { } // WRONG!
TypeExtendsCompiler enforced?ExamplesAction
CheckedException✅ YesIOException, SQLExceptionHandle or declare
UncheckedRuntimeException❌ NoNullPointer, IllegalArgumentFix the bug
ErrorError❌ NoOutOfMemory, StackOverflowNever catch
6.3

Custom exceptions — creating domain-specific exceptions

Application-specific errors

Create custom exceptions by extending Exception (checked) or RuntimeException (unchecked). Add meaningful fields (error codes, context). Use exception chaining (cause) to wrap lower-level exceptions. Industry standard: create a base exception + specific sub-exceptions per domain.

Hindi mein samjhoCustom exceptions banao Exception (checked) ya RuntimeException (unchecked) extend karke. Meaningful fields add karo (error codes, context). Exception chaining (cause) se lower-level exceptions wrap karo.
💻 Java — Custom Exceptions
// Custom checked exception
public class InsufficientFundsException extends Exception {
    private final double amount;
    private final double balance;

    public InsufficientFundsException(double amount, double balance) {
        super(String.format(
            "Cannot withdraw %.2f — balance is %.2f", amount, balance
        ));
        this.amount = amount;
        this.balance = balance;
    }

    public double getAmount() { return amount; }
    public double getBalance() { return balance; }
    public double getShortfall() { return amount - balance; }
}

// Custom unchecked exception
public class InvalidEmailException extends RuntimeException {
    public InvalidEmailException(String email) {
        super("Invalid email format: " + email);
    }
}

// Usage
public void withdraw(double amount) throws InsufficientFundsException {
    if (amount > balance) {
        throw new InsufficientFundsException(amount, balance);
    }
    balance -= amount;
}

// Exception chaining — wrap cause
public User loadUser(int id) {
    try {
        return database.findById(id);
    } catch (SQLException e) {
        throw new UserNotFoundException("User " + id + " not found", e);
        // Original cause preserved for debugging!
    }
}
🏭 Industry pattern: Create a BaseAppException with error codes, then extend for specific cases: UserNotFoundException, PaymentFailedException, etc. Always include the original cause in exception chaining.
6.4

try-with-resources — AutoCloseable, resource management

Automatic cleanup

try-with-resources (Java 7+) automatically closes resources implementing AutoCloseable. No need for finally blocks. Resources are closed in reverse order. This eliminates resource leaks — the #1 production bug in old Java code. Use for files, streams, connections, sockets.

Hindi mein samjhotry-with-resources (Java 7+) automatically AutoCloseable resources close karta hai. finally blocks ki zaroorat nahi. Resources reverse order me close hote hain. Files, streams, connections, sockets ke liye use karo.
💻 Java — try-with-resources
// ❌ Old way — verbose, error-prone
BufferedReader reader = null;
try {
    reader = new BufferedReader(new FileReader("data.txt"));
    String line = reader.readLine();
} catch (IOException e) {
    e.printStackTrace();
} finally {
    if (reader != null) {
        try { reader.close(); } catch (IOException e) { /* 😫 */ }
    }
}

// ✅ try-with-resources — clean, safe!
try (BufferedReader reader = new BufferedReader(new FileReader("data.txt"))) {
    String line;
    while ((line = reader.readLine()) != null) {
        System.out.println(line);
    }
} // reader.close() called automatically!

// Multiple resources
try (
    FileReader fr = new FileReader("input.txt");
    FileWriter fw = new FileWriter("output.txt")
) {
    int ch;
    while ((ch = fr.read()) != -1) fw.write(ch);
} // Both closed in reverse order (fw first, then fr)

// Custom AutoCloseable
public class DatabaseConnection implements AutoCloseable {
    public DatabaseConnection() {
        System.out.println("Connected to DB");
    }
    public void query(String sql) { /* ... */ }

    @Override
    public void close() {
        System.out.println("Disconnected from DB");
    }
}

try (var db = new DatabaseConnection()) {
    db.query("SELECT * FROM users");
} // Auto-disconnects!
Rule: Every resource that needs closing (files, streams, connections, sockets) should use try-with-resources. If you see finally { resource.close(); } in your code, refactor to try-with-resources.
6.5

File I/O — reading, writing, BufferedReader, PrintWriter

Reading and writing files

Java has multiple I/O APIs: legacy java.io (streams, readers) and modern java.nio.file (Files, Path). Use Files class for simple operations — it's cleaner and handles encoding. BufferedReader/BufferedWriter for line-by-line. Scanner for formatted input.

Hindi mein samjhoJava me multiple I/O APIs hain: legacy java.io aur modern java.nio.file. Simple operations ke liye Files class use karo — cleaner hai aur encoding handle karta hai. BufferedReader/BufferedWriter line-by-line ke liye.
💻 Java — File I/O
import java.nio.file.*;
import java.io.*;

// ✅ Modern way — Files class (Java 11+)
// Read entire file as string
String content = Files.readString(Path.of("data.txt"));

// Read all lines as List
List<String> lines = Files.readAllLines(Path.of("data.txt"));

// Write string to file
Files.writeString(Path.of("output.txt"), "Hello, World!\n");

// Write lines
Files.write(Path.of("output.txt"), List.of("Line 1", "Line 2"));

// Append to file
Files.writeString(Path.of("log.txt"), "New entry\n",
    StandardOpenOption.APPEND, StandardOpenOption.CREATE);

// BufferedReader — line by line (large files)
try (BufferedReader br = Files.newBufferedReader(Path.of("big.txt"))) {
    String line;
    while ((line = br.readLine()) != null) {
        System.out.println(line);
    }
}

// PrintWriter — formatted writing
try (PrintWriter pw = new PrintWriter(new FileWriter("report.txt"))) {
    pw.println("=== Report ===");
    pw.printf("Name: %s, Score: %d%n", "Alice", 95);
    pw.printf("Name: %s, Score: %d%n", "Bob", 87);
}

// Stream lines (memory efficient for huge files)
try (Stream<String> stream = Files.lines(Path.of("huge.txt"))) {
    stream.filter(l -> l.contains("ERROR"))
          .forEach(System.out::println);
}
MethodUse caseMemory
Files.readString()Small files (< 10MB)Entire file in memory
Files.readAllLines()Small files, need linesAll lines in memory
BufferedReaderLarge files, line-by-lineOne line at a time
Files.lines()Huge files + StreamLazy, memory-efficient
Files.writeString()Write/overwriteSimple string
PrintWriterFormatted outputBuffered writing
6.6

NIO.2 — Path, Files, directory walking, file attributes

Modern file system operations

java.nio.file (NIO.2, Java 7+) provides Path for file paths and Files for operations. Supports creating, copying, moving, deleting files/dirs. Files.walk() recursively traverses directories. Files.find() searches with predicates. WatchService monitors file changes.

Hindi mein samjhojava.nio.file (NIO.2, Java 7+) me Path file paths ke liye aur Files operations ke liye hai. Files/dirs create, copy, move, delete support karta hai. Files.walk() recursively directories traverse karta hai. WatchService file changes monitor karta hai.
💻 Java — NIO.2 Path & Files
import java.nio.file.*;

// Path — file system paths
Path p = Path.of("src", "main", "data.txt"); // src/main/data.txt
Path abs = p.toAbsolutePath();
p.getFileName();   // data.txt
p.getParent();     // src/main
p.getNameCount();  // 3
p.resolve("sub");  // src/main/data.txt/sub

// File operations
Files.exists(p);
Files.isDirectory(p);
Files.isRegularFile(p);
Files.size(p);        // bytes

// Create
Files.createFile(Path.of("new.txt"));
Files.createDirectory(Path.of("newDir"));
Files.createDirectories(Path.of("a/b/c")); // Creates parents

// Copy, Move, Delete
Files.copy(source, target, StandardCopyOption.REPLACE_EXISTING);
Files.move(source, target, StandardCopyOption.ATOMIC_MOVE);
Files.delete(p);            // Throws if not exists
Files.deleteIfExists(p);     // Safe

// Walk directory tree
try (Stream<Path> walk = Files.walk(Path.of("src"))) {
    walk.filter(Files::isRegularFile)
        .filter(f -> f.toString().endsWith(".java"))
        .forEach(System.out::println);
}

// List directory contents
try (Stream<Path> list = Files.list(Path.of("."))) {
    list.forEach(System.out::println);
}

// File attributes
BasicFileAttributes attrs = Files.readAttributes(p, BasicFileAttributes.class);
attrs.creationTime();
attrs.lastModifiedTime();
attrs.size();
Files MethodPurposeNotes
Files.exists()Check existenceReturns boolean
Files.copy()Copy fileUse REPLACE_EXISTING
Files.move()Move/renameATOMIC_MOVE for safety
Files.delete()Delete fileThrows if missing
Files.walk()Recursive traversalReturns Stream<Path>
Files.list()Directory contentsNon-recursive
Files.find()Search with filterBiPredicate matcher
6.7

Serialization — ObjectOutputStream, JSON, best practices

Persisting objects

Java serialization converts objects to bytes (Serializable interface). Avoid it in production — it's insecure and brittle. Use JSON (Jackson/Gson) instead. transient fields are skipped during serialization. serialVersionUID ensures version compatibility.

Hindi mein samjhoJava serialization objects ko bytes me convert karta hai (Serializable interface). Production me avoid karo — insecure aur brittle hai. JSON (Jackson/Gson) use karo. transient fields serialization me skip hote hain.
💻 Java — Serialization
// Java Serialization (legacy — avoid in new code!)
public class User implements Serializable {
    private static final long serialVersionUID = 1L;
    private String name;
    private int age;
    private transient String password; // NOT serialized!
}

// Serialize (write)
try (ObjectOutputStream oos = new ObjectOutputStream(
        new FileOutputStream("user.dat"))) {
    oos.writeObject(new User("Alice", 25));
}

// Deserialize (read)
try (ObjectInputStream ois = new ObjectInputStream(
        new FileInputStream("user.dat"))) {
    User user = (User) ois.readObject();
}

// ✅ Modern approach — JSON with Jackson
// ObjectMapper mapper = new ObjectMapper();
// String json = mapper.writeValueAsString(user);
// User fromJson = mapper.readValue(json, User.class);

// ✅ Simple CSV writing (no library needed)
try (PrintWriter pw = new PrintWriter("data.csv")) {
    pw.println("Name,Age,Score");
    pw.println("Alice,20,95");
    pw.println("Bob,21,87");
}
⚠️ Security warning: Java's built-in serialization (ObjectInputStream) is a known attack vector. Oracle recommends avoiding it. Use JSON (Jackson, Gson) or Protocol Buffers for data exchange in modern applications.

Error-handling release workflow (service-grade)

Treat error handling as a release gate. A service is not production-ready until failure paths are validated.

Hindi mein samjhoError handling ko release gate ki tarah treat karo. Jab tak failure paths test nahi hote, deploy mat karo.
💻 Exception/file readiness workflow
# 1) Run tests for exception and I/O paths
mvn -q -Dtest='**/*Exception*Test,**/*File*Test' test

# 2) Full verify (unit + integration)
mvn -q verify

# 3) Static checks + dependency scan
mvn -q spotbugs:check
mvn org.owasp:dependency-check-maven:check

# 5) Deploy + monitor error budget
