7.1

Lambda expressions — syntax, closures, effectively final

Anonymous functions in Java

Lambdas (Java 8+) are anonymous functions — concise implementations of functional interfaces. Syntax: (params) -> expression or (params) -> { statements }. Lambdas can capture effectively final variables from enclosing scope. They replace verbose anonymous inner classes.

Hindi mein samjhoLambdas (Java 8+) anonymous functions hain — functional interfaces ki concise implementations. Syntax: (params) -> expression ya (params) -> { statements }. Lambdas effectively final variables capture kar sakte hain. Ye verbose anonymous inner classes replace karte hain.
💻 Java — Lambda Expressions
// ❌ Old way — anonymous inner class
Comparator<String> oldWay = new Comparator<String>() {
    @Override
    public int compare(String a, String b) {
        return a.length() - b.length();
    }
};

// ✅ Lambda — one line!
Comparator<String> byLength = (a, b) -> a.length() - b.length();

// Lambda syntax variations
Runnable r1 = () -> System.out.println("Hello");        // No params
Consumer<String> c1 = s -> System.out.println(s);       // One param (no parens)
BiFunction<Integer,Integer,Integer> add = (a, b) -> a + b; // Two params

// Multi-line lambda (use braces + return)
Function<String, Integer> wordCount = s -> {
    String[] words = s.split("\\s+");
    return words.length;
};

// Using lambdas with collections
List<String> names = List.of("Charlie", "Alice", "Bob");
names.sort((a, b) -> a.compareTo(b));         // Sort alphabetically
names.forEach(n -> System.out.println(n));     // Print each
names.removeIf(n -> n.startsWith("A"));       // Remove if starts with A

// ✅ Effectively final — lambdas capture outer variables
String prefix = "Hello";  // Effectively final (never reassigned)
Consumer<String> greeter = name -> System.out.println(prefix + ", " + name);
greeter.accept("Alice");  // "Hello, Alice"

// ❌ Cannot modify captured variable
// int count = 0;
// list.forEach(item -> count++); // Compile error!

// ✅ Workaround — use AtomicInteger or array
var count = new int[]{0};
names.forEach(n -> count[0]++);
SyntaxExampleWhen
() -> expr() -> 42No parameters
x -> exprs -> s.length()One parameter
(x, y) -> expr(a, b) -> a + bMultiple params
(x) -> { stmts }(s) -> { return s.toUpperCase(); }Multi-line body
7.2

Method references — ::, constructor references

Shorthand for lambdas

Method references (::) are shorthand for lambdas that just call an existing method. Four types: static (Math::abs), instance on object (str::length), instance on type (String::length), constructor (ArrayList::new). Use when the lambda simply delegates.

Hindi mein samjhoMethod references (::) lambdas ka shorthand hain jo sirf existing method call karte hain. 4 types: static (Math::abs), instance on object, instance on type (String::length), constructor (ArrayList::new).
💻 Java — Method References
// 1. Static method reference
Function<String, Integer> parse = Integer::parseInt;
// Same as: s -> Integer.parseInt(s)

List<Integer> nums = List.of(-3, 1, -7, 4);
nums.stream().map(Math::abs); // |-3|, |1|, |-7|, |4|

// 2. Instance method on specific object
String prefix = "Hello";
Predicate<String> startsHello = prefix::startsWith;
// Same as: s -> prefix.startsWith(s)

// 3. Instance method on type (most common)
Function<String, Integer> len = String::length;
// Same as: s -> s.length()

names.sort(String::compareToIgnoreCase);
names.forEach(System.out::println);  // Most iconic usage

// 4. Constructor reference
Supplier<ArrayList<String>> listMaker = ArrayList::new;
Function<String, StringBuilder> sbMaker = StringBuilder::new;

// Practical examples
List<String> words = List.of("hello", "world");
List<String> upper = words.stream()
    .map(String::toUpperCase)  // Method ref on type
    .toList();                // ["HELLO", "WORLD"]

// When NOT to use method references
// ❌ names.stream().map(String::substring) — ambiguous!
// ✅ names.stream().map(s -> s.substring(0, 3)) — clear
TypeSyntaxLambda equivalent
StaticClassName::staticMethodx -> ClassName.staticMethod(x)
Instance (object)obj::instanceMethodx -> obj.instanceMethod(x)
Instance (type)ClassName::instanceMethodx -> x.instanceMethod()
ConstructorClassName::newx -> new ClassName(x)
7.3

Stream API — creating streams, pipeline concept, lazy evaluation

Declarative data processing

Streams (Java 8+) are lazy, one-pass pipelines for processing collections declaratively. A stream has: source → intermediate operations (lazy) → terminal operation (triggers execution). Streams don't modify the source. They enable functional-style code: filter, map, reduce.

Hindi mein samjhoStreams (Java 8+) lazy, one-pass pipelines hain collections ko declaratively process karne ke liye. Stream me: source → intermediate operations (lazy) → terminal operation (execution trigger) hoti hai. Streams source modify nahi karte.
💻 Java — Stream API Basics
import java.util.stream.*;

// Creating streams
Stream<String> s1 = List.of("a", "b", "c").stream();
Stream<String> s2 = Stream.of("x", "y", "z");
Stream<Integer> s3 = Stream.iterate(0, n -> n + 2).limit(5); // 0,2,4,6,8
Stream<Double> s4 = Stream.generate(Math::random).limit(3);
IntStream s5 = IntStream.range(1, 6);          // 1,2,3,4,5
IntStream s6 = IntStream.rangeClosed(1, 5);   // 1,2,3,4,5

// ✅ Stream pipeline: source → intermediate → terminal
List<String> names = List.of("Alice", "Bob", "Charlie", "Dave", "Eve");

List<String> result = names.stream()   // Source
    .filter(n -> n.length() > 3)      // Intermediate (lazy!)
    .map(String::toUpperCase)           // Intermediate (lazy!)
    .sorted()                          // Intermediate (lazy!)
    .toList();                         // Terminal (triggers!)
// ["ALICE", "CHARLIE", "DAVE"]

// Nothing happens without terminal operation!
names.stream()
    .filter(n -> {
        System.out.println("Filtering: " + n); // Never printed!
        return n.length() > 3;
    }); // No terminal op → nothing executes!

// Streams are one-shot — cannot reuse!
Stream<String> stream = names.stream();
stream.forEach(System.out::println); // ✅ First use
// stream.forEach(System.out::println); // ❌ IllegalStateException!
ConceptDescriptionKey point
SourceCollection, array, generatorProvides elements
Intermediatefilter, map, sorted, distinctLazy — returns Stream
Terminalcollect, forEach, count, reduceTriggers execution
LazyNo work until terminal opShort-circuits possible
One-shotStream consumed after terminalCannot reuse
7.4

Stream operations — filter, map, flatMap, reduce, peek

Transforming and reducing data

filter() selects elements, map() transforms each element, flatMap() flattens nested streams, reduce() combines all elements into one value. distinct() removes duplicates, sorted() orders, limit()/skip() paginate. peek() is for debugging only.

Hindi mein samjhofilter() elements select karta hai, map() har element transform karta hai, flatMap() nested streams flatten karta hai, reduce() sab elements ko ek value me combine karta hai. distinct() duplicates hatata hai, sorted() order karta hai.
💻 Java — Stream Operations
List<String> names = List.of("Alice", "Bob", "Charlie", "Alice", "Dave");

// filter — keep elements matching predicate
names.stream().filter(n -> n.length() > 3).toList();
// ["Alice", "Charlie", "Alice", "Dave"]

// map — transform each element
names.stream().map(String::toUpperCase).toList();
// ["ALICE", "BOB", "CHARLIE", "ALICE", "DAVE"]

// map to different type
names.stream().map(String::length).toList(); // [5, 3, 7, 5, 4]

// distinct — remove duplicates
names.stream().distinct().toList(); // ["Alice","Bob","Charlie","Dave"]

// sorted
names.stream().sorted().toList(); // Alphabetical
names.stream().sorted(Comparator.comparingInt(String::length)).toList();

// limit & skip (pagination!)
names.stream().skip(2).limit(2).toList(); // ["Charlie", "Alice"]

// flatMap — flatten nested collections
List<List<String>> nested = List.of(
    List.of("A", "B"), List.of("C", "D"), List.of("E")
);
nested.stream().flatMap(List::stream).toList();
// ["A", "B", "C", "D", "E"] — flattened!

// flatMap — split words from sentences
List<String> sentences = List.of("Hello World", "Java Streams");
sentences.stream()
    .flatMap(s -> Arrays.stream(s.split(" ")))
    .toList(); // ["Hello", "World", "Java", "Streams"]

// reduce — combine to single value
int sum = List.of(1, 2, 3, 4, 5).stream()
    .reduce(0, Integer::sum); // 15

String joined = names.stream()
    .reduce("", (a, b) -> a + ", " + b); // Concatenate all

// Terminal operations
long count = names.stream().filter(n -> n.length() > 3).count();
boolean any = names.stream().anyMatch(n -> n.startsWith("A")); // true
boolean all = names.stream().allMatch(n -> n.length() > 1);  // true
boolean none = names.stream().noneMatch(String::isEmpty);   // true

// findFirst / findAny
Optional<String> first = names.stream()
    .filter(n -> n.startsWith("C"))
    .findFirst(); // Optional["Charlie"]
OperationTypeReturnsPurpose
filter()IntermediateStreamSelect elements
map()IntermediateStreamTransform elements
flatMap()IntermediateStreamFlatten nested
sorted()IntermediateStreamOrder elements
distinct()IntermediateStreamRemove duplicates
limit(n)IntermediateStreamTake first n
collect()TerminalResultGather into collection
reduce()TerminalSingle valueCombine all elements
forEach()TerminalvoidSide-effect per element
count()TerminallongCount elements
7.5

Collectors — toList, toMap, groupingBy, joining, partitioning

Gathering stream results

Collectors is the powerhouse for collecting stream results. toList()/toSet() for collections, toMap() for maps, groupingBy() for grouping, partitioningBy() for true/false split, joining() for strings. Java 16+ adds .toList() directly on streams.

Hindi mein samjhoCollectors stream results collect karne ka powerhouse hai. toList()/toSet() collections ke liye, toMap() maps ke liye, groupingBy() grouping ke liye, joining() strings ke liye. Java 16+ me .toList() directly stream pe available hai.
💻 Java — Collectors
import static java.util.stream.Collectors.*;

record Student(String name, int age, double gpa, String dept) {}
List<Student> students = List.of(
    new Student("Alice", 20, 9.2, "CS"),
    new Student("Bob", 21, 8.5, "Math"),
    new Student("Charlie", 20, 9.8, "CS"),
    new Student("Dave", 22, 7.5, "Math"),
    new Student("Eve", 21, 9.0, "CS")
);

// toList, toSet, toUnmodifiableList
List<String> nameList = students.stream()
    .map(Student::name).collect(toList());
Set<String> deptSet = students.stream()
    .map(Student::dept).collect(toSet()); // {"CS", "Math"}

// toMap
Map<String, Double> gpaMap = students.stream()
    .collect(toMap(Student::name, Student::gpa));

// ✅ groupingBy — the most powerful collector!
Map<String, List<Student>> byDept = students.stream()
    .collect(groupingBy(Student::dept));
// {"CS": [Alice, Charlie, Eve], "Math": [Bob, Dave]}

// groupingBy with downstream collector
Map<String, Long> countByDept = students.stream()
    .collect(groupingBy(Student::dept, counting()));
// {"CS": 3, "Math": 2}

Map<String, Double> avgGpaByDept = students.stream()
    .collect(groupingBy(Student::dept, averagingDouble(Student::gpa)));

// partitioningBy — true/false split
Map<Boolean, List<Student>> passedFailed = students.stream()
    .collect(partitioningBy(s -> s.gpa() >= 8.0));
// {true: [Alice,Bob,Charlie,Eve], false: [Dave]}

// joining — concatenate strings
String allNames = students.stream()
    .map(Student::name)
    .collect(joining(", ", "[", "]"));
// "[Alice, Bob, Charlie, Dave, Eve]"

// summarizingDouble — statistics in one pass
DoubleSummaryStatistics stats = students.stream()
    .collect(summarizingDouble(Student::gpa));
stats.getAverage(); stats.getMax(); stats.getMin(); stats.getCount();
CollectorOutputExample
toList()ListCollect to ArrayList
toSet()SetUnique elements
toMap(k, v)MapKey-value mapping
groupingBy(f)Map<K, List>Group by classifier
partitioningBy(p)Map<Boolean, List>True/false split
joining(delim)StringConcatenate strings
counting()LongCount in group
summarizingDouble(f)Statisticsmin/max/avg/sum/count
7.6

Optional — avoiding null, map, flatMap, orElse patterns

The null killer

Optional<T> (Java 8+) wraps a value that might be absent — replaces null returns. Use orElse() for defaults, orElseThrow() for required values, map() for transformations, ifPresent() for side effects. Never use Optional.get() without checking — it defeats the purpose!

Hindi mein samjhoOptional<T> (Java 8+) ek value wrap karta hai jo absent ho sakti hai — null returns replace karta hai. orElse() defaults ke liye, orElseThrow() required values ke liye, map() transformations ke liye use karo.
💻 Java — Optional
// Creating Optional
Optional<String> name = Optional.of("Alice");       // Non-null
Optional<String> empty = Optional.empty();           // Empty
Optional<String> maybe = Optional.ofNullable(str); // null-safe

// ❌ Old way — null checks everywhere
if (user != null) {
    Address addr = user.getAddress();
    if (addr != null) {
        String city = addr.getCity();
        if (city != null) {
            System.out.println(city.toUpperCase());
        }
    }
}

// ✅ Optional way — clean chain!
Optional.ofNullable(user)
    .map(User::getAddress)
    .map(Address::getCity)
    .map(String::toUpperCase)
    .ifPresent(System.out::println);

// Getting values safely
String result1 = name.orElse("Unknown");         // Default value
String result2 = name.orElseGet(() -> loadDefault()); // Lazy default
String result3 = name.orElseThrow();              // NoSuchElement
String result4 = name.orElseThrow(
    () -> new NotFoundException("Not found"));

// Conditional actions
name.ifPresent(n -> System.out.println("Hello, " + n));
name.ifPresentOrElse(
    n -> System.out.println("Found: " + n),  // Present
    () -> System.out.println("Not found")    // Empty
);

// Filtering
Optional<String> longName = name.filter(n -> n.length() > 3);

// Stream integration
name.stream().forEach(System.out::println); // 0 or 1 element stream

// ✅ Return Optional from methods
public Optional<User> findById(int id) {
    User user = database.find(id);
    return Optional.ofNullable(user);
}
MethodPurposeIf empty
orElse(val)Default valueReturns val
orElseGet(supplier)Lazy defaultCalls supplier
orElseThrow()Required valueThrows exception
map(func)Transform if presentReturns empty
flatMap(func)Transform → OptionalReturns empty
filter(pred)Keep if matchesReturns empty
ifPresent(action)Side effectDoes nothing
isPresent()Check existencefalse
Optional anti-patterns: Don't use Optional.get() without checking. Don't use Optional for fields or parameters — only for return types. Don't use Optional<Collection> — return empty collection instead.
7.7

Real-world patterns — parallel streams, primitive streams, best practices

Production-grade stream usage

Primitive streams (IntStream, LongStream, DoubleStream) avoid autoboxing overhead. Parallel streams (.parallelStream()) use ForkJoinPool for multi-core. Use for CPU-heavy tasks on large datasets. Avoid for I/O or small collections.

Hindi mein samjhoPrimitive streams (IntStream, LongStream, DoubleStream) autoboxing overhead avoid karte hain. Parallel streams (.parallelStream()) multi-core ke liye ForkJoinPool use karte hain. CPU-heavy tasks aur large datasets ke liye use karo.
💻 Java — Advanced Streams
// Primitive streams — avoid autoboxing!
int sum = IntStream.range(1, 101).sum(); // 5050
double avg = IntStream.of(1, 2, 3, 4, 5)
    .average().orElse(0); // 3.0

// mapToInt — convert to primitive
int totalLength = names.stream()
    .mapToInt(String::length)
    .sum(); // Sum of all name lengths

// Parallel streams — multi-core
long count = IntStream.range(0, 10_000_000)
    .parallel()
    .filter(n -> isPrime(n))
    .count();

// Convert collection to parallel
students.parallelStream()
    .filter(s -> s.gpa() > 8.0)
    .map(Student::name)
    .toList();

// ✅ Real-world patterns
// 1. CSV processing
Map<String, Long> wordFreq = Files.lines(Path.of("text.txt"))
    .flatMap(line -> Arrays.stream(line.split("\\s+")))
    .map(String::toLowerCase)
    .collect(groupingBy(Function.identity(), counting()));

// 2. Top-N pattern
List<Student> top3 = students.stream()
    .sorted(Comparator.comparingDouble(Student::gpa).reversed())
    .limit(3)
    .toList();

// 3. Grouping + mapping
Map<String, List<String>> namesByDept = students.stream()
    .collect(groupingBy(Student::dept,
        mapping(Student::name, toList())));
🏭 Industry insight: Streams are the backbone of modern Java backends. Spring Data repositories return Stream<Entity>, Jackson serializes via streams, and reactive programming (WebFlux) is built on stream concepts. Master groupingBy() and flatMap() — they solve 80% of data transformation needs.

Streams and Optionals improve readability, but production code must still be measured and validated. Use this checklist before merging stream-heavy logic.
