4.1

Inheritance — extends, super, IS-A relationship

Reusing and extending classes

Inheritance lets a child class reuse fields/methods from a parent class. Java supports single inheritance only (one parent). Use extends to inherit, super to call parent constructor/methods. Every class implicitly extends Object. The child IS-A type of parent.

Hindi mein samjhoInheritance se child class parent class ke fields/methods reuse kar sakti hai. Java me single inheritance hi hai (ek parent). extends se inherit karo, super se parent constructor/methods call karo. Har class implicitly Object extend karti hai.
💻 Java — Inheritance
// Parent class (superclass / base class)
public class Animal {
    protected String name;
    protected int age;

    public Animal(String name, int age) {
        this.name = name;
        this.age = age;
    }

    public void eat() {
        System.out.println(name + " is eating");
    }

    public String getInfo() {
        return String.format("%s (age %d)", name, age);
    }
}

// Child class (subclass / derived class)
public class Dog extends Animal {
    private String breed;

    public Dog(String name, int age, String breed) {
        super(name, age);  // Must call parent constructor first!
        this.breed = breed;
    }

    // New method specific to Dog
    public void bark() {
        System.out.println(name + " says: Woof!");
    }

    @Override
    public String getInfo() {
        return super.getInfo() + ", breed: " + breed;
    }
}

// Usage
Dog dog = new Dog("Buddy", 3, "Golden Retriever");
dog.eat();       // Inherited: "Buddy is eating"
dog.bark();      // Own method: "Buddy says: Woof!"
dog.getInfo();   // Overridden: "Buddy (age 3), breed: Golden Retriever"

// IS-A relationship
System.out.println(dog instanceof Dog);    // true
System.out.println(dog instanceof Animal); // true — Dog IS-A Animal
System.out.println(dog instanceof Object); // true — Everything IS-A Object
KeywordPurposeExample
extendsInherit from parentclass Dog extends Animal
super()Call parent constructorsuper(name, age)
super.method()Call parent methodsuper.getInfo()
protectedAccessible in subclassesprotected String name
@OverrideMark overridden methodCompile-time safety
Rules: super() must be the first statement in child constructor. If parent has no no-arg constructor, you MUST call super(args) explicitly. private members are NOT inherited (not visible to child).
4.2

Polymorphism — method overriding, dynamic dispatch, upcasting

One type, many behaviors

Polymorphism = parent reference can hold child objects. The actual method called depends on the object's runtime type, not the reference type. This is dynamic dispatch (resolved at runtime). Enables writing flexible, extensible code.

Hindi mein samjhoPolymorphism = parent reference child objects ko hold kar sakta hai. Actual method object ke runtime type pe depend karta hai, reference type pe nahi. Ise dynamic dispatch kehte hain (runtime pe resolve hota hai). Flexible, extensible code likhne me madad karta hai.
💻 Java — Polymorphism
public class Shape {
    public double area() { return 0; }
    public String describe() { return "Shape"; }
}

public class Circle extends Shape {
    private double radius;
    public Circle(double r) { this.radius = r; }

    @Override
    public double area() { return Math.PI * radius * radius; }
    @Override
    public String describe() { return "Circle(r=" + radius + ")"; }
}

public class Rectangle extends Shape {
    private double w, h;
    public Rectangle(double w, double h) { this.w = w; this.h = h; }

    @Override
    public double area() { return w * h; }
    @Override
    public String describe() { return "Rect(" + w + "x" + h + ")"; }
}

// ✅ Polymorphism in action!
Shape[] shapes = {
    new Circle(5),
    new Rectangle(4, 6),
    new Circle(3)
};

// Same code handles ALL shape types!
for (Shape s : shapes) {
    System.out.printf("%s → area = %.2f%n", s.describe(), s.area());
}
// Circle(r=5.0) → area = 78.54
// Rect(4.0x6.0) → area = 24.00
// Circle(r=3.0) → area = 28.27

// Method that works with ANY shape
public static double totalArea(Shape[] shapes) {
    double total = 0;
    for (Shape s : shapes) total += s.area(); // Dynamic dispatch!
    return total;
}
ConceptCompile-timeRuntime
Overloading✅ Resolved at compileSame name, different params
OverridingDeclared✅ Resolved at runtime
Reference typeDetermines available methods—
Object type—Determines which version runs
4.3

abstract classes — abstract methods, template pattern

Partial implementations

Abstract classes cannot be instantiated. They can have both abstract methods (no body — subclass MUST implement) and concrete methods (with body). Use for partial implementations and the Template Method design pattern. A class with any abstract method must be declared abstract.

Hindi mein samjhoAbstract classes ka object nahi ban sakta. Inme abstract methods (bina body — subclass ko MUST implement karna padta hai) aur concrete methods (body ke saath) dono ho sakte hain. Partial implementations aur Template Method pattern ke liye use karo.
💻 Java — Abstract Classes
// Abstract class — cannot instantiate!
public abstract class Vehicle {
    protected String brand;
    protected int speed;

    public Vehicle(String brand) {
        this.brand = brand;
        this.speed = 0;
    }

    // Abstract method — no body! Subclass MUST implement.
    public abstract String fuelType();
    public abstract int maxSpeed();

    // Concrete method — shared by all subclasses
    public void accelerate(int amount) {
        speed = Math.min(speed + amount, maxSpeed());
        System.out.printf("%s speed: %d/%d km/h%n", brand, speed, maxSpeed());
    }

    // Template method pattern
    public final void startEngine() {
        System.out.println("Checking fuel: " + fuelType());
        System.out.println("Starting " + brand + "...");
        onStart(); // Hook for subclasses
        System.out.println("Ready to go!");
    }
    protected void onStart() {} // Optional hook
}

public class ElectricCar extends Vehicle {
    public ElectricCar(String brand) { super(brand); }

    @Override
    public String fuelType() { return "Electric"; }
    @Override
    public int maxSpeed() { return 250; }
    @Override
    protected void onStart() { System.out.println("Silent mode activated"); }
}

// Vehicle v = new Vehicle("X");  // ❌ Cannot instantiate abstract!
Vehicle tesla = new ElectricCar("Tesla"); // ✅ Polymorphism
tesla.startEngine();  // Template method runs
tesla.accelerate(100);

4.4

Interfaces — contracts, default methods, functional interfaces

Defining contracts

Interfaces define a contract — what a class MUST do, not HOW. A class can implement multiple interfaces (solving Java's single-inheritance limit). Java 8+ added default methods (with body) and static methods. Functional interfaces (one abstract method) enable lambdas.

Hindi mein samjhoInterfaces ek contract define karte hain — class ko KYA karna hai, KAISE nahi. Ek class multiple interfaces implement kar sakti hai. Java 8+ me default methods (body ke saath) aur static methods aaye. Functional interfaces (ek abstract method) lambdas enable karte hain.
💻 Java — Interfaces
// Interface — pure contract
public interface Flyable {
    void fly();                    // Abstract (no body)
    int maxAltitude();             // Abstract

    // Default method (Java 8+) — optional override
    default String flightStatus() {
        return "In flight at max " + maxAltitude() + "m";
    }

    // Static method — called on interface
    static boolean canFly(Object obj) {
        return obj instanceof Flyable;
    }
}

public interface Swimmable {
    void swim();
    int maxDepth();
}

// ✅ Multiple interfaces!
public class Duck extends Animal implements Flyable, Swimmable {
    public Duck(String name) { super(name, 2); }

    @Override public void fly() { System.out.println(name + " flies!"); }
    @Override public int maxAltitude() { return 100; }
    @Override public void swim() { System.out.println(name + " swims!"); }
    @Override public int maxDepth() { return 5; }
}

// Use as interface type (polymorphism)
Flyable bird = new Duck("Donald");
bird.fly();
bird.flightStatus(); // Default method

// ✅ Functional interface (one abstract method) → lambdas!
@FunctionalInterface
public interface Validator<T> {
    boolean isValid(T item);
}

Validator<String> notEmpty = s -> !s.isEmpty();
Validator<Integer> positive = n -> n > 0;
notEmpty.isValid("hello"); // true
positive.isValid(-5);     // false

4.5

Sealed classes (Java 17+) — restricted hierarchies

Controlling who can extend

Sealed classes (Java 17) restrict which classes can extend them using permits. Subclasses must be final, sealed, or non-sealed. Combined with pattern matching in switch, they enable exhaustive type checking — the compiler knows ALL possible subtypes.

Hindi mein samjhoSealed classes (Java 17) restrict karte hain ki kaun classes extend kar sakti hain permits ke saath. Subclasses ko final, sealed, ya non-sealed hona chahiye. Switch me pattern matching ke saath, compiler ko sab possible subtypes pata hote hain.
💻 Java — Sealed Classes
// Sealed class — only listed classes can extend
public sealed class Payment
    permits CreditCard, DebitCard, UPI {
    protected double amount;
    public Payment(double amount) { this.amount = amount; }
}

// final — no further extension
public final class CreditCard extends Payment {
    private String cardNumber;
    public CreditCard(double amount, String card) {
        super(amount); this.cardNumber = card;
    }
}

public final class DebitCard extends Payment {
    public DebitCard(double amount) { super(amount); }
}

// non-sealed — open for further extension
public non-sealed class UPI extends Payment {
    private String upiId;
    public UPI(double amount, String upiId) {
        super(amount); this.upiId = upiId;
    }
}

// ✅ Exhaustive switch — compiler knows ALL subtypes!
public String processPayment(Payment payment) {
    return switch (payment) {
        case CreditCard cc -> "Processing credit: " + cc.amount;
        case DebitCard dc  -> "Processing debit: " + dc.amount;
        case UPI upi       -> "Processing UPI: " + upi.amount;
        // No default needed! Compiler knows it's exhaustive.
    };
}
Subclass modifierMeaningCan be extended?
finalEnd of hierarchy❌ No
sealedRestricted extension✅ Only permitted classes
non-sealedOpen for extension✅ Anyone
🏭 Industry insight: Sealed classes + records + switch pattern matching = algebraic data types in Java. This pattern is used in domain modeling, payment systems, and event sourcing architectures.
4.6

Enums — constants with behavior, enum methods

Type-safe constants

Enums define a fixed set of constants. Unlike simple int constants, enums are type-safe, can have fields, methods, and constructors. Enums implicitly extend java.lang.Enum. Use values() to iterate, valueOf() to parse from string.

Hindi mein samjhoEnums fixed set of constants define karte hain. Simple int constants ke unlike, enums type-safe hain, inme fields, methods, aur constructors ho sakte hain. values() se iterate karo, valueOf() se string se parse karo.
💻 Java — Enums
// Simple enum
public enum Day {
    MONDAY, TUESDAY, WEDNESDAY, THURSDAY, FRIDAY, SATURDAY, SUNDAY
}

Day today = Day.MONDAY;
System.out.println(today);         // MONDAY
System.out.println(today.name());  // "MONDAY" (string)
System.out.println(today.ordinal()); // 0 (index)

// Iterate all values
for (Day d : Day.values()) {
    System.out.println(d);
}

// Parse from string
Day parsed = Day.valueOf("FRIDAY"); // Case-sensitive!

// ✅ Enum with fields, constructor, methods
public enum Planet {
    MERCURY(3.303e+23, 2.4397e6),
    VENUS(4.869e+24, 6.0518e6),
    EARTH(5.976e+24, 6.37814e6),
    MARS(6.421e+23, 3.3972e6);

    private final double mass;    // in kg
    private final double radius;  // in meters

    // Private constructor! Enums cannot be instantiated.
    Planet(double mass, double radius) {
        this.mass = mass;
        this.radius = radius;
    }

    public double surfaceGravity() {
        final double G = 6.67300E-11;
        return G * mass / (radius * radius);
    }

    public double surfaceWeight(double otherMass) {
        return otherMass * surfaceGravity();
    }
}

// Usage in switch
String type = switch (today) {
    case SATURDAY, SUNDAY -> "Weekend 🎉";
    default -> "Weekday 💼";
};

4.7

Object casting — upcasting, downcasting, ClassCastException

Converting between types in hierarchies

Upcasting (child → parent) is automatic and safe. Downcasting (parent → child) requires explicit cast and may throw ClassCastException. Always check with instanceof before downcasting. Java 16+ pattern matching makes this safer and cleaner.

Hindi mein samjhoUpcasting (child → parent) automatic aur safe hai. Downcasting (parent → child) me explicit cast chahiye aur ClassCastException aa sakta hai. Downcasting se pehle hamesha instanceof check karo. Java 16+ pattern matching ise safer banata hai.
💻 Java — Casting
// Upcasting — automatic, always safe
Dog dog = new Dog("Buddy", 3, "Lab");
Animal animal = dog;  // Upcasting (implicit)
animal.eat();         // ✅ Animal methods work
// animal.bark();    // ❌ Compile error! Animal doesn't have bark()

// Downcasting — explicit, risky!
if (animal instanceof Dog) {
    Dog d = (Dog) animal;  // Safe — we checked first
    d.bark();              // ✅ Now bark() is available
}

// ✅ Pattern matching instanceof (Java 16+)
if (animal instanceof Dog d) {  // Check + cast in one!
    d.bark();
}

// ❌ Unsafe downcasting
Animal cat = new Animal("Cat", 2);
// Dog bad = (Dog) cat;  // ❌ ClassCastException at runtime!

// Polymorphic collection with type checking
Animal[] zoo = { new Dog("Rex", 5, "GSD"), new Animal("Cat", 3) };
for (Animal a : zoo) {
    if (a instanceof Dog d) {
        d.bark();  // Only for dogs
    }
    a.eat();  // Works for all animals
}
CastingDirectionSyntaxSafe?
UpcastingChild → ParentAnimal a = dog;✅ Always
DowncastingParent → ChildDog d = (Dog) animal;⚠️ Check first
Pattern matchCheck + castif (a instanceof Dog d)✅ Safe (16+)
