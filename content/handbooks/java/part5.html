5.1

List — ArrayList, LinkedList, List.of(), operations

Dynamic, ordered collections

List is an ordered, indexed collection that allows duplicates. ArrayList (backed by array) is fastest for random access. LinkedList (doubly-linked) is faster for insertions/deletions. Java 9+ adds List.of() for immutable lists. Always declare as List<T> (interface type).

Hindi mein samjhoList ek ordered, indexed collection hai jo duplicates allow karta hai. ArrayList (array-backed) random access me fastest hai. LinkedList insertions/deletions me faster hai. Java 9+ me List.of() immutable lists ke liye hai. Hamesha List<T> (interface type) se declare karo.
💻 Java — List & ArrayList
import java.util.*;

// ✅ Declare as List (interface), create as ArrayList
List<String> names = new ArrayList<>();

// Add elements
names.add("Alice");        // [Alice]
names.add("Bob");          // [Alice, Bob]
names.add(0, "Charlie");  // [Charlie, Alice, Bob]
names.addAll(List.of("Dave", "Eve")); // Add multiple

// Access
names.get(0);        // "Charlie" (by index)
names.size();        // 5
names.isEmpty();     // false
names.contains("Bob"); // true
names.indexOf("Alice"); // 1

// Modify
names.set(0, "Carl");  // Replace at index
names.remove("Bob");    // Remove by value
names.remove(0);        // Remove by index

// Iterate
for (String name : names) System.out.println(name);
names.forEach(System.out::println); // Method reference

// Sort
Collections.sort(names);          // Natural order
names.sort(Comparator.reverseOrder()); // Reverse

// ✅ Immutable list (Java 9+)
List<String> fixed = List.of("A", "B", "C");
// fixed.add("D"); // ❌ UnsupportedOperationException!

// Convert array ↔ list
String[] arr = names.toArray(new String[0]);
List<String> fromArr = Arrays.asList("X", "Y"); // Fixed-size!
List<String> mutable = new ArrayList<>(List.of("X", "Y")); // Mutable copy

5.2

Set — HashSet, LinkedHashSet, TreeSet, no duplicates

Unique elements only

Set stores unique elements — no duplicates allowed. HashSet is fastest (O(1) add/contains) but unordered. LinkedHashSet maintains insertion order. TreeSet keeps elements sorted. Sets use equals()/hashCode() for uniqueness.

Hindi mein samjhoSet unique elements store karta hai — duplicates allowed nahi. HashSet fastest hai (O(1)) par unordered. LinkedHashSet insertion order maintain karta hai. TreeSet sorted rakhta hai. Uniqueness ke liye equals()/hashCode() use hota hai.
💻 Java — Sets
// HashSet — fast, unordered
Set<String> colors = new HashSet<>();
colors.add("Red");
colors.add("Blue");
colors.add("Red");   // Ignored! Already exists
System.out.println(colors.size()); // 2 (no duplicates)
colors.contains("Blue"); // true — O(1)!
colors.remove("Red");

// LinkedHashSet — maintains insertion order
Set<String> ordered = new LinkedHashSet<>();
ordered.add("C"); ordered.add("A"); ordered.add("B");
// Iterates: C, A, B (insertion order)

// TreeSet — sorted (natural order)
Set<Integer> sorted = new TreeSet<>();
sorted.addAll(List.of(30, 10, 20, 50, 40));
// Iterates: 10, 20, 30, 40, 50 (sorted!)

// Set operations
Set<Integer> a = new HashSet<>(Set.of(1, 2, 3, 4));
Set<Integer> b = new HashSet<>(Set.of(3, 4, 5, 6));

Set<Integer> union = new HashSet<>(a);
union.addAll(b);        // {1,2,3,4,5,6}

Set<Integer> intersection = new HashSet<>(a);
intersection.retainAll(b); // {3,4}

Set<Integer> diff = new HashSet<>(a);
diff.removeAll(b);      // {1,2}

// Immutable set (Java 9+)
Set<String> immutable = Set.of("A", "B", "C");

5.3

Map — HashMap, LinkedHashMap, TreeMap, key-value pairs

Key-value data stores

Map stores key-value pairs — keys must be unique, values can repeat. HashMap is fastest (O(1) get/put). LinkedHashMap keeps insertion order. TreeMap sorts by keys. Use Map.of() for immutable maps. The getOrDefault() and computeIfAbsent() methods are essential.

Hindi mein samjhoMap key-value pairs store karta hai — keys unique honi chahiye, values repeat ho sakti hain. HashMap fastest hai (O(1)). LinkedHashMap insertion order rakhta hai. TreeMap keys ke hisaab se sort karta hai.
💻 Java — Maps
// HashMap — fast, unordered
Map<String, Integer> scores = new HashMap<>();
scores.put("Alice", 95);
scores.put("Bob", 87);
scores.put("Charlie", 92);
scores.put("Alice", 98); // Overwrites! Keys unique.

// Access
scores.get("Alice");       // 98
scores.get("Unknown");     // null
scores.getOrDefault("Unknown", 0); // 0 (safe!)
scores.containsKey("Bob");  // true
scores.containsValue(87);   // true
scores.size();              // 3

// Remove
scores.remove("Charlie");

// Iterate
for (Map.Entry<String, Integer> entry : scores.entrySet()) {
    System.out.printf("%s: %d%n", entry.getKey(), entry.getValue());
}

// Java 10+ — var makes it cleaner
scores.forEach((name, score) ->
    System.out.printf("%s: %d%n", name, score)
);

// Advanced methods
scores.putIfAbsent("Dave", 75);  // Only if key absent
scores.computeIfAbsent("Eve", k -> 80); // Lazy compute
scores.merge("Alice", 5, Integer::sum); // 98 + 5 = 103

// Word frequency counter pattern
Map<String, Integer> freq = new HashMap<>();
for (String word : words) {
    freq.merge(word, 1, Integer::sum);
}

// Immutable map (Java 9+)
Map<String, Integer> fixed = Map.of("A", 1, "B", 2);

// TreeMap — sorted by keys
Map<String, Integer> sorted = new TreeMap<>(scores);
Map TypeKey Orderget/putUse case
HashMapNoneO(1)Default — fastest
LinkedHashMapInsertion orderO(1)Need ordering
TreeMapSorted by keyO(log n)Need sorted keys
ConcurrentHashMapNoneO(1)Thread-safe
Never use mutable objects as Map keys! If the key's hashCode() changes after insertion, you'll lose the entry. Use immutable types (String, Integer, records) as keys.
5.4

Generics — type parameters, bounded types, wildcards

Type-safe reusable code

Generics add compile-time type safety to collections and classes. <T> is a type parameter — replaced with actual type at usage. Bounded types (<T extends Number>) restrict allowed types. Wildcards (? extends, ? super) enable flexible method signatures.

Hindi mein samjhoGenerics compile-time type safety dete hain collections aur classes ko. <T> ek type parameter hai. Bounded types (<T extends Number>) allowed types restrict karte hain. Wildcards (? extends, ? super) flexible method signatures enable karte hain.
💻 Java — Generics
// Generic class
public class Box<T> {
    private T value;

    public Box(T value) { this.value = value; }
    public T getValue() { return value; }
    public void setValue(T value) { this.value = value; }
}

Box<String> strBox = new Box<>("Hello");
Box<Integer> intBox = new Box<>(42);
String s = strBox.getValue(); // No cast needed!

// Generic method
public static <T> List<T> listOf(T... items) {
    return new ArrayList<>(Arrays.asList(items));
}

// Bounded type — T must extend Number
public static <T extends Number> double sum(List<T> list) {
    double total = 0;
    for (T item : list) total += item.doubleValue();
    return total;
}
sum(List.of(1, 2, 3));     // ✅ Integer extends Number
sum(List.of(1.5, 2.5));   // ✅ Double extends Number
// sum(List.of("a"));     // ❌ String doesn't extend Number

// Wildcards
// ? extends T — read-only (producer)
public void printAll(List<? extends Number> list) {
    for (Number n : list) System.out.println(n);
}

// ? super T — write-only (consumer)
public void addNumbers(List<? super Integer> list) {
    list.add(1);
    list.add(2);
}

// Multiple bounds
public <T extends Comparable<T> & Serializable> T max(T a, T b) {
    return a.compareTo(b) >= 0 ? a : b;
}
WildcardMeaningRead?Write?Mnemonic
? extends TT or subtype✅ as T❌ NoPECS: Producer Extends
? super TT or supertype⚠️ as Object✅ as TPECS: Consumer Super
?Unknown type⚠️ as Object❌ NoRead-only, any type
PECS Rule: Producer Extends, Consumer Super. If you READ from a collection → ? extends. If you WRITE to a collection → ? super.
5.5

Comparable & Comparator — sorting custom objects

Custom sorting logic

Comparable<T> defines natural ordering inside the class (implement compareTo()). Comparator<T> defines external ordering — multiple sort strategies without modifying the class. Java 8+ adds Comparator.comparing() for clean lambda-based sorting.

Hindi mein samjhoComparable<T> class ke andar natural ordering define karta hai (compareTo() implement karo). Comparator<T> external ordering define karta hai — class modify kiye bina multiple sort strategies. Java 8+ me Comparator.comparing() clean sorting deta hai.
💻 Java — Comparable & Comparator
// Comparable — natural ordering (inside the class)
public class Student implements Comparable<Student> {
    private String name;
    private double gpa;

    public Student(String name, double gpa) {
        this.name = name; this.gpa = gpa;
    }

    @Override
    public int compareTo(Student other) {
        return Double.compare(this.gpa, other.gpa); // By GPA
    }

    public String getName() { return name; }
    public double getGpa() { return gpa; }
}

List<Student> students = new ArrayList<>(List.of(
    new Student("Alice", 9.2),
    new Student("Bob", 8.5),
    new Student("Charlie", 9.8)
));
Collections.sort(students); // Uses compareTo() → by GPA

// ✅ Comparator — external sorting (multiple strategies)
Comparator<Student> byName = Comparator.comparing(Student::getName);
Comparator<Student> byGpaDesc = Comparator.comparingDouble(Student::getGpa).reversed();
Comparator<Student> byNameThenGpa = byName.thenComparingDouble(Student::getGpa);

students.sort(byName);      // Sort by name
students.sort(byGpaDesc);   // Sort by GPA descending

// Inline lambda comparator
students.sort((a, b) -> Double.compare(b.getGpa(), a.getGpa()));

// Collections utility sorting
Collections.sort(students, byName);
Collections.min(students); // Lowest by natural order
Collections.max(students); // Highest by natural order

5.6

Iterator & Iterable — custom iteration, ConcurrentModification

Traversing collections safely

Iterator<T> provides hasNext(), next(), and remove() for safe traversal. For-each loops use Iterable internally. Never modify a collection while iterating with for-each — use Iterator.remove() or removeIf(). Implement Iterable to make your class work with for-each.

Hindi mein samjhoIterator<T> me hasNext(), next(), aur remove() hain safe traversal ke liye. For-each loops internally Iterable use karte hain. For-each se iterate karte waqt collection modify mat karo — Iterator.remove() ya removeIf() use karo.
💻 Java — Iterator
List<String> names = new ArrayList<>(List.of("A", "B", "C", "D"));

// ❌ ConcurrentModificationException!
// for (String s : names) { if (s.equals("B")) names.remove(s); }

// ✅ Safe removal with Iterator
Iterator<String> it = names.iterator();
while (it.hasNext()) {
    String s = it.next();
    if (s.equals("B")) it.remove(); // Safe!
}

// ✅ Even simpler — removeIf (Java 8+)
names.removeIf(s -> s.equals("C"));

// Custom Iterable class
public class NumberRange implements Iterable<Integer> {
    private final int start, end;
    public NumberRange(int start, int end) {
        this.start = start; this.end = end;
    }

    @Override
    public Iterator<Integer> iterator() {
        return new Iterator<>() {
            int current = start;
            public boolean hasNext() { return current <= end; }
            public Integer next() { return current++; }
        };
    }
}

// Now works with for-each!
for (int n : new NumberRange(1, 5)) {
    System.out.print(n + " "); // 1 2 3 4 5
}
Golden rule: Never modify a collection inside a for-each loop. Use Iterator.remove(), removeIf(), or create a new collection.
5.7

Collections utility class — sort, shuffle, unmodifiable, frequency

Power tools for collections

java.util.Collections provides static utility methods: sorting, searching, shuffling, creating unmodifiable wrappers, frequency counting, and more. Java 9+ adds factory methods (List.of(), Map.of()) for immutable collections. Collections.unmodifiableList() wraps a mutable list as read-only.

Hindi mein samjhojava.util.Collections static utility methods provide karta hai: sorting, searching, shuffling, unmodifiable wrappers, frequency counting. Java 9+ me factory methods (List.of(), Map.of()) immutable collections ke liye hain.
💻 Java — Collections Utility
List<Integer> nums = new ArrayList<>(List.of(5, 2, 8, 1, 9, 3));

// Sorting
Collections.sort(nums);          // [1, 2, 3, 5, 8, 9]
Collections.sort(nums, Comparator.reverseOrder()); // [9,8,5,3,2,1]

// Searching (must be sorted first!)
Collections.sort(nums);
int idx = Collections.binarySearch(nums, 5); // index of 5

// Min, Max
Collections.min(nums); // 1
Collections.max(nums); // 9

// Shuffle
Collections.shuffle(nums); // Random order

// Reverse
Collections.reverse(nums);

// Frequency
List<String> words = List.of("a", "b", "a", "c", "a");
Collections.frequency(words, "a"); // 3

// Unmodifiable wrappers
List<String> readOnly = Collections.unmodifiableList(names);
// readOnly.add("X"); // ❌ UnsupportedOperationException!

// Empty collections (immutable)
List<String> empty = Collections.emptyList();
Map<String, Integer> emptyMap = Collections.emptyMap();

// Singleton (immutable, one element)
List<String> single = Collections.singletonList("only");

// Fill, nCopies
Collections.fill(nums, 0);  // All elements → 0
List<Integer> fives = Collections.nCopies(10, 5); // [5,5,5,...×10]
