5.1

Responsive Design Principles — Mobile-first, viewport, fluid design

The viewport meta tag

Without the viewport meta tag, mobile browsers render pages at desktop width (~980px) and then scale down. The viewport meta tag tells the browser to match the device width, enabling true responsive design. This tag is mandatory on every responsive page.

Hindi mein samjhoViewport meta tag ke bina mobile browser page ko desktop width (~980px) pe render karta hai phir chhota karta hai. Ye tag browser ko bolta hai device ki width match karo — har responsive page pe zaroori hai.
HTML — Viewport meta
<!-- ✅ Required in every responsive page -->
<meta name="viewport"
      content="width=device-width, initial-scale=1.0">

Mobile-first vs desktop-first

Mobile-first writes base styles for small screens, then uses min-width to add complexity for larger screens. Desktop-first does the opposite with max-width. Industry standard is always mobile-first because 60%+ of web traffic is mobile, and it produces cleaner, lighter CSS.

Hindi mein samjhoMobile-first me base styles chhoti screens ke liye hain, min-width se bade screens ke liye add karte hain. Desktop-first me ulta hota hai max-width se. Industry standard hamesha mobile-first hai kyunki 60%+ traffic mobile se aata hai.
ApproachBase styles forMedia queryRecommended?
Mobile-first ✅Small screensmin-width (add complexity)Yes — industry standard
Desktop-first ❌Large screensmax-width (remove features)No — legacy approach
CSS — Mobile-first approach
/* BASE: Mobile styles (no media query needed) */
.container {
  width: 100%;
  padding: 0 16px;
}
.nav-links { display: none; }  /* Hidden on mobile */
.hamburger { display: block; } /* Shown on mobile */

/* TABLET: 768px and up */
@media (min-width: 768px) {
  .container { max-width: 720px; margin: 0 auto; }
  .nav-links { display: flex; }  /* Visible on tablet */
  .hamburger { display: none; }  /* Hidden on tablet */
}

/* DESKTOP: 1024px and up */
@media (min-width: 1024px) {
  .container { max-width: 960px; }
}
Industry standard: Always start mobile-first. Write base styles for mobile → use min-width queries to add tablet/desktop layouts. Never use max-width first.

Fluid design principles

Fluid design uses relative units (%, vw, rem) instead of fixed pixels so elements scale naturally. Combined with max-width constraints and clamp(), you get layouts that work at any screen size without breakpoints.

Hindi mein samjhoFluid design me fixed pixels ki jagah relative units (%, vw, rem) use hote hain taaki elements naturally scale karein. max-width aur clamp() ke saath kisi bhi screen size pe kaam karta hai.
CSS — Fluid design
/* Fluid container */
.wrapper {
  width: 90%;         /* Fluid width */
  max-width: 1200px;  /* Max constraint */
  margin: 0 auto;
}

/* Fluid text — scales with viewport */
h1 {
  font-size: clamp(1.8rem, 4vw + 1rem, 3.5rem);
}
Example explained: The width: 90% makes the container fluid — it adapts to any screen. max-width: 1200px prevents it from becoming too wide on large monitors. clamp() on font-size creates text that smoothly scales between a minimum and maximum — no media queries needed.

CSS units — complete comparison for responsive design

Choosing the right CSS unit is critical for responsive design. Fixed units (px) don't scale. Relative units (rem, em, %, vw) adapt to context. Here's when to use each one.

Hindi mein samjhoResponsive design me sahi CSS unit choose karna critical hai. Fixed units (px) scale nahi hote. Relative units (rem, em, %, vw) context ke hisaab se adapt hote hain. Ye table batati hai kab konsa use karna hai.

Viewport units on mobile — the 100vh problem

On mobile browsers, 100vh includes the area behind the address bar — causing content to be hidden behind it. New viewport units solve this: dvh (dynamic — changes as URL bar shows/hides), svh (small — minimum viewport), lvh (large — maximum viewport).

Hindi mein samjhoMobile browsers me 100vh address bar ke peeche ka area bhi include karta hai — content chhup jaata hai. Naye viewport units ise solve karte hain: dvh (dynamic), svh (small), lvh (large).
UnitBehavior on mobileWhen to use
100vh (legacy)❌ Includes hidden area behind URL barNever on mobile full-height
100dvh✅ Adjusts as URL bar appears/disappears✅ Hero sections, full-screen layouts
100svhSmallest possible viewport (URL bar visible)Safe minimum height
100lvhLargest possible viewport (URL bar hidden)Maximum available space
CSS — Mobile-safe full height
/* ❌ OLD: content hidden behind mobile URL bar */
.hero { min-height: 100vh; }

/* ✅ NEW: respects mobile browser chrome */
.hero { min-height: 100dvh; }

/* Fallback for older browsers */
.hero {
  min-height: 100vh;   /* fallback */
  min-height: 100dvh;  /* modern override */
}
Always provide fallback: Set min-height: 100vh first, then min-height: 100dvh as override. Browsers that don't support dvh will ignore it and use the vh fallback.

Media Queries — Breakpoints, min-width, prefers-color-scheme

Media queries — responsive breakpoints

Media queries apply styles conditionally based on screen size, orientation, or user preferences. Standard breakpoints: 640px (mobile), 768px (tablet), 1024px (desktop), 1280px (wide).

Hindi mein samjhoMedia queries se screen size ke hisaab se alag styles lagte hain. Standard breakpoints: 640px (mobile), 768px (tablet), 1024px (desktop), 1280px (wide).
BreakpointWidthTargetsColumns
sm640pxLarge phones1–2
md768pxTablets2
lg1024pxLaptops3
xl1280pxDesktops4
2xl1536pxWide monitors4–6
CSS — Media queries
/* Mobile-first: base styles for all screens */
.grid {
  display: grid;
  grid-template-columns: 1fr;   /* 1 column on mobile */
  gap: 16px;
}

/* Tablet and up */
@media (min-width: 768px) {
  .grid { grid-template-columns: 1fr 1fr; }
}

/* Desktop and up */
@media (min-width: 1024px) {
  .grid { grid-template-columns: repeat(3, 1fr); }
}

Content-driven breakpoints (professional approach)

Great teams do not pick breakpoints by random device names alone. They place breakpoints where the layout actually starts breaking: text wraps awkwardly, cards become cramped, nav collisions happen, or reading width becomes too wide.

Hindi mein samjhoProfessional approach me breakpoints random device names se nahi choose hote. Jahan layout tootna start hota hai (text wrap, cramped cards, nav collision), wahi breakpoint set karo.
CSS — content-first breakpoints
/* Base mobile styles */
.feature-grid { display: grid; grid-template-columns: 1fr; }

/* Breakpoint added exactly when cards become too narrow */
@media (min-width: 720px) {
  .feature-grid { grid-template-columns: 1fr 1fr; }
}

/* Next breakpoint when reading width gets too large */
@media (min-width: 1100px) {
  .feature-grid { grid-template-columns: repeat(3, 1fr); }
}

User preference media queries

Modern CSS lets you detect user preferences: prefers-color-scheme for dark/light mode, prefers-reduced-motion for animation sensitivity, prefers-contrast for high contrast needs. These make your site more accessible and respectful of user settings.

Hindi mein samjhoModern CSS se user preferences detect hoti hain: dark/light mode, motion sensitivity, high contrast. Ye aapki site ko accessible aur user-friendly banate hain.
CSS — User preference queries
/* Dark mode preference */
@media (prefers-color-scheme: dark) {
  :root {
    --bg: #0f0f1a;
    --text: #e2e8f0;
    --card-bg: #1a1a2e;
  }
}

/* Reduced motion preference */
@media (prefers-reduced-motion: reduce) {
  * { animation-duration: 0.01ms !important; }
}

/* Print styles */
@media print {
  .navbar, .footer { display: none; }
  body { font-size: 12pt; }
}
Pro tip: Always test with DevTools → Rendering → Emulate CSS media features. You can simulate dark mode, reduced motion, and print without changing OS settings.

Modern media query range syntax (2024+)

CSS now supports range syntax for media queries — more readable than the traditional min-width/max-width approach. You can use <=, >=, <, > operators.

Hindi mein samjhoCSS me ab media queries ke liye range syntax support hai — traditional min-width/max-width se zyada readable. <=, >= operators use kar sakte ho.

Before shipping any responsive layout, verify these critical checks at every breakpoint. Missing even one causes real-world bugs.

5.3

Responsive Images & Media — srcset, picture, object-fit, aspect-ratio

Making images responsive

Images must adapt to screen size. Use max-width: 100% as a baseline. For performance, use srcset to serve different sizes, <picture> for art direction, and aspect-ratio to prevent layout shift.

Hindi mein samjhoImages screen size ke hisaab se adjust honi chahiye. max-width: 100% base hai. Performance ke liye srcset se alag sizes serve karo, aspect-ratio se layout shift roko.
CSS — Responsive images
/* Base responsive image rule */
img {
  max-width: 100%;
  height: auto;
  display: block;
}

/* Fixed aspect ratio container */
.thumbnail {
  aspect-ratio: 16 / 9;
  object-fit: cover;    /* Crop to fill */
  border-radius: 12px;
}

srcset & picture — serve optimized images

srcset lets the browser choose the best image size based on device pixel density and viewport width. <picture> enables art direction — showing different crops or formats for different screens. This dramatically improves loading speed on mobile devices.

Hindi mein samjhosrcset se browser device ke hisaab se best image size choose karta hai. <picture> se alag screens ke liye alag images dikhaa sakte ho. Mobile pe loading speed bahut improve hoti hai.
HTML — srcset & picture
<!-- srcset: browser picks best size -->
<img src="hero-800.jpg"
     srcset="hero-400.jpg 400w,
             hero-800.jpg 800w,
             hero-1200.jpg 1200w"
     sizes="(max-width: 768px) 100vw, 50vw"
     alt="Hero banner">

<!-- picture: art direction -->
<picture>
  <source media="(min-width: 1024px)" srcset="hero-wide.webp">
  <source media="(min-width: 640px)" srcset="hero-medium.webp">
  <img src="hero-mobile.webp" alt="Hero">
</picture>
PropertyWhat it doesCommon values
object-fitHow image fills containercover, contain, fill, none
object-positionWhere image is positionedcenter, top, 50% 25%
aspect-ratioEnforces width:height ratio16/9, 4/3, 1/1

Performance rule: Add loading="lazy" to all below-fold images. Add width and height attributes to prevent Cumulative Layout Shift (CLS).

Using the right image format can reduce page weight by 50-80%. Modern formats like WebP and AVIF offer dramatically better compression than JPEG/PNG.

Hindi mein samjhoSahi image format use karne se page weight 50-80% kam ho sakta hai. Modern formats (WebP, AVIF) purane JPEG/PNG se bahut better compression dete hain.

object-fit — how images fill their container

object-fit controls how an <img> or <video> fills its container — similar to background-size but for HTML elements. Understanding each value prevents stretched or cropped images.

Hindi mein samjhoobject-fit se control hota hai ki image apne container me kaise fit hogi — jaise background-size lekin HTML elements ke liye. Har value samajhne se stretched ya cropped images se bachoge.

CSS — object-fit patterns
/* Avatar: always square, never stretched */
.avatar {
  width: 48px;
  height: 48px;
  border-radius: 50%;
  object-fit: cover;        /* Crop to fill circle */
  object-position: top;    /* Focus on face */
}

/* Card thumbnail: fixed aspect ratio */
.card-img {
  width: 100%;
  aspect-ratio: 16 / 9;
  object-fit: cover;
}
Example explained: The avatar uses object-fit: cover with object-position: top so faces are visible even in small circles. The card image uses aspect-ratio to maintain 16:9 regardless of the original image dimensions. Both prevent the stretching that fill (default) would cause.

CSS Custom Properties (Variables) — :root, var(), theming, dark mode

CSS Variables — the foundation of design systems

CSS custom properties (variables) let you define reusable values. Declare them on :root for global access. They enable dark mode toggling, consistent theming, and easy updates across your entire codebase.

Hindi mein samjhoCSS variables se reusable values define hote hain. :root pe declare karo global access ke liye. Dark mode, theming, aur consistent design systems ke liye essential hain.
CSS — Variables & dark mode
/* Define variables */
:root {
  --primary: #7c3aed;
  --bg: #ffffff;
  --text: #1e293b;
  --radius: 12px;
}

/* Dark mode override */
[data-theme="dark"] {
  --bg: #0f0f1a;
  --text: #e2e8f0;
}

/* Use variables */
.card {
  background: var(--bg);
  color: var(--text);
  border-radius: var(--radius);
  border: 1px solid var(--primary);
}
Power move: CSS variables cascade — you can override them on any element. Set --gap: 8px on a compact card and --gap: 24px on a spacious one.

Design tokens — professional variable organization

Professional design systems organize CSS variables into design tokens — categorized by purpose. This makes theming, dark mode, and brand updates trivial.

Hindi mein samjhoProfessional design systems CSS variables ko design tokens me organize karte hain. Isse theming, dark mode, aur brand updates bahut easy ho jaate hain.
CSS — Design tokens
:root {
  /* Colors */
  --clr-primary: #7c3aed;
  --clr-primary-light: #a78bfa;
  --clr-surface: #ffffff;
  --clr-text: #1e293b;
  --clr-muted: #64748b;

  /* Spacing (4px base) */
  --space-xs: 4px;
  --space-sm: 8px;
  --space-md: 16px;
  --space-lg: 32px;
  --space-xl: 64px;

  /* Typography */
  --font-body: 'Inter', system-ui, sans-serif;
  --font-mono: 'JetBrains Mono', monospace;

  /* Effects */
  --radius-sm: 6px;
  --radius-md: 12px;
  --shadow: 0 4px 20px rgba(0,0,0,0.08);
}

CSS variables vs preprocessor variables (Sass/SCSS)

CSS custom properties are not the same as Sass variables. CSS variables are live in the browser — they cascade, can be changed at runtime with JS, and respond to media queries. Sass variables are compiled away at build time.

Hindi mein samjhoCSS custom properties Sass variables se alag hain. CSS variables browser me live hain — cascade karte hain, JS se runtime pe change ho sakte hain. Sass variables build time pe compile ho jaate hain.

Industry trend: Use CSS custom properties for theming, dark mode, and any value that changes at runtime. Use Sass only for loops, mixins, and build-time utilities. Many teams are dropping Sass entirely in favor of native CSS.

var() with fallback chains and computed values

var() supports fallback values — if the variable is not defined, the fallback is used. You can chain multiple var() calls and combine them with calc() for dynamic computed values.

Hindi mein samjhovar() me fallback values hote hain — agar variable defined nahi to fallback use hota hai. Multiple var() chain aur calc() ke saath combine karke dynamic values bana sakte ho.
CSS — var() advanced patterns
/* Fallback chain */
.card {
  color: var(--card-text, var(--text, #1e293b));
  /* Try --card-text → then --text → then #1e293b */
}

/* Responsive variable override */
:root { --cols: 1; }
@media (min-width: 768px) { :root { --cols: 2; } }
@media (min-width: 1024px) { :root { --cols: 3; } }
.grid { grid-template-columns: repeat(var(--cols), 1fr); }
Example explained: The fallback chain tries component-specific variables first, then falls back to global tokens. The responsive override pattern lets you change a single variable at each breakpoint, and every element using that variable updates automatically.
5.5

Modern CSS Functions — clamp(), min(), max(), calc()

Fluid typography & spacing with clamp()

clamp(min, preferred, max) creates fluid values that scale with viewport. Perfect for responsive font sizes and spacing without media queries. calc() lets you mix units (e.g., 100% - 40px).

Hindi mein samjhoclamp() se values viewport ke saath automatically scale hoti hain — bina media queries ke. calc() se alag units mix kar sakte ho (jaise 100% - 40px).
CSS — Modern functions
/* Fluid typography (no media queries!) */
h1 {
  font-size: clamp(1.8rem, 4vw, 3.5rem);
  /* min: 1.8rem, scales with 4vw, max: 3.5rem */
}

/* Fluid spacing */
.section {
  padding: clamp(1rem, 5vw, 4rem);
}

/* calc() for mixed-unit math */
.sidebar {
  width: calc(100% - 280px);
  margin-left: calc(var(--gap) * 2);
}
Industry game-changer: clamp() eliminates the need for many media queries. Use it for font-size, padding, margin, and gap. Your CSS becomes simpler and more fluid.

min() and max() — responsive constraints without breakpoints

min() and max() pick the smallest or largest value. width: min(90%, 1200px) replaces both width: 90% and max-width: 1200px in a single declaration.

Hindi mein samjhomin() sabse chhoti value pick karta hai. width: min(90%, 1200px) ek line me width: 90% aur max-width: 1200px dono ka kaam karta hai.
CSS — min() and max()
/* Container: fluid with max constraint */
.container {
  width: min(90%, 1200px);  /* Replaces width + max-width */
  margin-inline: auto;
}

/* Ensure minimum touch target size */
.btn {
  min-height: max(44px, 2.75rem);  /* At least 44px OR 2.75rem */
}
Key insight: min() acts like a "max constraint" (picks smallest, prevents growing too large). max() acts like a "min constraint" (picks largest, prevents shrinking too small). The naming is counterintuitive!

Container Queries — @container, container-type, component-level responsiveness

Container queries — the future of responsive design

Container queries let components respond to their parent container's size rather than the viewport. This makes truly reusable components that adapt whether they're in a sidebar or full-width area.

Hindi mein samjhoContainer queries se components apne parent container ke size ke hisaab se change hote hain, viewport ke nahi. Iska matlab truly reusable components ban sakte hain jo kahi bhi kaam kare.
CSS — Container queries
/* Define a container */
.card-wrapper {
  container-type: inline-size;
  container-name: card;
}

/* Style based on container width */
@container card (min-width: 400px) {
  .card {
    display: flex;
    gap: 16px;
  }
}

ReusabilityComponents break in new contextsComponents work anywhere
Browser supportAll browsersChrome 105+, Firefox 110+, Safari 16+
Progressive enhancement: Container queries are newer — use them alongside media queries. Start with media queries for page layout, add container queries for component-level responsiveness.

Fallback strategy for container queries

Use media queries as a safe baseline, then enhance with container queries inside a feature-support guard. This ensures older browsers still get a usable layout while modern browsers receive component-intelligent behavior.

Hindi mein samjhoPehle media-query fallback do, phir modern browsers ke liye container query enhancement add karo. Isse old browsers me bhi layout usable rehta hai.
CSS — progressive enhancement
/* Baseline fallback (works everywhere) */
.profile-card { display: block; }
@media (min-width: 900px) {
  .profile-card { display: grid; grid-template-columns: 1fr 2fr; }
}

/* Enhancement for modern browsers */
@supports (container-type: inline-size) {
  .profile-card-wrap { container-type: inline-size; }
  @container (min-width: 420px) {
    .profile-card { display: grid; grid-template-columns: 1fr 2fr; }
  }
}

CSS Nesting & Cascade Layers — @layer, native nesting, scalable architecture

Native CSS nesting (2024+)

CSS now supports native nesting — similar to Sass/SCSS but without a preprocessor. Use & to reference the parent selector. @layer lets you control the cascade order of your styles, preventing specificity wars.

Hindi mein samjhoCSS me ab native nesting support hai — Sass jaisa lekin bina preprocessor ke. & se parent selector refer hota hai. @layer se cascade order control hota hai, specificity wars nahi hote.
CSS — Nesting & layers
/* Native CSS nesting */
.card {
  padding: 20px;

  & .title {
    font-weight: 700;
  }

  &:hover {
    transform: translateY(-2px);
  }
}

/* Cascade layers */
@layer reset, base, components, utilities;

@layer base {
  body { font-family: system-ui; }
}
@layer components {
  .btn { padding: 12px 24px; }
}

@layer — controlling cascade priority

@layer lets you group styles and define their priority order explicitly. Styles in later layers override earlier layers regardless of specificity. This eliminates !important wars.

Hindi mein samjho@layer se styles ko group karke priority order define kar sakte ho. Later layers pehle wale ko override karte hain chahe specificity kuch bhi ho. !important wars khatam!
Layer orderPurposePriority
resetCSS reset/normalizeLowest (overridden by all)
baseTypography, body defaultsLow
componentsCards, buttons, navMedium
utilitiesHelper classes (.sr-only)Highest (overrides all)
Modern CSS is powerful: With native nesting + cascade layers + CSS variables, you may not need Sass/SCSS anymore for many projects. Native CSS covers 90% of what preprocessors offered.

CSS nesting rules and gotchas

Native CSS nesting has specific rules that differ from Sass. Understanding these prevents subtle bugs.

Hindi mein samjhoNative CSS nesting ke specific rules hain jo Sass se alag hain. Inhe samajhna subtle bugs se bachata hai.

CSS — Nesting with media queries
/* Component with nested states + responsive */
.card {
  padding: 16px;
  display: block;

  & .title { font-size: 1.25rem; }
  &:hover { box-shadow: var(--shadow-lg); }
  &.featured { border-color: var(--primary); }

  /* Media query INSIDE the component — colocation! */
  @media (min-width: 768px) {
    display: flex;
    gap: 20px;
  }
}
Best practice: Nest media queries inside component rules (colocation). This keeps all card styles together instead of scattering responsive overrides across the file. Maximum nesting depth: 3 levels to maintain readability.

@scope — component-scoped styles (2024+)

@scope limits CSS rules to a specific DOM subtree. Unlike BEM naming conventions, @scope provides real style isolation at the browser level. Styles inside a scope cannot leak out.

Hindi mein samjho@scope CSS rules ko ek specific DOM subtree tak limit karta hai. BEM naming ke opposite, @scope browser level pe real style isolation deta hai. Scope ke andar ke styles bahar leak nahi hote.
CSS — @scope
/* Styles only apply inside .card */
@scope (.card) {
  h2 { font-size: 1.5rem; }  /* Only card h2, not global h2 */
  p { color: var(--muted); }
}

/* Scope with exclusion (donut scope) */
@scope (.card) to (.card-footer) {
  /* Styles apply to .card content but NOT .card-footer */
  a { color: var(--primary); }
}
Game changer: @scope with the "donut scope" pattern (to keyword) lets you style a component's content while excluding nested sub-components. This prevents style leaking that has plagued CSS for decades.
