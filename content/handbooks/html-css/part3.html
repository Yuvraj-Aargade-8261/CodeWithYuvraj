3.1

Introduction to CSS — What is CSS, syntax, how CSS connects to HTML

What is CSS?

CSS (Cascading Style Sheets) controls the visual presentation of HTML elements — colors, layout, fonts, spacing, animations. Without CSS, every website would look like a plain text document. CSS separates content (HTML) from presentation (CSS), making code cleaner and easier to maintain.

Hindi mein samjhoCSS se HTML elements ki visual presentation control hoti hai — colors, layout, fonts, spacing sab. CSS ke bina har website plain text jaisi dikhegi. CSS content (HTML) ko presentation se alag rakhta hai.

Analogy: Think of HTML as the skeleton (bones and structure), CSS as the skin and clothing (how things look), and JavaScript as the muscles and brain (movement and logic). Each has a separate job — never mix them.

CSS syntax — rules, properties, values

A CSS rule has three parts: a selector (what to style), a property (which aspect), and a value (how to style it). Rules are wrapped in curly braces with property: value; pairs.

Hindi mein samjhoCSS rule me selector (kya style karna hai), property (kaun si cheez), aur value (kaise) hota hai. Rules curly braces me likhe jaate hain.
CSS — Basic syntax
/* Selector { property: value; } */
h1 {
  color: #7c3aed;
  font-size: 2rem;
  font-weight: 800;
}

p {
  color: #64748b;
  line-height: 1.8;
  margin-bottom: 16px;
}
Example explained: h1 is the selector. color and font-size are properties. #7c3aed and 2rem are values. Each declaration ends with a semicolon.

Three ways to add CSS

CSS can be added via inline (style attribute), internal (<style> tag in head), or external (linked .css file). Industry standard: always use external stylesheets. Inline styles break separation of concerns and are hard to maintain.

Hindi mein samjhoCSS teen tarike se add hota hai: inline (style attribute), internal (style tag), external (.css file). Industry me hamesha external CSS use hota hai — inline styles avoid karo.
HTML — Three CSS methods
<!-- ❌ Inline (avoid in production) -->
<p style="color: red;">Red text</p>

<!-- ⚠️ Internal (okay for single-page experiments) -->
<style>
  p { color: blue; }
</style>

<!-- ✅ External (industry standard) -->
<link rel="stylesheet" href="style.css">
Industry rule: External CSS = maintainable, cacheable, reusable. One CSS file can style hundreds of pages. Inline styles should only be used for dynamic JavaScript-set values.

Cascade strategy (how large teams prevent CSS conflicts)

In real projects, CSS failures usually come from poor cascade control, not missing properties. A professional approach is: use low-specificity class selectors, keep component styles scoped, and define a predictable layering order (reset → base → components → utilities → overrides). This avoids “why is this style not applying?” chaos.

Hindi mein samjhoReal projects me CSS issues zyada tar cascade/specificity se aate hain. Best practice: low-specificity class selectors, scoped component styles, aur clear layer order rakho (reset → base → components → utilities → overrides).
CSS — layered architecture
/* 1) Reset / normalize */
*, *::before, *::after { box-sizing: border-box; }

/* 2) Base */
body { font-family: 'Inter', sans-serif; line-height: 1.6; }

/* 3) Components */
.card { padding: 1rem; border-radius: 12px; }

/* 4) Utilities */
.mt-2 { margin-top: 0.5rem; }

/* 5) Rare overrides */
.theme-dark .card { background: #111827; }

How the browser processes CSS (CSSOM pipeline)

When the browser downloads a CSS file, it doesn't just "apply" it. It goes through a precise pipeline: 1) Parse the CSS text into tokens, 2) Build the CSSOM (CSS Object Model) — a tree of all style rules, 3) Cascade — resolve conflicts using origin, specificity, and order, 4) Compute final values (convert relative units, inherit values), 5) Apply computed styles to matching DOM nodes.

Hindi mein samjhoBrowser CSS file download karke seedha apply nahi karta. Pipeline hai: 1) CSS text ko tokens me parse karo, 2) CSSOM (CSS Object Model) tree banao, 3) Cascade se conflicts resolve karo (origin, specificity, order), 4) Final values compute karo (relative units convert, values inherit), 5) Computed styles DOM nodes pe apply karo.

CSS Inheritance — which properties pass to children

Some CSS properties are inherited — their values automatically pass from parent to child elements. Text-related properties (color, font-size, line-height) inherit by default. Layout properties (margin, padding, border, display) do NOT inherit. You can force inheritance with inherit keyword or reset with initial/unset.

Hindi mein samjhoKuch CSS properties inherited hain — parent se child me automatically jaati hain. Text properties (color, font-size, line-height) inherit hoti hain. Layout properties (margin, padding, border, display) inherit nahi hoti. inherit keyword se force kar sakte ho, initial/unset se reset.

Text & Font✅ Yescolor, font-family, font-size, font-weight, line-height, letter-spacing, text-align, text-transformChildren should match parent text style by default
List✅ Yeslist-style, list-style-typeAll list items should share bullet style
Visibility✅ Yesvisibility, cursorHiding parent should hide children
Box Model❌ Nomargin, padding, border, width, heightEach element needs its own box sizing
Layout❌ Nodisplay, position, float, flex, gridLayout is element-specific
Background❌ Nobackground, background-color, background-imageBackground is per-element visual
CSS — Inheritance in action
/* Parent sets text styles — children inherit automatically */
body {
  color: #1e293b;          /* All text inherits this color */
  font-family: 'Inter', sans-serif;
  line-height: 1.7;
}

/* Override inheritance for specific elements */
a {
  color: #7c3aed;          /* Links get different color */
}

/* Force a non-inherited property to inherit */
.card {
  border: inherit;           /* Unusual — forces border from parent */
}

/* Reset keywords */
.reset {
  color: initial;           /* Revert to browser default (black) */
  all: unset;              /* Reset ALL properties at once */
}
Example explained: Setting color on body makes all text elements use that color automatically — you don't need to repeat it on every p, h1, li. Links override it because a has browser default styles. The all: unset shorthand resets every property on an element — powerful for creating custom components from scratch.

The Cascade — how the browser decides which style wins

When multiple CSS rules target the same element and property, the cascade algorithm resolves the conflict. It checks in this exact order: 1) Origin (user-agent → user → author), 2) Specificity (inline → ID → class → element), 3) Source order (last declaration wins if specificity is equal). Understanding this prevents 90% of "why isn't my CSS working?" frustrations.

Hindi mein samjhoJab multiple CSS rules ek hi element aur property pe lage, cascade algorithm conflict resolve karta hai. Order: 1) Origin (browser → user → developer), 2) Specificity (inline → ID → class → element), 3) Source order (barabar specificity me last rule jeetti hai). Ye samajh lo to 90% CSS frustration khatam.

Common mistake: Using IDs for styling creates specificity wars. A single #hero .title rule has specificity 1-1-0, requiring equally specific selectors to override. Stick to classes (0-1-0) for predictable, maintainable CSS.
3.2

Selectors & Specificity — Element, class, ID, combinators, specificity calculation

CSS selector types

Selectors target which HTML elements to style. From basic element selectors to powerful combinators, choosing the right selector determines both precision and maintainability of your styles.

Hindi mein samjhoSelectors decide karte hain ki kaun se HTML elements pe style lagega. Sahi selector choose karna code ki precision aur maintainability dono decide karta hai.
CSS — Selector types
/* Element selector */
p { color: #333; }

/* Class selector (reusable — preferred) */
.card { padding: 20px; }

/* ID selector (unique — use sparingly) */
#hero { background: #0f0f1a; }

/* Attribute selector */
input[type="email"] { border-color: #7c3aed; }

/* Descendant combinator */
.nav a { text-decoration: none; }

/* Direct child combinator */
.menu > li { display: inline-block; }

/* Grouping selector */
h1, h2, h3 { font-weight: 700; }
Industry rule: Prefer classes over IDs for styling. Classes are reusable; IDs have high specificity that's hard to override. Use IDs for JavaScript hooks and anchor links.

Specificity — how the browser resolves conflicts

When multiple rules target the same element, the browser uses specificity to decide which wins. Specificity is calculated as a score: inline (1000) > ID (100) > class (10) > element (1). Higher specificity always wins, regardless of source order.

Hindi mein samjhoJab ek element pe multiple rules lage, browser specificity se decide karta hai kaun jeeta. Score: inline (1000) > ID (100) > class (10) > element (1). Zyada score hamesha jeetta hai.
SelectorSpecificityScore
p1 element0-0-1
.card1 class0-1-0
#hero1 ID1-0-0
.card .title2 classes0-2-0
#hero .card p1 ID + 1 class + 1 element1-1-1
style="..."Inline1-0-0-0
Avoid !important! It overrides everything and creates unmaintainable CSS. If you need !important, your specificity architecture is broken.

Modern selector patterns: :where(), :is(), and nesting mindset

Modern CSS gives safer ways to compose selectors. :where() adds zero specificity, perfect for base styles. :is() simplifies long selector groups. Combined with thoughtful naming, these reduce override battles in large systems.

Hindi mein samjho:where() zero specificity deta hai, base styles ke liye best hai. :is() long selector groups ko short karta hai. Inse large projects me CSS conflict kam hota hai.
CSS — modern selectors
/* :where() -> zero specificity baseline */
:where(h1, h2, h3) {
  line-height: 1.2;
  margin: 0 0 0.75rem;
}

/* :is() -> cleaner grouped selector */
.card :is(a, button) {
  font-weight: 600;
}

/* Explicit component scope */
.nav__item:hover .nav__link { color: #7c3aed; }

The Box Model — Content, padding, border, margin, box-sizing

Everything is a box

Every HTML element is rendered as a rectangular box. The box model has four layers from inside out: content (your text/image), padding (space inside border), border (visible edge), and margin (space outside border). Understanding this is the #1 key to mastering layout.

Hindi mein samjhoHar HTML element ek rectangular box hai. Box model me 4 layers hain: content (andar ka text/image), padding (border ke andar space), border (visible edge), margin (border ke bahar space). Ye samajhna layout ka #1 key hai.

box-sizing: border-box (industry standard)

By default, width only applies to content — padding and border are added on top (content-box). box-sizing: border-box makes width include padding and border, which is far more intuitive. Every production CSS file starts with this reset.

Hindi mein samjhoDefault me width sirf content pe lagti hai — padding aur border upar se add hoti hai. border-box se width me padding aur border include hoti hai. Har professional CSS file ye reset se shuru hoti hai.
CSS — Box model reset
/* ✅ Universal box-sizing reset (always use this) */
*, *::before, *::after {
  box-sizing: border-box;
}

/* Example: a card with predictable sizing */
.card {
  width: 300px;       /* Total width stays 300px */
  padding: 20px;
  border: 2px solid #7c3aed;
  margin: 16px;
}
Must-know: With border-box, a 300px card stays 300px even with padding. Without it, it becomes 300 + 40 (padding) + 4 (border) = 344px. Always use the reset.

content-box vs border-box — visual comparison

The difference between the two box models is the #1 source of CSS sizing bugs. With content-box (default), padding and border are added to the specified width. With border-box, the specified width includes padding and border, so the content area shrinks.

Hindi mein samjhocontent-box me width sirf content ki hoti hai — padding aur border upar se add hote hain. border-box me width me padding aur border include hai, content area chhota ho jaata hai. Ye CSS sizing bugs ka #1 source hai.
Propertycontent-box (default)border-box (✅ recommended)

padding: 20pxAdds 40px total → 340pxIncluded → still 300px
border: 2pxAdds 4px total → 344pxIncluded → still 300px

DevTools tip: Open Chrome DevTools → select any element → look at the Computed panel. You'll see the exact box model diagram with content, padding, border, and margin values rendered visually.

Margin collapse

When two vertical margins touch, they collapse into a single margin equal to the larger one. This only happens vertically, not horizontally. Understanding this prevents spacing bugs.

Hindi mein samjhoJab do vertical margins milte hain, wo ek ho jaate hain (bada wala jeetta hai). Ye sirf vertically hota hai, horizontally nahi. Ye samajhna spacing bugs rokta hai.
CSS — Margin collapse
/* Both have 20px margin — but gap is 20px, NOT 40px */
.box-a { margin-bottom: 20px; }
.box-b { margin-top: 20px; }

/* Fix: use padding on parent, or gap in Flexbox/Grid */
3.4

Colors & Backgrounds — hex, RGB, HSL, gradients, opacity

Color formats in CSS

CSS supports multiple color formats. Hex (#ff0000) is most common. RGB uses red/green/blue values. HSL (hue, saturation, lightness) is the most intuitive for creating color palettes. Modern CSS also supports oklch() for perceptually uniform colors.

Hindi mein samjhoCSS me multiple color formats hain. Hex (#ff0000) sabse common hai. HSL (hue, saturation, lightness) color palettes banane ke liye sabse easy hai. Modern CSS me oklch() bhi hai.
CSS — Color formats
.text {
  color: #7c3aed;                /* Hex */
  color: rgb(124, 58, 237);       /* RGB */
  color: rgba(124, 58, 237, 0.8);  /* RGB + alpha */
  color: hsl(265, 82%, 58%);      /* HSL (recommended) */
  color: hsla(265, 82%, 58%, 0.8); /* HSL + alpha */
}

Backgrounds & gradients

CSS backgrounds can be solid colors, images, or gradients. Linear gradients flow in one direction, radial gradients radiate from a center point. Gradients are pure CSS — no image files needed.

Hindi mein samjhoCSS backgrounds solid colors, images, ya gradients ho sakte hain. Gradients pure CSS se bante hain — koi image file nahi chahiye. Modern UI me gradients bahut use hote hain.
CSS — Gradients
.hero {
  /* Linear gradient */
  background: linear-gradient(135deg, #7c3aed, #06b6d4);

  /* Radial gradient */
  background: radial-gradient(circle, #7c3aed, #0f0f1a);
}

.overlay {
  /* Semi-transparent overlay */
  background: rgba(0, 0, 0, 0.6);
  opacity: 0.9;
}
Design tip: Use HSL for building color palettes — keep hue same, adjust saturation/lightness for variants. Example: hsl(265, 82%, 58%) → lighter: hsl(265, 82%, 75%).

opacity vs rgba — critical difference

opacity affects the entire element and all its children. rgba() / hsla() only makes that one property transparent. This distinction is critical — if you use opacity: 0.5 on a card, all text inside becomes semi-transparent too. Use rgba() for background transparency while keeping content fully visible.

Hindi mein samjhoopacity poore element aur uske saare children ko transparent banata hai. rgba() sirf ek property ko transparent karta hai. Card pe opacity: 0.5 lagaoge to andar ka text bhi dhundla hoga. Background transparent chahiye to rgba() use karo.

CSS — opacity vs rgba
/* ❌ WRONG: opacity makes ALL content semi-transparent */
.overlay-bad {
  background: black;
  opacity: 0.6;     /* Text inside is also 60% transparent! */
}

/* ✅ CORRECT: only background is transparent */
.overlay-good {
  background: rgba(0, 0, 0, 0.6);  /* Text stays fully visible */
}
Example explained: The .overlay-bad approach makes everything inside the overlay semi-transparent, including headings and buttons. The .overlay-good approach only affects the background color, keeping all child content fully opaque and readable. Always use rgba()/hsla() for overlays.

Typography & Text Styling — font-family, size, weight, line-height, Google Fonts

Font properties

Typography is 90% of design. Key properties: font-family (typeface), font-size (size), font-weight (boldness 100–900), line-height (spacing between lines), and letter-spacing. Always provide a font stack with fallbacks.

Hindi mein samjhoTypography design ka 90% hai. Font-family se typeface, font-size se size, font-weight se boldness, line-height se lines ke beech spacing control hoti hai. Hamesha fallback fonts do.
CSS — Typography
/* Font stack with fallbacks */
body {
  font-family: 'Inter', 'Segoe UI', sans-serif;
  font-size: 16px;       /* Base size */
  line-height: 1.7;       /* 1.5–1.8 is ideal */
  color: #1e293b;
}

h1 {
  font-size: 2.5rem;
  font-weight: 800;
  letter-spacing: -0.02em; /* Tighter for headings */
  line-height: 1.2;
}

Google Fonts — using custom fonts

Google Fonts provides hundreds of free, high-quality web fonts. Add them via <link> in your HTML head. Popular choices: Inter (UI), Outfit (headings), JetBrains Mono (code).

Hindi mein samjhoGoogle Fonts se free web fonts milte hain. HTML head me link tag se add karo. Inter, Outfit, JetBrains Mono popular choices hain.
HTML — Google Fonts
<!-- In HTML head -->
<link rel="preconnect" href="https://fonts.googleapis.com">
<link href="https://fonts.googleapis.com/css2?family=Inter:wght@400;600;800&display=swap"
      rel="stylesheet">
Performance: Only load weights you actually use. Each extra weight adds ~20KB. Use font-display: swap to prevent invisible text during loading.

Font loading strategies — preventing invisible text

When using custom web fonts, the browser has 3 possible behaviors: FOIT (Flash of Invisible Text — text disappears while loading), FOUT (Flash of Unstyled Text — system font shows first, then swaps), and FOFT (Flash of Faux Text — uses synthetic bold/italic temporarily). The font-display property controls which strategy the browser uses.

Hindi mein samjhoCustom web fonts load hone me time lagta hai. Tab tak 3 behaviors ho sakte hain: FOIT (text invisible), FOUT (system font dikhta hai phir swap), FOFT (fake bold/italic temporarily). font-display property se control hota hai konsa behavior hoga.

  overflow: hidden;
}
Example explained: The single-line truncation pattern uses 3 properties together: nowrap prevents wrapping, overflow: hidden clips excess content, and text-overflow: ellipsis adds "..." at the cut point. The multi-line version uses the WebKit line clamp — despite the vendor prefix, it works in all modern browsers.
3.6

Units & Values — px, em, rem, %, vw, vh, ch, choosing the right unit

Absolute vs relative units

Absolute units (px) are fixed. Relative units (em, rem, %, vw, vh) scale based on context. Industry standard: use rem for font sizes, px for borders/shadows, % or vw for widths.

Hindi mein samjhoAbsolute units (px) fixed hain. Relative units (rem, %, vw) context ke hisaab se scale hote hain. Industry standard: font sizes ke liye rem, borders ke liye px, widths ke liye % ya vw.
UnitRelative toBest for
pxViewport pixelBorders, shadows, small spacing
remRoot font size (16px)Font sizes, padding, margins
emParent font sizeContextual sizing, padding on buttons
%Parent elementWidths, responsive layouts
vw / vhViewport width/heightFull-screen sections, hero banners
chCharacter "0" widthLimiting text line length
CSS — Units in practice
.hero {
  height: 100vh;          /* Full viewport height */
  padding: 2rem;          /* Scales with root font */
}

.content {
  max-width: 65ch;        /* ~65 characters per line */
  font-size: 1rem;        /* 16px by default */
  border: 1px solid #e2e8f0; /* px for thin borders */
}
Golden rule: rem for sizing, px for precision, %/vw for responsiveness. Never use px for font sizes — it breaks user zoom preferences.

3.7

Display & Visibility — block, inline, inline-block, none, visibility, overflow

Display property — controlling element behavior

The display property defines how an element participates in layout. block takes full width, inline flows with text, inline-block combines both. none removes from layout entirely.

Hindi mein samjhoDisplay property se element ka layout behavior decide hota hai. Block full width leta hai, inline text ke saath flow karta hai, inline-block dono ka mix hai, none se element hatata hai.
ValueBehaviorWidth/HeightExamples
blockNew line, full width✅ Acceptsdiv, p, h1–h6, section
inlineFlows in text❌ Ignoredspan, a, strong, em
inline-blockFlows in text✅ Acceptsbuttons, badges
noneRemoved entirely—Hidden elements

Visibility & overflow

visibility: hidden hides an element but preserves its space in layout (unlike display: none). overflow controls what happens when content overflows its container: hidden clips it, scroll adds scrollbars, auto scrolls only when needed.

Hindi mein samjhovisibility: hidden element chhupata hai lekin jagah reserve rakhta hai. display: none se jagah bhi hat jaati hai. overflow se control hota hai jab content container se bahar nikle.
CSS — Display, visibility, overflow
/* display: none vs visibility: hidden */
.hidden-a { display: none; }          /* Gone from layout */
.hidden-b { visibility: hidden; }     /* Invisible but space kept */

/* Overflow control */
.card-body {
  max-height: 200px;
  overflow-y: auto;   /* Scroll only if needed */
}

.avatar {
  width: 50px;
  height: 50px;
  border-radius: 50%;
  overflow: hidden;   /* Clip image to circle */
}
Accessibility note: display: none also hides from screen readers. For visually hidden but accessible content, use the .sr-only pattern instead.

Hiding methods comparison — which to use when

There are many ways to hide elements in CSS. Each behaves differently regarding layout, accessibility, and animation.

Hindi mein samjhoCSS me elements chhupane ke bahut tarike hain. Har ek ka layout, accessibility, aur animation me alag behavior hai.

The .sr-only pattern: position: absolute; width: 1px; height: 1px; padding: 0; margin: -1px; overflow: hidden; clip: rect(0,0,0,0); border: 0; — visually hidden but screen readers can read it. Use for skip links and form labels.
