8.1

Professional Project Setup — File structure, reset CSS, Git workflow, VS Code config

Industry-standard project structure

Every professional project starts with a clean structure: organized folders, a CSS reset, version control with Git, and proper tooling. This is the foundation of maintainable code.

Hindi mein samjhoHar professional project clean structure se shuru hota hai: organized folders, CSS reset, Git se version control, aur proper tooling. Ye maintainable code ki neenv hai.
📂 Project structure
project/
├── index.html
├── css/
│   ├── reset.css        /* Normalize browser defaults */
│   ├── variables.css    /* Design tokens */
│   ├── base.css         /* Typography, body */
│   ├── components.css   /* Cards, buttons, nav */
│   └── utilities.css    /* Helpers (.sr-only, .flex) */
├── js/
│   └── main.js
├── assets/
│   └── images/
├── .gitignore
└── README.md
CSS — Modern reset
/* Modern CSS reset (2024) */
*, *::before, *::after { box-sizing: border-box; }
* { margin: 0; padding: 0; }
html { scroll-behavior: smooth; }
body {
  min-height: 100vh;
  line-height: 1.7;
  -webkit-font-smoothing: antialiased;
}
img, picture, video, canvas, svg {
  display: block;
  max-width: 100%;
}
input, button, textarea, select {
  font: inherit;
}

Essential Git workflow

Git is mandatory for every project. Learn these core commands and you'll handle 95% of day-to-day version control. Always commit in small, meaningful chunks.

Hindi mein samjhoGit har project ke liye zaroori hai. Ye core commands seekho — 95% daily version control handle ho jayega. Chhote, meaningful commits karo.
💻 Terminal — Git commands
# Initialize new project
git init
git add .
git commit -m "Initial commit: project structure"

# Daily workflow
git add -A
git commit -m "feat: add responsive navbar"
git push origin main

# Branching (for features)
git checkout -b feature/contact-form
# ... make changes ...
git commit -m "feat: add contact form with validation"
git checkout main
git merge feature/contact-form
Commit message format: Use conventional commits: feat: for features, fix: for bugs, style: for CSS, docs: for documentation.

Definition of Done (DoD) for front-end projects

Professional teams ship with a clear DoD checklist so quality is consistent across contributors. A feature is not “done” when it looks correct locally; it is done when tested, accessible, responsive, and deployed.

Hindi mein samjhoProfessional workflow me DoD checklist hoti hai. Feature tab complete maana jata hai jab wo test ho, responsive ho, accessible ho, aur deploy bhi ho — sirf local pe sahi dikhna enough nahi.
AreaDone criteria
ResponsivenessWorks on mobile/tablet/desktop breakpoints
AccessibilityKeyboard navigable + visible focus + semantic labels
PerformanceNo major Lighthouse regressions; optimized assets
Code qualityConsistent naming + no dead CSS + clear structure
DeliveryCommitted, pushed, and live deployment updated

Project: Personal Portfolio Website — Hero, about, projects, contact

Portfolio — your most important project

A portfolio website is the #1 thing recruiters look at. It must include: hero section with CTA, about section, project showcase with live links, skills section, and a contact form. Mobile-first, accessible, and fast.

Hindi mein samjhoPortfolio website recruiters ki #1 cheez hai. Hero section, about, projects showcase, skills, aur contact form hona chahiye. Mobile-first, accessible, aur fast hona zaroori hai.
HTML — Portfolio structure
<body>
  <header> <!-- Sticky nav --> </header>
  <main>
    <section id="hero">     <!-- Name, tagline, CTA --> </section>
    <section id="about">    <!-- Bio, photo --> </section>

Must-have features: Dark/light mode toggle, smooth scroll navigation, responsive project grid with hover effects, contact form with validation, Lighthouse score 90+.

Portfolio hero section — CSS

The hero is the first thing visitors see. It must be visually stunning, load fast, and have a clear CTA. Use CSS Grid or Flexbox for layout, clamp() for fluid text, and gradient backgrounds.

Hindi mein samjhoHero sabse pehle dikhta hai. Visually stunning, fast loading, aur clear CTA hona chahiye. CSS Grid/Flexbox layout ke liye, clamp() fluid text ke liye, gradient backgrounds use karo.
CSS — Hero section
.hero {
  min-height: 100vh;
  display: flex;
  flex-direction: column;
  justify-content: center;
  padding: clamp(2rem, 8vw, 6rem);
  background: linear-gradient(135deg, #0f0f1a, #1a0a2e);
}

.hero__title {
  font-size: clamp(2rem, 5vw + 1rem, 4.5rem);
  line-height: 1.1;
}

.hero__cta {
  display: inline-flex;
  padding: 14px 32px;
  background: var(--primary);
  border-radius: 8px;
  transition: all 0.3s ease;
}

Project: Admin Dashboard UI — Sidebar, grid layout, cards, charts area, dark mode

Dashboard — complex layout challenge

Dashboards combine CSS Grid for overall layout, Flexbox for component internals, CSS variables for theming, and responsive breakpoints. This is the ultimate test of your layout skills.

Hindi mein samjhoDashboard me CSS Grid (overall layout), Flexbox (components ke andar), CSS variables (theming), aur responsive breakpoints sab use hote hain. Ye aapke layout skills ka ultimate test hai.
CSS — Dashboard layout
.dashboard {
  display: grid;
  grid-template-columns: 260px 1fr;
  grid-template-rows: 64px 1fr;
  grid-template-areas:
    "sidebar topbar"
    "sidebar content";
  min-height: 100vh;
}

@media (max-width: 768px) {
  .dashboard {
    grid-template-columns: 1fr;
    grid-template-areas:
      "topbar"
      "content";
  }
}

Dashboard stat cards & dark mode toggle

Dashboard stat cards show key metrics at a glance. Combine with CSS variables for instant dark mode. Use data-theme attribute toggled via JS.

Hindi mein samjhoStat cards se key metrics ek nazar me dikhte hain. CSS variables ke saath dark mode instantly toggle hota hai.

CSS Methodologies & Preprocessors — BEM, SMACSS, Sass/SCSS, PostCSS, Tailwind overview

Scaling CSS for teams

As projects grow, you need a methodology. BEM for naming, SCSS for features (variables, mixins, nesting), PostCSS for autoprefixing, and Tailwind for utility-first approaches. Know all, master one.

Hindi mein samjhoJaise projects bade hote hain, methodology chahiye. BEM naming ke liye, SCSS features ke liye, PostCSS autoprefixing ke liye, Tailwind utility-first ke liye. Sab jaano, ek master karo.

SCSS mixins — reusable patterns

SCSS mixins are reusable blocks of CSS. Create mixins for responsive breakpoints, Flexbox centering, and commonly repeated patterns.

Hindi mein samjhoSCSS mixins reusable CSS blocks hain. Responsive breakpoints, Flexbox centering, aur repeated patterns ke liye mixins banao.
SCSS — Mixins
// Responsive mixin
@mixin respond($bp) {
  @if $bp == tablet {
    @media (min-width: 768px) { @content; }
  } @else if $bp == desktop {
    @media (min-width: 1024px) { @content; }
  }
}

// Flexbox center mixin
@mixin flex-center {
  display: flex;
  justify-content: center;
  align-items: center;
}

// Usage
.hero {
  @include flex-center;
  min-height: 100vh;

  @include respond(tablet) {
    padding: 4rem;
  }
}

Getting your site live

Deployment is the final step. GitHub Pages is free for static sites. Netlify and Vercel offer one-click deploys with custom domains, HTTPS, and CI/CD. Every project you build should be deployed.
