6.1

File I/O — open(), read/write modes, encoding

Reading and writing files

open() returns a file object. Always specify encoding="utf-8". Use with statement to auto-close files. Modes: "r" read, "w" write (truncates!), "a" append, "x" create (fails if exists), "b" binary.

Hindi mein samjhoopen() file object return karta hai. Hamesha encoding="utf-8" specify karo. Files auto-close ke liye with use karo. Modes: "r" read, "w" write (truncate!), "a" append, "x" create, "b" binary.
💻 Python — File I/O
# Read entire file
with open("data.txt", "r", encoding="utf-8") as f:
    content = f.read()        # Entire file as string

# Read line by line (memory efficient)
with open("data.txt", encoding="utf-8") as f:
    for line in f:
        print(line.strip())  # Remove \n

# Read all lines into list
with open("data.txt") as f:
    lines = f.readlines()  # ['line1\n', 'line2\n', ...]

# Write (creates or truncates!)
with open("output.txt", "w", encoding="utf-8") as f:
    f.write("Hello, World!\n")
    f.writelines(["Line 1\n", "Line 2\n"])

# Append (doesn't truncate)
with open("log.txt", "a") as f:
    f.write("New entry\n")

# pathlib — modern file I/O
from pathlib import Path
text = Path("data.txt").read_text(encoding="utf-8")
Path("out.txt").write_text("Hello", encoding="utf-8")

6.2

Context managers — with statement, custom __enter__/__exit__

Automatic resource management

Context managers use with to guarantee cleanup (closing files, releasing locks, etc.). Implement with __enter__/__exit__ methods or the @contextmanager decorator from contextlib.

Hindi mein samjhoContext managers with ke saath cleanup guarantee karte hain (files close, locks release, etc.). __enter__/__exit__ methods ya contextlib se @contextmanager decorator se implement karo.
💻 Python — Context managers
# Built-in with statement
with open("file.txt") as f:
    data = f.read()
# f is automatically closed here, even if error occurs!

# Custom context manager (class-based)
class Timer:
    def __enter__(self):
        import time
        self.start = time.time()
        return self

    def __exit__(self, exc_type, exc_val, exc_tb):
        import time
        self.elapsed = time.time() - self.start
        print(f"Took {self.elapsed:.3f}s")
        return False  # Don't suppress exceptions

with Timer():
    sum(range(1000000))
# Took 0.032s

# Decorator-based (simpler!)
from contextlib import contextmanager

@contextmanager
def managed_file(path):
    f = open(path, "w")
    try:
        yield f
    finally:
        f.close()

with managed_file("test.txt") as f:
    f.write("Hello!")
6.3

CSV files — csv module, DictReader, DictWriter

Tabular data exchange

The csv module handles CSV reading/writing properly (handles commas in fields, quoting, etc.). DictReader maps rows to dicts using headers. DictWriter writes dicts as rows.

Hindi mein samjhocsv module CSV reading/writing properly handle karta hai (fields me commas, quoting, etc.). DictReader rows ko headers use karke dicts me map karta hai. DictWriter dicts ko rows ke roop me likhta hai.
💻 Python — CSV handling
import csv

# Read CSV
with open("students.csv", newline="") as f:
    reader = csv.reader(f)
    header = next(reader)  # Skip header row
    for row in reader:
        print(row)  # ['Alice', '21', '9.5']

# DictReader — rows as dictionaries
with open("students.csv", newline="") as f:
    reader = csv.DictReader(f)
    for row in reader:
        print(row["name"], row["gpa"])

# Write CSV
with open("output.csv", "w", newline="") as f:
    writer = csv.writer(f)
    writer.writerow(["name", "age", "gpa"])
    writer.writerows([
        ["Alice", 21, 9.5],
        ["Bob", 22, 8.7],
    ])

# DictWriter
with open("output.csv", "w", newline="") as f:
    fields = ["name", "age"]
    writer = csv.DictWriter(f, fieldnames=fields)
    writer.writeheader()
    writer.writerow({"name": "Alice", "age": 21})
6.4

JSON files — json.load/dump, custom encoders

The universal data format

json module converts between Python objects and JSON strings/files. json.dump() writes to file, json.loads() parses from string. Custom classes need a custom encoder or default function.

Hindi mein samjhojson module Python objects aur JSON strings/files ke beech convert karta hai. json.dump() file me likhta hai, json.loads() string se parse karta hai. Custom classes ke liye custom encoder ya default function chahiye.
💻 Python — JSON handling
import json

data = {"name": "Yuvraj", "age": 21, "skills": ["Python", "C++"]}

# Python → JSON string
json_str = json.dumps(data, indent=2)
print(json_str)

# JSON string → Python
parsed = json.loads(json_str)

# Write to file
with open("data.json", "w") as f:
    json.dump(data, f, indent=2, ensure_ascii=False)

# Read from file
with open("data.json") as f:
    loaded = json.load(f)

# Custom encoder for non-serializable types
from datetime import datetime

def custom_encoder(obj):
    if isinstance(obj, datetime):
        return obj.isoformat()
    raise TypeError(f"Not serializable: {type(obj)}")

json.dumps({"ts": datetime.now()}, default=custom_encoder)

6.5

Exceptions — try/except/else/finally, exception hierarchy

Handling errors gracefully

try wraps risky code, except catches specific exceptions, else runs if no exception, finally always runs (cleanup). Always catch specific exceptions — never bare except:.

Hindi mein samjhotry risky code wrap karta hai, except specific exceptions catch karta hai, else tab chalta hai jab koi exception na ho, finally hamesha chalta hai (cleanup). Hamesha specific exceptions catch karo — kabhi bare except: mat use karo.
💻 Python — Exception handling
# Basic try/except
try:
    result = 10 / 0
except ZeroDivisionError as e:
    print(f"Error: {e}")

# Multiple exceptions
try:
    value = int(input("Number: "))
    result = 100 / value
except ValueError:
    print("Not a number!")
except ZeroDivisionError:
    print("Can't divide by zero!")
except (TypeError, OverflowError) as e:
    print(f"Other error: {e}")

# else + finally
try:
    f = open("data.txt")
except FileNotFoundError:
    print("File not found")
else:
    data = f.read()   # Only runs if no exception
    f.close()
finally:
    print("Done")  # Always runs

# ❌ NEVER do this:
# except:           # Catches everything including SystemExit!
# except Exception:  # Better but still too broad

6.6

Custom exceptions — creating, raising, chaining

Domain-specific errors

Create custom exceptions by subclassing Exception. Use raise to throw, raise ... from ... for exception chaining. Custom exceptions make error handling more semantic and debuggable.

Hindi mein samjhoCustom exceptions banane ke liye Exception subclass karo. Throw karne ke liye raise, exception chaining ke liye raise ... from ... use karo. Custom exceptions error handling ko zyada semantic aur debuggable banate hain.
💻 Python — Custom exceptions
# Custom exception hierarchy
class AppError(Exception):
    """Base exception for our app."""

class ValidationError(AppError):
    def __init__(self, field, message):
        self.field = field
        super().__init__(f"{field}: {message}")

class NotFoundError(AppError):
    pass

# Raise custom exception
def set_age(age):
    if age < 0:
        raise ValidationError("age", "Must be positive")
    return age

try:
    set_age(-5)
except ValidationError as e:
    print(e)        # age: Must be positive
    print(e.field)  # age

# Exception chaining
try:
    int("abc")
except ValueError as e:
    raise ValidationError("input", "Invalid number") from e
6.7

Logging — logging module, levels, handlers, formatters

Production-grade debugging

Use logging instead of print() for production code. It supports levels (DEBUG → CRITICAL), handlers (console, file, network), and formatters. Never use print for debugging in production apps.

Hindi mein samjhoProduction code me print() ki jagah logging use karo. Ye levels (DEBUG → CRITICAL), handlers (console, file, network), aur formatters support karta hai. Production apps me debugging ke liye kabhi print mat use karo.
💻 Python — Logging
import logging

# Basic setup
logging.basicConfig(
    level=logging.DEBUG,
    format="%(asctime)s [%(levelname)s] %(name)s: %(message)s",
    handlers=[
        logging.FileHandler("app.log"),
        logging.StreamHandler()  # Console
    ]
)

logger = logging.getLogger(__name__)

# Log levels
logger.debug("Variable x = 42")      # Development detail
logger.info("Server started")        # Normal operation
logger.warning("Disk 80% full")      # Something to watch
logger.error("Connection failed")    # Something broke
logger.critical("Database down!")    # System is unusable

# Log exceptions with traceback
try:
    result = 10 / 0
except Exception:
    logger.exception("Division failed")  # Includes traceback!

🏭 Industry insight: In production applications, always use logging over print(), structured logging (JSON format) for log aggregation, and rotating file handlers (RotatingFileHandler) to prevent disk exhaustion. Use with statements for all file operations, and always specify encoding="utf-8" to avoid cross-platform encoding issues.

Data safety checklist (files, parsing, exceptions)

Production reliability in Python depends on defensive data boundaries: validate before parse, fail with explicit context, and never lose critical error information. Most real incidents are caused by silent parsing failures, encoding assumptions, and broad exception swallowing.

Hindi mein samjhoPython production reliability ka core rule hai defensive data boundaries: parse se pehle validate karo, explicit context ke saath fail karo, aur critical errors ko suppress mat karo. Real incidents mostly silent parsing failures, encoding assumptions, aur broad exception handling ki wajah se aate hain.

Error-handling release workflow (service-grade)

Before release, file and exception paths should be validated as rigorously as happy paths: malformed input behavior, partial writes, missing files, permission failures, and log observability under failure.

Hindi mein samjhoRelease se pehle file aur exception paths ko happy path jitna hi seriously test karo: malformed input, partial write, missing files, permission errors, aur failure logs ka behavior verify karo.
