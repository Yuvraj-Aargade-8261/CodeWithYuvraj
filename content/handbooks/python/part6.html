6.1

File Handling Basics — Open, Read, Write, Append

Why file handling matters

File I/O allows persistence of data beyond program runtime: logs, reports, user records, exports, and configuration files. In real systems, correct file strategy affects reliability, portability, and auditability of application behavior.

Hindi mein samjhoFile handling se runtime data durable banta hai. Production apps me logs, reports, backups aur configs sab file I/O pe depend karte hain.

Modes: r, w, a

File mode controls behavior: read existing content, overwrite content, or append new content. Choosing incorrect mode can cause accidental data loss, so mode selection should always match intent explicitly.

Hindi mein samjhoFile mode selection critical hai. Galat mode se data overwrite ya loss ho sakta hai, isliye read/write intent clear rakhna zaruri hai.
Python — write and read file
f = open("notes.txt", "w", encoding="utf-8")
f.write("Python handbook notes\n")
f.close()

f = open("notes.txt", "r", encoding="utf-8")
print(f.read())
f.close()
Example explained: First block writes fresh content; second block opens same file and prints it.
6.2

Context Managers — with open(...) Best Practice

Why with is preferred

Context managers guarantee automatic cleanup, even when errors occur. This prevents resource leaks and locked files. The with pattern is an essential reliability practice and should be considered default for resource management.

Hindi mein samjhowith block safer pattern hai kyunki cleanup automatic hota hai. Error cases me bhi file handles properly close ho jate hain.

Safe read/write pattern

Use one with block per operation for clear flow and reliable file closure. This style keeps side effects localized and simplifies exception boundaries during debugging.

Hindi mein samjhoOne-operation-per-with style se code predictable rehta hai. Debugging aur failure handling dono simpler ho jate hain.
Python — context manager
with open("tasks.txt", "w", encoding="utf-8") as file:
    file.write("Learn exceptions\nPractice logging\n")

with open("tasks.txt", "r", encoding="utf-8") as file:
    print(file.read())
Example explained: File gets closed automatically after each block; no manual cleanup required.
6.3

CSV Handling — Structured Tabular Data

When to use CSV

CSV is useful for spreadsheets, reports, and simple data exchange between systems. It is human-readable and widely interoperable, making it ideal for reporting and lightweight ETL pipelines.

Hindi mein samjhoCSV ka major benefit interoperability hai. Excel, BI tools, scripts sab is format ko easily handle kar lete hain.

Read and write CSV with csv module

Use csv.writer and csv.reader for reliable parsing instead of manual split logic. Built-in parser handles edge cases like quoted commas and escaped values safely.

Hindi mein samjhoManual split approach fragile hota hai. csv module quoting/comma edge cases ko robust tarike se handle karta hai.
Python — csv module
import csv

with open("students.csv", "w", newline="", encoding="utf-8") as f:
    writer = csv.writer(f)
    writer.writerow(["name", "marks"])
    writer.writerow(["Asha", 88])

with open("students.csv", "r", encoding="utf-8") as f:
    reader = csv.reader(f)
    for row in reader:
        print(row)
Example explained: Rows are written as list fields and read back safely as parsed records.
6.4

JSON Handling — API-Style Data Serialization

Why JSON is important

JSON is the standard data format for APIs, configuration files, and service communication. Its structure maps naturally to Python dictionaries/lists, making serialization and deserialization straightforward.

Hindi mein samjhoJSON modern system integration ka default format hai. Python ke dict/list mapping ki wajah se JSON handling practical aur intuitive hoti hai.

Serialize and deserialize

json.dump writes Python data to JSON file; json.load reads JSON back into Python objects. Validate schema assumptions before consuming loaded data to avoid downstream key/type errors.

Hindi mein samjhodump aur load basic operations hain, lekin advanced usage me data schema verify karna bhi important hota hai taaki runtime key/type issues avoid ho.
Python — JSON read/write
import json

data = {"name": "Yuvraj", "skills": ["Python", "Django"]}
with open("profile.json", "w", encoding="utf-8") as f:
    json.dump(data, f, indent=2)

with open("profile.json", "r", encoding="utf-8") as f:
    loaded = json.load(f)
    print(loaded["name"])
Yuvraj
Example explained: Python dictionary is saved in JSON format and then loaded back for normal key access.
6.5

Exception Handling — try, except, else, finally

Why exceptions exist

Exceptions represent runtime failures and allow controlled recovery instead of abrupt program termination. Robust exception handling is a design discipline that separates expected failure modes from truly unexpected faults.

Hindi mein samjhoExceptions runtime failure contract jaisa kaam karte hain. Proper handling se app crash ke bajay controlled recovery aur meaningful feedback deta hai.

Structured try-except flow

Catch specific exceptions first. Use finally for mandatory cleanup operations. Avoid broad bare-except blocks unless absolutely necessary, because they hide root causes and complicate debugging.

Hindi mein samjhoSpecific exception catching best practice hai. Broad exception blocks debugging ko hard bana dete hain, isliye targeted handlers likhna better hota hai.
Python — exception flow
try:
    n = int(input("Enter number: "))
    result = 100 / n
except ValueError:
    print("Invalid input. Enter numeric value.")
except ZeroDivisionError:
    print("Cannot divide by zero.")
else:
    print(f"Result: {result}")
finally:
    print("Execution complete.")
Example explained: Errors are handled by type, success path uses else, and finally runs always.
6.6

Custom Exceptions — Domain-specific Error Design

Why custom exceptions

Custom exceptions make business errors explicit and easier to catch, log, and communicate. They improve domain clarity by encoding business rules directly into exception taxonomy.

Hindi mein samjhoCustom exception se domain rules clearly represent hote hain. Error handling generic nahi rehta, balki business-level semantics ke saath readable ban jata hai.

Create and raise custom exception

Inherit from Exception and raise it where validation fails. Keep exception messages actionable so callers and logs provide enough context for quick triage.

Hindi mein samjhoCustom exception raise karte waqt clear aur actionable message dena important hai taaki issue quickly diagnose ho sake.
Python — custom exception
class InvalidAgeError(Exception):
    pass

def register_user(age):
    if age < 18:
        raise InvalidAgeError("User must be at least 18 years old.")
    return "Registration successful"

try:
    print(register_user(16))
except InvalidAgeError as e:
    print(e)
User must be at least 18 years old.
Example explained: Domain rule violation is represented by a specific exception type.
6.7

Logging — Production-grade Debugging and Monitoring

Why logging over print

Logging provides severity levels, timestamps, and structured diagnostics required in real systems. Unlike print statements, logs can be centralized, filtered by level, and integrated with monitoring pipelines.

Hindi mein samjhoprint() ad-hoc debugging ke liye theek hai, lekin production observability ke liye structured logging zaruri hota hai.

Basic logging setup

Configure logger once and emit logs at appropriate levels: INFO, WARNING, ERROR. Consistent formatting and severity discipline make incident investigation much faster in production.

Hindi mein samjhoLogging setup me level discipline aur consistent format bahut important hai. Isse incident analysis aur troubleshooting significantly fast ho jati hai.
Python — logging
import logging

logging.basicConfig(
    filename="app.log",
    level=logging.INFO,
    format="%(asctime)s - %(levelname)s - %(message)s"
)

logging.info("Application started")
logging.warning("Disk usage is high")
logging.error("Failed to connect database")
Example explained: Logs are written to file with timestamp and severity metadata for production debugging.

Logging patterns: logger name, handlers, and console + file

In real applications, prefer named loggers per module and configure multiple handlers: one for console (dev) and one for file (audit/troubleshooting). This creates clean separation between developer feedback and operational diagnostics.

Hindi mein samjhoProduction apps me usually module-wise named loggers hote hain. Console handler dev ke liye hota hai aur file handler audit/debugging ke liye. Isse logs structured aur maintainable hote hain.
Python — logger with handlers
import logging

logger = logging.getLogger("cwy.app")
logger.setLevel(logging.INFO)

fmt = logging.Formatter("%(asctime)s %(levelname)s %(name)s - %(message)s")

ch = logging.StreamHandler()
ch.setFormatter(fmt)

fh = logging.FileHandler("app.log", encoding="utf-8")
fh.setFormatter(fmt)

logger.addHandler(ch)
logger.addHandler(fh)

logger.info("App started")
Example explained: Same log entry goes to console and file with consistent formatting.
