pathlib — modern file paths, glob, traversal

Object-oriented file system paths

pathlib.Path replaces os.path with an object-oriented API. Paths support / operator for joining, .glob() for pattern matching, and methods for reading, writing, and checking existence. Always prefer pathlib over os.path.

Hindi mein samjhopathlib.Path os.path ko object-oriented API se replace karta hai. Paths / operator se join hote hain, .glob() pattern matching ke liye, aur reading, writing, existence check ke methods hain. Hamesha pathlib prefer karo os.path se.
💻 Python — pathlib
from pathlib import Path

# Create paths
p = Path("src") / "models" / "user.py"
home = Path.home()          # C:\Users\Yuvraj
cwd = Path.cwd()            # Current directory

# Path properties
p.name       # 'user.py'
p.stem       # 'user'
p.suffix     # '.py'
p.parent     # Path('src/models')
p.parts      # ('src', 'models', 'user.py')

# Check existence
p.exists()     # True/False
p.is_file()    # True if file
p.is_dir()     # True if directory

# Read/Write
text = Path("data.txt").read_text(encoding="utf-8")
Path("out.txt").write_text("Hello", encoding="utf-8")
data = Path("image.png").read_bytes()

# Glob — find files by pattern
for py_file in Path("src").glob("**/*.py"):
    print(py_file)  # Recursive!

# Create directories
Path("output/reports").mkdir(parents=True, exist_ok=True)

# Rename / Delete
Path("old.txt").rename("new.txt")
Path("temp.txt").unlink(missing_ok=True)

datetime — dates, times, timedelta, timezones

Working with dates and times

The datetime module handles dates, times, and durations. datetime.now() gets current time. timedelta represents durations. Always use timezone-aware datetimes in production. strftime() formats, strptime() parses.

Hindi mein samjhodatetime module dates, times, aur durations handle karta hai. datetime.now() current time deta hai. timedelta durations represent karta hai. Production me hamesha timezone-aware datetimes use karo. strftime() format karta hai, strptime() parse karta hai.
💻 Python — datetime
from datetime import datetime, date, time, timedelta
from zoneinfo import ZoneInfo  # Python 3.9+

# Current date/time
now = datetime.now()               # Local time (naive)
utc = datetime.now(ZoneInfo("UTC"))  # UTC (aware)
today = date.today()               # Just the date

# Create specific dates
d = date(2026, 4, 27)
dt = datetime(2026, 4, 27, 14, 30)

# Formatting — datetime → string
now.strftime("%Y-%m-%d %H:%M:%S")  # 2026-04-27 14:30:00
now.strftime("%d/%m/%Y")           # 27/04/2026

# Parsing — string → datetime
parsed = datetime.strptime("2026-04-27", "%Y-%m-%d")

# Arithmetic with timedelta
tomorrow = today + timedelta(days=1)
next_week = now + timedelta(weeks=1)
diff = date(2026, 12, 31) - today
print(f"{diff.days} days left in 2026")

# ISO format
now.isoformat()  # '2026-04-27T14:30:00'

# Timezone-aware
ist = ZoneInfo("Asia/Kolkata")
now_ist = datetime.now(ist)

8.3

subprocess — running external commands, pipes

Execute system commands from Python

subprocess.run() executes external commands. Use capture_output=True to get stdout/stderr. check=True raises on non-zero exit. Never use shell=True with user input (security risk!).

Hindi mein samjhosubprocess.run() external commands execute karta hai. stdout/stderr get karne ke liye capture_output=True use karo. check=True non-zero exit pe error raise karta hai. User input ke saath kabhi shell=True mat use karo (security risk!).
💻 Python — subprocess
import subprocess

# Run command and capture output
result = subprocess.run(
    ["python", "--version"],
    capture_output=True,
    text=True
)
print(result.stdout)      # "Python 3.12.0\n"
print(result.returncode)  # 0

# Check for errors
try:
    subprocess.run(
        ["git", "status"],
        check=True,           # Raises on error
        capture_output=True,
        text=True
    )
except subprocess.CalledProcessError as e:
    print(f"Error: {e.stderr}")

# Run with timeout
result = subprocess.run(
    ["ping", "google.com"],
    timeout=5,
    capture_output=True
)

# ⚠️ NEVER do this with user input!
# subprocess.run(user_input, shell=True)  # INJECTION RISK!

Packaging — pyproject.toml, setuptools, publishing

Distributing your code

pyproject.toml is the modern standard for Python project configuration (PEP 518/621). It replaces setup.py and setup.cfg. Use build to create distributions and twine to upload to PyPI.

Hindi mein samjhopyproject.toml Python project configuration ka modern standard hai (PEP 518/621). Ye setup.py aur setup.cfg replace karta hai. Distributions banane ke liye build aur PyPI pe upload karne ke liye twine use karo.
💻 pyproject.toml
# pyproject.toml — modern Python project config
[build-system]
requires = ["setuptools>=68.0", "wheel"]
build-backend = "setuptools.build_meta"

[project]
name = "my-package"
version = "1.0.0"
description = "A useful Python package"
authors = [{name = "Yuvraj", email = "y@mail.com"}]
requires-python = ">=3.10"
dependencies = [
    "requests>=2.28",
    "click>=8.0",
]

[project.optional-dependencies]
dev = ["pytest", "mypy", "ruff"]

[project.scripts]
my-cli = "my_package.cli:main"
💻 Terminal — Build & publish
# Build distribution
pip install build
python -m build  # Creates dist/*.whl and dist/*.tar.gz

# Upload to PyPI
pip install twine
twine upload dist/*

# Install in editable mode (development)
pip install -e .

Project structure — src layout, config, .gitignore

Industry-standard project layout

Use the src layout for distributable packages. Keep tests separate, config in pyproject.toml, and always include .gitignore, README.md, and LICENSE. Use .env for secrets (never commit!).

Hindi mein samjhoDistributable packages ke liye src layout use karo. Tests alag rakho, config pyproject.toml me, aur hamesha .gitignore, README.md, LICENSE include karo. Secrets ke liye .env use karo (commit mat karo!).

Code quality — linting (ruff), formatting (black), pre-commit

Automated code standards

Ruff is the fastest Python linter (replaces flake8, isort, pyupgrade). Black is the opinionated formatter — zero config, consistent output. pre-commit runs checks before every git commit automatically.

Hindi mein samjhoRuff sabse fast Python linter hai (flake8, isort, pyupgrade replace karta hai). Black opinionated formatter hai — zero config, consistent output. pre-commit har git commit se pehle automatically checks run karta hai.
💻 Terminal — Code quality tools
# Install tools
pip install ruff black mypy pre-commit

# Ruff — lint & fix
ruff check .           # Find issues
ruff check . --fix     # Auto-fix issues
ruff format .          # Format (like black)

# Black — format code
black .                # Format all files
black --check .        # Check without modifying

# Mypy — type checking
mypy src/              # Static type check

# Pre-commit — auto-check on git commit
pre-commit install     # Setup hooks
pre-commit run --all-files

Secure Python checklist (production baseline)

Production Python security is mostly about discipline at boundaries: validate all external input, sanitize subprocess/database/file operations, protect secrets, and lock dependency risk. Treat security checks as standard CI gates, not optional tasks.

Hindi mein samjhoProduction Python security ka core rule hai boundary discipline: external input validate karo, subprocess/database/file operations sanitize karo, secrets protect karo, aur dependencies secure rakho. Security checks ko CI gate ka mandatory part banao.
AreaRulePractical implementation
Input validationNever trust user/API/file input directlySchema validation with pydantic or custom validators
SecretsNo hardcoded credentialsUse env vars + secret managers + rotate keys
DependenciesAudit third-party packagesUse pip-audit, pin versions, update regularly
Subprocess safetyAvoid command injection vectorsUse list args, avoid untrusted shell=True
File safetyPrevent path traversal and unsafe writesResolve/normalize paths with pathlib, enforce allowed roots
SerializationAvoid unsafe deserializationPrefer JSON over pickle for untrusted data
Error handlingNo sensitive data in logsMask tokens/passwords, structured sanitized logging

Release workflow (dev to production)

A strong Python release process is repeatable: lint/type/test/security checks pass, lockfile is deterministic, and deployment artifacts are versioned. This reduces regressions and makes rollbacks predictable.

Hindi mein samjhoReliable Python release process repeatable hota hai: lint/type/test/security checks pass, dependencies deterministic hoti hain, aur artifacts versioned hote hain. Isse regressions kam hote hain aur rollback easy hota hai.

mypy src/

# 2) Security gates
