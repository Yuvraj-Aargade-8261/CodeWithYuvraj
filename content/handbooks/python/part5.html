5.1

Classes & objects — __init__, self, instance vs class

Blueprints for objects

A class is a blueprint; an object is an instance of that blueprint. __init__ is the constructor, self refers to the current instance. Class attributes are shared; instance attributes are per-object.

Hindi mein samjhoEk class blueprint hai; ek object us blueprint ka instance hai. __init__ constructor hai, self current instance ko refer karta hai. Class attributes shared hote hain; instance attributes per-object hote hain.
💻 Python — Classes & objects
class Dog:
    # Class attribute — shared by ALL instances
    species = "Canis familiaris"

    def __init__(self, name: str, age: int):
        # Instance attributes — unique per object
        self.name = name
        self.age = age

    def bark(self) -> str:
        return f"{self.name} says Woof!"

    def __str__(self) -> str:
        return f"Dog({self.name}, {self.age})"

# Create instances
rex = Dog("Rex", 5)
buddy = Dog("Buddy", 3)

print(rex.bark())       # Rex says Woof!
print(rex.species)      # Canis familiaris
print(rex)              # Dog(Rex, 5)

# Class method vs static method
class Employee:
    raise_pct = 1.05

    def __init__(self, name, salary):
        self.name = name
        self.salary = salary

    def apply_raise(self):
        self.salary *= self.raise_pct

    @classmethod
    def set_raise_pct(cls, pct):
        cls.raise_pct = pct  # Modifies class attr

    @staticmethod
    def is_workday(day):
        return day.weekday() < 5
ConceptDescriptionKeyword
Instance methodOperates on instance datadef method(self)
Class methodOperates on class data@classmethod
Static methodNo access to class/instance@staticmethod
Instance attributePer-object dataself.x = val
Class attributeShared across instancescls.x = val

Object creation lifecycle — __new__ vs __init__

Object creation is a 2-step process: __new__ allocates memory and creates the instance, then __init__ initializes it. Most classes only need __init__. Override __new__ only for immutable types, singletons, or metaclass magic.

Hindi mein samjhoObject creation 2-step process hai: __new__ memory allocate karta hai aur instance banata hai, phir __init__ usse initialize karta hai. Zyada classes ko sirf __init__ chahiye. __new__ sirf immutable types, singletons, ya metaclass magic ke liye override karo.
StepMethodReceivesReturnsWhen to override
1. Create__new__(cls)Class itselfNew instanceSingletons, immutable types
2. Initialize__init__(self)InstanceNoneAlmost always — set attributes
3. Destroy__del__(self)InstanceNoneResource cleanup (prefer context managers)
Don't use __del__ for cleanup! It's called unpredictably by the garbage collector. Use with statements and __enter__/__exit__ instead.
5.2

Encapsulation — public, _protected, __private, @property

Controlling access to data

Python uses naming conventions (not access modifiers like Java). _name = protected (convention), __name = name-mangled (semi-private). @property creates getter/setter with attribute syntax.

Hindi mein samjhoPython naming conventions use karta hai (Java jaisi access modifiers nahi). _name = protected (convention), __name = name-mangled (semi-private). @property attribute syntax ke saath getter/setter banata hai.
💻 Python — Encapsulation
class BankAccount:
    def __init__(self, owner: str, balance: float = 0):
        self.owner = owner        # Public
        self._bank = "SBI"        # Protected (convention)
        self.__balance = balance   # Private (name-mangled)

    @property
    def balance(self) -> float:
        """Read-only balance."""
        return self.__balance

    @balance.setter
    def balance(self, amount: float):
        if amount < 0:
            raise ValueError("Balance cannot be negative")
        self.__balance = amount

    def deposit(self, amount: float):
        if amount > 0:
            self.__balance += amount

    def withdraw(self, amount: float):
        if 0 < amount <= self.__balance:
            self.__balance -= amount
        else:
            raise ValueError("Insufficient funds")

acc = BankAccount("Yuvraj", 1000)
print(acc.balance)    # 1000 (property getter)
acc.deposit(500)
print(acc.balance)    # 1500
# acc.__balance       ❌ AttributeError
# acc._BankAccount__balance  ✅ Name-mangled access

Name mangling — how Python handles __private

Python doesn't have true private members. __name is "name-mangled" to _ClassName__name to avoid accidental overrides in subclasses. It's not security — it's a collision-prevention mechanism.

Hindi mein samjhoPython me true private members nahi hain. __name ko "name-mangled" karke _ClassName__name bana diya jaata hai subclasses me accidental overrides avoid karne ke liye. Ye security nahi hai — collision-prevention mechanism hai.
ConventionAccessManglingUse case
namePublicNoneNormal attributes and methods
_nameProtectedNone"Internal use" signal — not enforced
__namePrivate_Class__namePrevent subclass collision
__name__SpecialNone (reserved)Dunder/magic methods only
Python philosophy: "We're all consenting adults here." Python trusts developers to respect naming conventions instead of enforcing access control through the language.
5.3

Inheritance — single, multiple, MRO, super()

Code reuse through hierarchy

Inheritance lets child classes reuse parent code. Python supports multiple inheritance. super() calls parent methods. MRO (Method Resolution Order) determines which method is called — follows C3 linearization.

Hindi mein samjhoInheritance child classes ko parent code reuse karne deta hai. Python multiple inheritance support karta hai. super() parent methods call karta hai. MRO decide karta hai kaunsa method call hoga — C3 linearization follow karta hai.
💻 Python — Inheritance
# Single inheritance
class Animal:
    def __init__(self, name):
        self.name = name

    def speak(self):
        raise NotImplementedError

class Dog(Animal):
    def speak(self):
        return f"{self.name}: Woof!"

class Cat(Animal):
    def speak(self):
        return f"{self.name}: Meow!"

# Multiple inheritance
class Flyable:
    def fly(self):
        return "Flying!"

class Swimmable:
    def swim(self):
        return "Swimming!"

class Duck(Animal, Flyable, Swimmable):
    def speak(self):
        return f"{self.name}: Quack!"

donald = Duck("Donald")
donald.speak()  # Donald: Quack!
donald.fly()    # Flying!
donald.swim()   # Swimming!

# super() — call parent constructor
class Puppy(Dog):
    def __init__(self, name, toy):
        super().__init__(name)  # Call Dog.__init__
        self.toy = toy

# MRO — check resolution order
print(Duck.__mro__)
# (Duck, Animal, Flyable, Swimmable, object)

MRO & super() — the C3 linearization algorithm

When using multiple inheritance, Python computes the Method Resolution Order using C3 linearization. super() follows this MRO, not just the immediate parent. This ensures each class's method is called exactly once.

Hindi mein samjhoMultiple inheritance me Python MRO compute karta hai C3 linearization se. super() sirf immediate parent nahi, balki MRO follow karta hai. Ye ensure karta hai ki har class ka method exactly ek baar call ho.
ConceptBehaviorHow to check
MROLeft-to-right, depth-first, then linearizedClass.__mro__ or Class.mro()
super()Calls next class in MRO (not parent!)Always use for cooperative MI
Diamond problemC3 ensures each base called onceD.__mro__ shows the resolved order
Mixin patternSmall behavior classes with no __init__Place mixins before base in class declaration
Cooperative super(): In MI, ALL classes in the hierarchy should call super().__init__(). If any class breaks the chain, initialization of downstream classes is skipped silently.
5.4

Polymorphism — duck typing, abstract base classes

One interface, many implementations

Python uses duck typing: "if it walks like a duck, it's a duck." Objects are checked for method existence at runtime, not class type. Abstract Base Classes (ABC) enforce interface contracts with @abstractmethod.

Hindi mein samjhoPython duck typing use karta hai: "agar wo duck jaisa chale, toh wo duck hai." Objects ki methods runtime pe check hoti hain, class type se nahi. Abstract Base Classes (ABC) @abstractmethod se interface contracts enforce karte hain.
💻 Python — Polymorphism & ABC
# Duck typing — no type check needed
class Circle:
    def area(self):
        return 3.14 * self.r ** 2
    def __init__(self, r): self.r = r

class Square:
    def area(self):
        return self.side ** 2
    def __init__(self, side): self.side = side

# Works with ANY object that has .area()
def print_area(shape):
    print(f"Area: {shape.area()}")

print_area(Circle(5))   # Area: 78.5
print_area(Square(4))   # Area: 16

# Abstract Base Class — enforce interface
from abc import ABC, abstractmethod

class Shape(ABC):
    @abstractmethod
    def area(self) -> float:
        pass

    @abstractmethod
    def perimeter(self) -> float:
        pass

class Rectangle(Shape):
    def __init__(self, w, h):
        self.w, self.h = w, h

    def area(self): return self.w * self.h
    def perimeter(self): return 2 * (self.w + self.h)

# Shape()      ❌ TypeError — can't instantiate abstract class
# Rectangle(3, 4).area()  ✅ 12
5.5

Dunder methods — __str__, __repr__, __eq__, __lt__, __len__

Python protocols via magic methods

Dunder (double-underscore) methods let your classes integrate with Python's syntax: + calls __add__, len() calls __len__, print() calls __str__. They make custom objects behave like built-in types.

Hindi mein samjhoDunder methods tumhari classes ko Python ke syntax se integrate karte hain: + se __add__ call hota hai, len() se __len__, print() se __str__. Ye custom objects ko built-in types jaisa behave karate hain.
💻 Python — Dunder methods
class Vector:
    def __init__(self, x, y):
        self.x, self.y = x, y

    def __repr__(self):
        return f"Vector({self.x}, {self.y})"

    def __str__(self):
        return f"({self.x}, {self.y})"

    def __add__(self, other):
        return Vector(self.x + other.x, self.y + other.y)

    def __eq__(self, other):
        return self.x == other.x and self.y == other.y

    def __lt__(self, other):
        return abs(self) < abs(other)

    def __abs__(self):
        return (self.x**2 + self.y**2) ** 0.5

    def __len__(self):
        return 2

    def __getitem__(self, idx):
        return (self.x, self.y)[idx]

v1 = Vector(3, 4)
v2 = Vector(1, 2)
print(v1 + v2)     # (4, 6)
print(abs(v1))     # 5.0
print(v1 == v2)    # False
print(v1[0])       # 3

Dataclasses & NamedTuple — @dataclass, field(), frozen

Modern data containers

@dataclass (Python 3.7+) auto-generates __init__, __repr__, __eq__, and more. Use frozen=True for immutable instances. field() controls defaults. Far less boilerplate than manual classes.

Hindi mein samjho@dataclass (Python 3.7+) auto __init__, __repr__, __eq__ generate karta hai. Immutable instances ke liye frozen=True. field() defaults control karta hai. Manual classes se bahut kam boilerplate.
💻 Python — Dataclasses
from dataclasses import dataclass, field

@dataclass
class Student:
    name: str
    age: int
    gpa: float = 0.0
    courses: list = field(default_factory=list)

s = Student("Yuvraj", 21, 9.5)
print(s)  # Student(name='Yuvraj', age=21, gpa=9.5, courses=[])

# Auto-generated __eq__
s2 = Student("Yuvraj", 21, 9.5)
s == s2  # True

# Frozen (immutable)
@dataclass(frozen=True)
class Point:
    x: float
    y: float

p = Point(3, 4)
# p.x = 5  ❌ FrozenInstanceError

# With ordering
@dataclass(order=True)
class Score:
    value: int
    name: str = ""

scores = [Score(85), Score(92), Score(78)]
sorted(scores)  # Sorted by value automatically

Design patterns — Singleton, Factory, Observer, Strategy

Proven architectural solutions

Design patterns are reusable solutions to common OOP problems. Python's dynamic nature makes some patterns simpler than in Java/C++. Key patterns: Singleton, Factory, Observer, Strategy.

Hindi mein samjhoDesign patterns common OOP problems ke reusable solutions hain. Python ki dynamic nature se kuch patterns Java/C++ se simple hote hain. Key patterns: Singleton, Factory, Observer, Strategy.
💻 Python — Design patterns
# Singleton — only one instance
class Singleton:
    _instance = None

    def __new__(cls):
        if cls._instance is None:
            cls._instance = super().__new__(cls)
        return cls._instance

a = Singleton()
b = Singleton()
a is b  # True — same object!

# Factory — create objects without specifying class
class ShapeFactory:
    @staticmethod
    def create(shape_type, **kwargs):
        shapes = {"circle": Circle, "square": Square}
        return shapes[shape_type](**kwargs)

# Strategy — swap algorithms at runtime
class Sorter:
    def __init__(self, strategy=sorted):
        self.strategy = strategy

    def sort(self, data):
        return self.strategy(data)

s = Sorter(strategy=lambda x: sorted(x, reverse=True))
s.sort([3,1,2])  # [3, 2, 1]
