3.1

Strings — methods, slicing, f-strings, raw strings

Immutable text sequences

Strings are immutable sequences of Unicode characters. All string methods return new strings. Slicing with [start:stop:step] extracts substrings. Python supports single, double, and triple quotes.

Hindi mein samjhoStrings Unicode characters ki immutable sequences hain. Sab string methods naye strings return karte hain. [start:stop:step] se substrings extract hoti hain. Python single, double, aur triple quotes support karta hai.
💻 Python — String operations
# String creation
s = "Hello, World!"
multi = """Line 1
Line 2
Line 3"""

# Slicing [start:stop:step]
s[0]       # 'H'
s[-1]      # '!'
s[0:5]     # 'Hello'
s[::-1]    # '!dlroW ,olleH' (reverse)
s[7:]      # 'World!'

# Common methods
s.upper()           # 'HELLO, WORLD!'
s.lower()           # 'hello, world!'
s.strip()           # Remove whitespace
s.split(", ")       # ['Hello', 'World!']
"-".join(["a","b"]) # 'a-b'
s.replace("World", "Python")  # 'Hello, Python!'
s.find("World")     # 7 (index or -1)
s.count("l")        # 3
s.startswith("He") # True
s.endswith("!")    # True
s.isdigit()        # False
s.isalpha()        # False (has space, comma)

# String is immutable!
# s[0] = 'h'  # ❌ TypeError!

Unicode & encoding — str vs bytes internals

Python 3 strings are Unicode by default (each char is a Unicode code point). Internally CPython uses 1, 2, or 4 bytes per character depending on content (Latin-1 / UCS-2 / UCS-4). When working with files or network, you must encode (str→bytes) and decode (bytes→str).

Hindi mein samjhoPython 3 strings Unicode by default hain. Internally CPython 1, 2, ya 4 bytes per character use karta hai content ke according. Files ya network ke saath kaam karte waqt encode (str→bytes) aur decode (bytes→str) karna zaruri hai.
TypeContainsMutable?Use case
strUnicode text❌All text processing
bytesRaw byte data (0-255)❌Files, network, binary data
bytearrayRaw byte data (0-255)✅Mutable binary buffers
Always specify encoding: open("file.txt", encoding="utf-8"). On Windows the default is cp1252, not UTF-8. This causes silent data corruption with emoji or non-Latin characters.
3.2

Lists — CRUD, slicing, sorting, copying

Mutable ordered sequences

Lists are Python's most versatile data structure — ordered, mutable, and can hold mixed types. Use append(), insert(), remove(), pop() for CRUD. sort() modifies in-place; sorted() returns a new list.

Hindi mein samjhoLists Python ka sabse versatile data structure hai — ordered, mutable, aur mixed types rakh sakta hai. CRUD ke liye append(), insert(), remove(), pop() use karo. sort() in-place modify karta hai; sorted() naya list return karta hai.
💻 Python — List operations
# Create
nums = [1, 2, 3, 4, 5]
mixed = [1, "hello", True, 3.14]

# CRUD operations
nums.append(6)           # [1,2,3,4,5,6]
nums.insert(0, 0)       # [0,1,2,3,4,5,6]
nums.extend([7, 8])     # [0,1,2,3,4,5,6,7,8]
nums.remove(0)           # Remove first occurrence
last = nums.pop()        # Remove & return last
nums.pop(2)              # Remove at index 2

# Slicing (same as strings)
nums[1:4]    # [2, 3, 4]
nums[::-1]   # Reversed copy
nums[1:4] = [20, 30]  # Slice assignment!

# Sorting
nums.sort()                    # In-place, modifies list
nums.sort(reverse=True)       # Descending
new = sorted(nums)            # Returns new list
new = sorted(nums, key=abs)  # Custom key

# ⚠️ Shallow copy vs deep copy
a = [[1,2], [3,4]]
b = a.copy()       # Shallow — nested lists still shared!
import copy
c = copy.deepcopy(a)  # Deep — fully independent
Shallow copy trap! list.copy(), list[:], and list(original) only copy the top level. Nested objects are still shared references. Use copy.deepcopy() for nested structures.

CPython list internals — dynamic array architecture

Under the hood, a Python list is a dynamic array of pointers (not values). CPython over-allocates memory so append() is usually O(1). When the array fills up, it grows by ~12.5%, causing an occasional O(n) resize.

Hindi mein samjhoPython list internally ek dynamic array of pointers hai (values nahi). CPython memory over-allocate karta hai taaki append() usually O(1) rahe. Jab array bhar jaata hai, ~12.5% grow hota hai.
OperationTimeWhy
list[i]O(1)Direct pointer offset — array[i] = base + i×8
list.append(x)O(1)*Pre-allocated slots; rare resize is O(n)
list.insert(0, x)O(n)Must shift ALL elements right
list.pop()O(1)Just decrement length counter
list.pop(0)O(n)Must shift ALL elements left — use deque
x in listO(n)Linear scan — use set for O(1)
list.sort()O(n log n)Timsort — hybrid merge+insertion sort
Timsort: Python's built-in sort algorithm (invented by Tim Peters for Python). It finds naturally-occurring sorted runs and merges them efficiently. It's stable, adaptive, and has O(n) best case for nearly-sorted data.
3.3

Tuples — immutability, named tuples, unpacking

Immutable ordered sequences

Tuples are like lists but immutable. They're faster, hashable (can be dict keys), and used for fixed data. Named tuples add field names. Unpacking extracts values into variables.

Hindi mein samjhoTuples lists jaisi hain par immutable hain. Ye faster hain, hashable hain (dict keys ban sakte hain), aur fixed data ke liye use hote hain. Named tuples field names add karte hain. Unpacking values ko variables me extract karta hai.
💻 Python — Tuples
# Create tuples
point = (3, 4)
single = (42,)  # Single item needs trailing comma!
empty = ()

# Unpacking
x, y = point              # x=3, y=4
first, *rest = [1,2,3,4]  # first=1, rest=[2,3,4]
_, mid, _ = (1, 2, 3)     # Ignore with _

# Swap without temp variable
a, b = 1, 2
a, b = b, a  # a=2, b=1 (tuple swap!)

# Named tuples — readable tuples
from collections import namedtuple

Point = namedtuple("Point", ["x", "y"])
p = Point(3, 4)
print(p.x, p.y)  # 3, 4 (access by name!)

# Tuples as dict keys (lists can't!)
grid = {(0,0): "origin", (1,0): "right"}
3.4

Dictionaries — methods, merging (|), defaultdict

Key-value pairs

Dictionaries store key-value pairs with O(1) average lookup. Keys must be hashable (immutable). Since Python 3.7, dicts preserve insertion order. Use .get() for safe access, | (Python 3.9+) for merging.

Hindi mein samjhoDictionaries key-value pairs store karte hain O(1) average lookup ke saath. Keys hashable (immutable) honi chahiye. Python 3.7 se dicts insertion order preserve karte hain. Safe access ke liye .get(), merging ke liye | (Python 3.9+) use karo.
💻 Python — Dictionaries
# Create
person = {"name": "Yuvraj", "age": 21}
person = dict(name="Yuvraj", age=21)

# Access
person["name"]           # 'Yuvraj'
person.get("email", "N/A") # 'N/A' (safe!)

# CRUD
person["email"] = "y@mail.com"  # Add/update
del person["email"]              # Delete
age = person.pop("age", 0)       # Remove & return

# Iteration
for key in person:               # Keys
    print(key)
for k, v in person.items():     # Key-value pairs
    print(f"{k}: {v}")

# Merging (Python 3.9+)
d1 = {"a": 1}
d2 = {"b": 2}
merged = d1 | d2  # {'a': 1, 'b': 2}
d1 |= d2          # In-place merge

# setdefault — get or set default
counts = {}
counts.setdefault("apple", 0)
counts["apple"] += 1

# defaultdict — auto-default values
from collections import defaultdict
word_count = defaultdict(int)
for word in "hello world hello".split():
    word_count[word] += 1
# {'hello': 2, 'world': 1}

Hash table internals — how dicts actually work

Python dicts use a hash table: when you set d[key] = val, Python calls hash(key) to compute a bucket index, then stores the key-value pair. Collisions are resolved via open addressing (probing). The __hash__/__eq__ contract is critical.

Hindi mein samjhoPython dicts hash table use karte hain: jab aap d[key] = val set karte ho, Python hash(key) call karke bucket index compute karta hai. Collisions open addressing (probing) se resolve hoti hain.
StepWhat happensRequirement
1. Hashhash(key) computes integer hashKey must be hashable (__hash__ defined)
2. Indexhash % table_size = bucket indexTable auto-resizes at 2/3 full
3. ProbeIf bucket occupied, try next slots__eq__ needed to resolve collisions
4. StorePlace (hash, key, value) in slotSame key overwrites existing value
The hash/eq contract: If a == b, then hash(a) == hash(b) MUST be true. If you define __eq__ in a class, you MUST also define __hash__, or instances become unhashable (can't be dict keys).
3.5

Sets — operations, frozen sets, membership testing

Unordered unique collections

Sets hold unique elements with O(1) membership testing. They support mathematical operations: union |, intersection &, difference -, symmetric difference ^. frozenset is immutable (can be dict key).

Hindi mein samjhoSets unique elements hold karte hain O(1) membership testing ke saath. Ye mathematical operations support karte hain: union |, intersection &, difference -, symmetric difference ^. frozenset immutable hai (dict key ban sakta hai).
💻 Python — Sets
# Create
fruits = {"apple", "banana", "cherry"}
nums = set([1,2,3,2,1])  # {1, 2, 3} — duplicates removed!
empty = set()  # NOT {} (that's an empty dict!)

# Operations
a = {1, 2, 3}
b = {2, 3, 4}
a | b   # {1, 2, 3, 4} — union
a & b   # {2, 3}       — intersection
a - b   # {1}          — difference
a ^ b   # {1, 4}       — symmetric diff

# Membership (O(1) — FAST!)
3 in a    # True
5 in a    # False

# Modify
a.add(5)
a.discard(99)  # No error if missing
a.remove(1)    # KeyError if missing

# frozenset — immutable set
fs = frozenset([1, 2, 3])
d = {fs: "frozen!"}  # Can be dict key

# Practical: remove duplicates
names = ["Alice", "Bob", "Alice"]
unique = list(set(names))  # ['Alice', 'Bob']
3.6

Collections module — Counter, deque, OrderedDict, ChainMap

Specialized containers

The collections module provides high-performance container alternatives. Counter counts elements, deque is a fast double-ended queue, defaultdict provides default values, ChainMap combines multiple dicts.

Hindi mein samjhocollections module high-performance container alternatives provide karta hai. Counter elements count karta hai, deque fast double-ended queue hai, defaultdict default values deta hai, ChainMap multiple dicts combine karta hai.
💻 Python — collections module
from collections import Counter, deque, defaultdict, ChainMap

# Counter — count elements
c = Counter("abracadabra")
# Counter({'a': 5, 'b': 2, 'r': 2, 'c': 1, 'd': 1})
c.most_common(2)  # [('a', 5), ('b', 2)]

# Counter arithmetic
c1 = Counter(a=3, b=1)
c2 = Counter(a=1, b=2)
c1 + c2  # Counter({'a': 4, 'b': 3})
c1 - c2  # Counter({'a': 2})

# deque — fast append/pop from both ends
dq = deque([1, 2, 3], maxlen=5)
dq.appendleft(0)  # O(1) — lists are O(n)!
dq.rotate(1)       # [3, 0, 1, 2]

# defaultdict — auto-creates missing keys
groups = defaultdict(list)
for name, grade in [("Alice","A"), ("Bob","B"), ("Alice","A+")]:
    groups[name].append(grade)
# {'Alice': ['A', 'A+'], 'Bob': ['B']}

# ChainMap — search multiple dicts
defaults = {"color": "blue", "size": "M"}
user = {"color": "red"}
config = ChainMap(user, defaults)
config["color"]  # 'red' (user wins)
config["size"]   # 'M' (falls back to defaults)

Choosing the right container
