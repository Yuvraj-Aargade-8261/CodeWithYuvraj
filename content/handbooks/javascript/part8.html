8.1

Design Patterns — Singleton, Observer, Factory, Module, Strategy

Proven solutions to common problems

Design patterns are reusable solutions to recurring problems. Singleton: one instance. Observer: pub/sub events. Factory: create objects without new. Module: encapsulate with closures. Strategy: swap algorithms at runtime.

Hindi mein samjhoDesign patterns recurring problems ke reusable solutions hain. Singleton: ek hi instance. Observer: pub/sub events. Factory: bina new ke objects banao. Strategy: runtime pe algorithms swap karo.
💻 JavaScript — Design Patterns
// ✅ Singleton — one instance only
class Database {
    static #instance;
    constructor(url) {
        if (Database.#instance) return Database.#instance;
        this.url = url;
        Database.#instance = this;
    }
}
const db1 = new Database("mongodb://...");
const db2 = new Database("other");
db1 === db2; // true! Same instance

// ✅ Observer — event-driven communication
class EventEmitter {
    #listeners = {};
    on(event, fn) {
        (this.#listeners[event] ??= []).push(fn);
    }
    emit(event, ...args) {
        (this.#listeners[event] ?? []).forEach(fn => fn(...args));
    }
    off(event, fn) {
        this.#listeners[event] = (this.#listeners[event] ?? [])
            .filter(f => f !== fn);
    }
}
const bus = new EventEmitter();
bus.on("login", user => console.log(`Welcome ${user}`));
bus.emit("login", "Alice");

// ✅ Factory — create without new
function createUser(type, name) {
    const roles = {
        admin: { name, permissions: ["read","write","delete"] },
        viewer: { name, permissions: ["read"] }
    };
    return roles[type] ?? roles.viewer;
}

// ✅ Strategy — swap algorithms
const strategies = {
    percentage: (price, val) => price * (1 - val / 100),
    fixed: (price, val) => price - val,
    bogo: (price) => price / 2
};
function applyDiscount(price, type, value) {
    return strategies[type](price, value);
}
8.2

Clean Code — naming, functions, SOLID principles, refactoring

Code that humans can read

Clean code is readable, maintainable, and testable. Use descriptive names. Keep functions small and focused (one thing). DRY: Don't Repeat Yourself. SOLID: Single responsibility, Open/closed, Liskov substitution, Interface segregation, Dependency inversion.

Hindi mein samjhoClean code readable, maintainable aur testable hota hai. Descriptive names use karo. Functions chhote aur focused rakho (ek kaam). DRY: code repeat mat karo.
💻 JavaScript — Clean Code
// ❌ Bad — unclear names, does too much
function proc(d) {
    let r = [];
    for (let i = 0; i < d.length; i++) {
        if (d[i].a > 18 && d[i].s === "active") {
            r.push(d[i].n.toUpperCase());
        }
    }
    return r;
}

// ✅ Good — descriptive, composable, readable
const isAdult = (user) => user.age > 18;
const isActive = (user) => user.status === "active";
const toDisplayName = (user) => user.name.toUpperCase();

function getActiveAdultNames(users) {
    return users
        .filter(isAdult)
        .filter(isActive)
        .map(toDisplayName);
}

// ✅ Guard clauses — avoid deep nesting
// ❌ Bad
function processOrder(order) {
    if (order) {
        if (order.items.length > 0) {
            if (order.isPaid) { /* deep logic */ }
        }
    }
}
// ✅ Good
function processOrder(order) {
    if (!order) return;
    if (order.items.length === 0) return;
    if (!order.isPaid) return;
    // Main logic here — flat and clear
}
8.3

Functional Patterns — immutability, pure functions, composition, currying

Think in transformations

Pure functions: same input → same output, no side effects. Immutability: never mutate data, return new copies. Composition: combine small functions into complex ones. Currying: transform f(a, b) into f(a)(b). These patterns reduce bugs dramatically.

Hindi mein samjhoPure functions: same input → same output, koi side effects nahi. Immutability: data kabhi mutate mat karo, new copies return karo. Composition: chhoti functions ko combine karke complex banao.
💻 JavaScript — Functional Patterns
// ✅ Pure function — no side effects
const add = (a, b) => a + b;         // Pure ✅
const addTax = (price) => price * 1.18; // Pure ✅

// ✅ Immutable updates
const addItem = (cart, item) => [...cart, item];
const removeItem = (cart, id) => cart.filter(i => i.id !== id);
const updateQty = (cart, id, qty) =>
    cart.map(i => i.id === id ? { ...i, qty } : i);

// ✅ Function composition
const pipe = (...fns) => (x) => fns.reduce((v, f) => f(v), x);

const processPrice = pipe(
    price => price * 0.9,      // 10% discount
    price => price * 1.18,     // Add 18% tax
    price => Math.round(price) // Round
);
processPrice(1000); // 1062

// ✅ Currying
const multiply = (a) => (b) => a * b;
const double = multiply(2);
const triple = multiply(3);
double(5);  // 10
triple(5);  // 15
[1,2,3].map(double); // [2,4,6]

// Partial application
const log = (level) => (message) =>
    console.log(`[${level}] ${message}`);
const info = log("INFO");
const error = log("ERROR");
info("Server started"); // [INFO] Server started
8.4

Security — XSS, CSRF, Content Security Policy, input sanitization

Writing secure JavaScript

XSS (Cross-Site Scripting): never use innerHTML with user input — use textContent. CSRF: validate tokens on state-changing requests. CSP headers restrict what scripts can run. Always validate and sanitize input on both client and server.

Hindi mein samjhoXSS: user input ke saath kabhi innerHTML mat use karo — textContent use karo. CSRF: state-changing requests pe tokens validate karo. Input ko client aur server dono pe validate aur sanitize karo.
💻 JavaScript — Security
// ❌ XSS vulnerability — NEVER do this
el.innerHTML = userInput; // Attacker can inject <script>

// ✅ Safe alternatives
el.textContent = userInput; // Escaped automatically

// ✅ Sanitize HTML if you must render it
function sanitize(html) {
    const div = document.createElement("div");
    div.textContent = html;
    return div.innerHTML; // Entities escaped
}

// ✅ Content Security Policy (HTTP header)
// Content-Security-Policy: script-src 'self'; style-src 'self'

// ✅ Avoid eval() — biggest security hole
// eval(userInput); // ❌ NEVER
// new Function(userInput); // ❌ NEVER

// ✅ Validate inputs
function validateEmail(email) {
    return /^[\w.-]+@[\w.-]+\.\w{2,}$/.test(email);
}

// ✅ Use HttpOnly cookies for auth tokens
// Set-Cookie: token=abc; HttpOnly; Secure; SameSite=Strict
8.5

Performance — lazy loading, memoization, Web Workers, requestAnimationFrame

Making apps fast

Memoization caches function results. Web Workers run heavy computation off the main thread. requestAnimationFrame ensures smooth 60fps animations. Lazy loading defers non-critical resources. Virtual scrolling renders only visible items.

Hindi mein samjhoMemoization function results cache karta hai. Web Workers heavy computation main thread se alag run karte hain. requestAnimationFrame smooth 60fps animations ensure karta hai.
💻 JavaScript — Performance
// ✅ Memoization — cache expensive results
function memoize(fn) {
    const cache = new Map();
    return (...args) => {
        const key = JSON.stringify(args);
        if (cache.has(key)) return cache.get(key);
        const result = fn(...args);
        cache.set(key, result);
        return result;
    };
}
const expensiveCalc = memoize((n) => {
    console.log("Computing...");
    return n * n;
});
expensiveCalc(5); // Computes
expensiveCalc(5); // Cached!

// ✅ requestAnimationFrame — smooth animations
function animate(timestamp) {
    element.style.transform = `translateX(${timestamp / 10}px)`;
    requestAnimationFrame(animate);
}
requestAnimationFrame(animate);

// ✅ Web Worker — off-main-thread
// worker.js
// self.onmessage = (e) => {
//     const result = heavyComputation(e.data);
//     self.postMessage(result);
// };
const worker = new Worker("worker.js");
worker.postMessage(data);
worker.onmessage = (e) => console.log(e.data);

Interview Prep — common questions, coding challenges, concepts checklist

Ace the JavaScript interview

Hindi mein samjhoTop interview topics: closures, this keyword, event loop, prototypes vs classes. debounce, throttle, deepClone, flatten scratch se likhna aana chahiye.
💻 JavaScript — Interview Classics
// Q1: What does this output?
for (var i = 0; i < 3; i++) {
    setTimeout(() => console.log(i), 100);
}
// Answer: 3, 3, 3 (var is function-scoped!)
// Fix: use let (block-scoped)

// Q2: Implement Array.prototype.flat
function flat(arr, depth = 1) {
    if (depth === 0) return [...arr];
    return arr.reduce((acc, val) =>
        Array.isArray(val)
            ? [...acc, ...flat(val, depth - 1)]
            : [...acc, val]
    , []);
}

// Q3: Implement curry
function curry(fn) {
    return function curried(...args) {
        if (args.length >= fn.length) return fn(...args);
        return (...more) => curried(...args, ...more);
    };
}
const sum3 = curry((a, b, c) => a + b + c);
sum3(1)(2)(3); // 6
sum3(1, 2)(3); // 6

// Q4: Explain event loop output
console.log("A");
setTimeout(() => console.log("B"), 0);
Promise.resolve().then(() => console.log("C"));
console.log("D");
// Answer: A, D, C, B

Deep Clone — implement from scratch

Common interview question: implement structuredClone from scratch. Handle objects, arrays, dates, maps, sets, and circular references. Modern JS: just use structuredClone() built-in.

Hindi mein samjhoCommon interview question: structuredClone scratch se implement karo. Objects, arrays, dates handle karo. Modern JS me: sirf structuredClone() built-in use karo.
💻 JavaScript — Deep Clone
// ✅ Manual deep clone (interview version)
function deepClone(obj, seen = new WeakMap()) {
    if (obj === null || typeof obj !== "object") return obj;
    if (seen.has(obj)) return seen.get(obj); // Circular!

    if (obj instanceof Date) return new Date(obj);
    if (obj instanceof RegExp) return new RegExp(obj);
    if (obj instanceof Map) {
        const map = new Map();
        seen.set(obj, map);
        obj.forEach((v, k) => map.set(deepClone(k, seen), deepClone(v, seen)));
        return map;
    }
    if (obj instanceof Set) {
        const set = new Set();
        seen.set(obj, set);
        obj.forEach(v => set.add(deepClone(v, seen)));
        return set;
    }

    const clone = Array.isArray(obj) ? [] : {};
    seen.set(obj, clone);
    for (const key of Reflect.ownKeys(obj)) {
        clone[key] = deepClone(obj[key], seen);
    }
    return clone;
}

// ✅ Modern JS — just use structuredClone()
const copy = structuredClone(original); // Built-in!

RegExp — pattern matching essentials

Regular expressions match patterns in strings. Use test() for boolean, match() for results, replace() for substitution. Master character classes, quantifiers, groups, and lookaheads for interview questions.

Hindi mein samjhoRegular expressions strings me patterns match karte hain. test() boolean ke liye, match() results ke liye, replace() substitution ke liye use karo.
💻 JavaScript — RegExp
// ✅ Common patterns
const email = /^[\w.-]+@[\w.-]+\.\w{2,}$/;
const phone = /^\+?\d{10,15}$/;
const url = /^https?:\/\/[\w.-]+\.\w{2,}/;
const slug = /^[a-z0-9]+(?:-[a-z0-9]+)*$/;

email.test("alice@example.com"); // true

// ✅ Named capture groups (ES2018)
const datePattern = /(?<year>\d{4})-(?<month>\d{2})-(?<day>\d{2})/;
const match = "2024-03-15".match(datePattern);
match.groups.year;  // "2024"
match.groups.month; // "03"

// ✅ Replace with function
"hello world".replace(/\b\w/g, c => c.toUpperCase());
// "Hello World"

// ✅ matchAll — iterate all matches
const text = "Call 123-456 or 789-012";
for (const m of text.matchAll(/\d{3}-\d{3}/g)) {
    console.log(m[0]); // "123-456", "789-012"
}
