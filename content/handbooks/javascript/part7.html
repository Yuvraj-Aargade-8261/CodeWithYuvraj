7.1

ES Modules — import/export, named, default, dynamic import()

Organizing code into files

ES Modules (ESM) are the standard module system. export exposes values, import consumes them. Named exports for multiple values, default export for the primary value. import() enables dynamic/lazy loading. Use type="module" in <script> tags.

Hindi mein samjhoES Modules standard module system hai. export values expose karta hai, import consume karta hai. Named exports multiple values ke liye, default export primary value ke liye. import() se dynamic/lazy loading hoti hai.
💻 JavaScript — ES Modules
// ── utils.js ──
// Named exports
export const PI = 3.14159;
export function add(a, b) { return a + b; }
export class Vector {
    constructor(x, y) { this.x = x; this.y = y; }
}

// Default export (one per file)
export default class Calculator {
    add(a, b) { return a + b; }
}

// ── app.js ──
// Named imports (must match export names)
import { PI, add, Vector } from "./utils.js";
import { add as sum } from "./utils.js"; // Rename

// Default import (any name)
import Calculator from "./utils.js";
import Calc, { PI } from "./utils.js"; // Both

// Import all as namespace
import * as Utils from "./utils.js";
Utils.add(1, 2); Utils.PI;

// ✅ Dynamic import — lazy loading
const btn = document.querySelector("#chart-btn");
btn.addEventListener("click", async () => {
    const { renderChart } = await import("./chart.js");
    renderChart(data); // Loaded only when needed!
});

// In HTML
// <script type="module" src="app.js"></script>
Best practice: Prefer named exports — they enable tree-shaking (bundlers remove unused code). Reserve default exports for React components or single-class files.
7.2

npm — package.json, dependencies, scripts, semantic versioning

The JavaScript package manager

npm manages dependencies. package.json defines your project. npm install adds packages. Semantic versioning: ^1.2.3 means ≥1.2.3 <2.0.0. devDependencies are build-time only. scripts automate tasks. npx runs packages without installing.

Hindi mein samjhonpm dependencies manage karta hai. package.json project define karta hai. Semantic versioning: ^1.2.3 matlab ≥1.2.3 <2.0.0. scripts se tasks automate hote hain. npx bina install kiye packages run karta hai.
💻 Terminal / package.json
# Initialize project
npm init -y

# Install dependencies
npm install express        # Production dependency
npm install -D vitest      # Dev dependency
npm install -g typescript  # Global

# package.json
{
    "name": "my-app",
    "version": "1.0.0",
    "type": "module",  // Enable ESM
    "scripts": {
        "dev": "vite",
        "build": "vite build",
        "test": "vitest",
        "lint": "eslint ."
    },
    "dependencies": {
        "express": "^4.18.0"
    },
    "devDependencies": {
        "vitest": "^1.0.0"
    }
}

# Run scripts
npm run dev     # Run dev script
npm test        # Shorthand for npm run test
npx create-vite # Run without installing

Bundlers — Vite, Webpack concepts, tree-shaking, code splitting

Building for production

Bundlers combine modules into optimized files. Vite (fastest) uses native ESM in dev, Rollup for production. Tree-shaking removes unused exports. Code splitting creates chunks loaded on demand. HMR (Hot Module Replacement) updates without refresh.

Hindi mein samjhoBundlers modules ko optimized files me combine karte hain. Vite (fastest) dev me native ESM use karta hai. Tree-shaking unused exports remove karta hai. Code splitting on-demand chunks banata hai.
💻 Terminal — Vite Setup
# Create Vite project
npm create vite@latest my-app -- --template vanilla
cd my-app
npm install
npm run dev    # Dev server with HMR
npm run build  # Production build

# Output: dist/
# ├── index.html
# ├── assets/
# │   ├── index-abc123.js   (minified + tree-shaken)
# │   └── index-def456.css  (minified)

# vite.config.js
import { defineConfig } from "vite";

export default defineConfig({
    build: {
        rollupOptions: {
            output: {
                manualChunks: {
                    vendor: ["lodash", "axios"]
                }
            }
        }
    }
});

Vite⚡ FastestModern projects, SPAs

Linting & Formatting — ESLint, Prettier, editor integration

Consistent, error-free code

ESLint catches bugs and enforces coding standards. Prettier auto-formats code. Together they ensure consistent style across teams. Use eslint.config.js (flat config) with recommended rules. Integrate with your editor for real-time feedback.

Hindi mein samjhoESLint bugs pakadta hai aur coding standards enforce karta hai. Prettier code auto-format karta hai. Dono milke team me consistent style ensure karte hain.
💻 Terminal / Config
# Install ESLint + Prettier
npm install -D eslint prettier eslint-config-prettier

# eslint.config.js (flat config — ESLint 9+)
import js from "@eslint/js";
export default [
    js.configs.recommended,
    {
        rules: {
            "no-unused-vars": "warn",
            "no-console": "warn",
            "prefer-const": "error",
            "eqeqeq": "error"  // Force ===
        }
    }
];

# .prettierrc
{
    "semi": true,
    "singleQuote": false,
    "tabWidth": 4,
    "printWidth": 100
}

# Run
npx eslint .           # Check
npx eslint --fix .     # Auto-fix
npx prettier --write . # Format all
7.5

Testing — Vitest, unit tests, test structure, assertions, mocking

Writing reliable code

Vitest is the modern test runner (compatible with Jest API). Use describe/it/expect structure. Unit tests test individual functions. Mocking replaces dependencies. Test-Driven Development (TDD): write tests first, then code.

Hindi mein samjhoVitest modern test runner hai. describe/it/expect structure use karo. Unit tests individual functions test karte hain. TDD: pehle tests likho, phir code likho.
💻 JavaScript — Testing with Vitest
// math.js
export function add(a, b) { return a + b; }
export function divide(a, b) {
    if (b === 0) throw new Error("Division by zero");
    return a / b;
}

// math.test.js
import { describe, it, expect } from "vitest";
import { add, divide } from "./math.js";

describe("add", () => {
    it("adds two numbers", () => {
        expect(add(1, 2)).toBe(3);
    });
    it("handles negative numbers", () => {
        expect(add(-1, -2)).toBe(-3);
    });
});

describe("divide", () => {
    it("divides correctly", () => {
        expect(divide(10, 2)).toBe(5);
    });
    it("throws on zero", () => {
        expect(() => divide(1, 0)).toThrow("Division by zero");
    });
});

// Common assertions
expect(value).toBe(exact);
expect(value).toEqual(deepEqual);
expect(arr).toContain(item);
expect(obj).toHaveProperty("key");
expect(fn).toHaveBeenCalledWith(args);
7.6

TypeScript Intro — types, interfaces, generics, why TypeScript

JavaScript with superpowers

TypeScript adds static types to JavaScript. Catches bugs at compile time, enables better IDE support, and documents your code. Interfaces define object shapes. Generics create reusable typed code. All valid JS is valid TS.

Hindi mein samjhoTypeScript JavaScript me static types add karta hai. Compile time pe bugs pakadta hai, better IDE support deta hai. Interfaces object shapes define karte hain. Sab valid JS valid TS hai.
💻 TypeScript — Basics
// Basic types
let name: string = "Alice";
let age: number = 25;
let active: boolean = true;
let items: string[] = ["a", "b"];

// Function types
function greet(name: string, age?: number): string {
    return `Hi ${name}`;
}

// Interface — define object shape
interface User {
    id: number;
    name: string;
    email: string;
    role?: "admin" | "user"; // Optional + union
}

function createUser(data: User): User {
    return { ...data, role: data.role ?? "user" };
}

// Generics — reusable typed code
function first<T>(arr: T[]): T | undefined {
    return arr[0];
}
first([1,2,3]);        // type: number
first(["a","b"]);      // type: string

DevTools — debugging, breakpoints, network tab, performance profiling

Debug like a pro

Chrome DevTools is your best friend. Console: console.table(), console.group(), console.time(). Debugger: set breakpoints, step through code, inspect variables. Network tab: analyze requests. Performance tab: find bottlenecks.

Hindi mein samjhoChrome DevTools tumhara best friend hai. Console me console.table(), console.group() use karo. Debugger me breakpoints lagao, step through karo. Network tab se requests analyze karo.
💻 JavaScript — DevTools Tips
// ✅ Advanced console methods
console.table([{name:"Alice",age:25},{name:"Bob",age:30}]);
console.group("User Data");
  console.log("Name:", name);
  console.log("Age:", age);
console.groupEnd();

// Timing
console.time("fetch");
await fetch("/api/data");
console.timeEnd("fetch"); // "fetch: 234ms"

// Conditional logging
console.assert(x > 0, "x must be positive");

// ✅ debugger statement — pause execution

    debugger; // Pauses here in DevTools!
    return data.map(x => x.value);
}

// Styled console
console.log("%cSuccess!", "color:green;font-size:20px");

TypeScript Utility Types

TypeScript provides built-in utility types to transform types: Partial makes all properties optional, Required makes all required, Pick selects specific properties, Omit excludes properties. These eliminate repetitive type definitions.

Hindi mein samjhoTypeScript built-in utility types deta hai types transform karne ke liye: Partial sab properties optional banata hai, Pick specific properties select karta hai, Omit properties exclude karta hai.
💻 TypeScript — Utility Types
interface User {
    id: number;
    name: string;
    email: string;
    age: number;
}

// Partial — all optional
type UpdateUser = Partial<User>;
// { id?: number; name?: string; email?: string; age?: number }

// Required — all required
type StrictUser = Required<User>;

// Pick — select specific properties
type UserPreview = Pick<User, "id" | "name">;
// { id: number; name: string }

// Omit — exclude properties
type CreateUser = Omit<User, "id">;
// { name: string; email: string; age: number }

// Record — key-value mapping
type UserRoles = Record<string, "admin" | "user">;

// ReturnType — infer return type
function getUser() { return { id: 1, name: "Alice" }; }
type UserResult = ReturnType<typeof getUser>;
// { id: number; name: string }
