5.1

Event Loop — call stack, task queue, microtask queue, setTimeout

How JavaScript handles async

JS is single-threaded but non-blocking via the Event Loop. The Call Stack executes synchronous code. Async callbacks go to the Task Queue (macrotasks: setTimeout, setInterval). Promises go to the Microtask Queue (higher priority). Microtasks always run before macrotasks.

Hindi mein samjhoJS single-threaded hai lekin non-blocking hai Event Loop ki wajah se. Call Stack synchronous code run karta hai. Async callbacks Task Queue me jaate hain. Promises Microtask Queue me jaate hain (higher priority). Microtasks hamesha macrotasks se pehle run hote hain.
💻 JavaScript — Event Loop
// ✅ Event loop order demonstration
console.log("1. Synchronous");

setTimeout(() => console.log("2. Macrotask (setTimeout)"), 0);

Promise.resolve().then(() => console.log("3. Microtask (Promise)"));

console.log("4. Synchronous");

// Output order:
// 1. Synchronous
// 4. Synchronous
// 3. Microtask (Promise)  ← runs BEFORE setTimeout!
// 2. Macrotask (setTimeout)

// ✅ Why? Execution order:
// 1. Call stack runs all synchronous code
// 2. Microtask queue is drained (Promises)
// 3. One macrotask runs (setTimeout)
// 4. Repeat from step 2

// ✅ More complex example
setTimeout(() => console.log("A"), 0);
setTimeout(() => console.log("B"), 0);
Promise.resolve().then(() => {
    console.log("C");
    Promise.resolve().then(() => console.log("D"));
});
Promise.resolve().then(() => console.log("E"));
console.log("F");
// Output: F, C, E, D, A, B

// queueMicrotask — explicitly add microtask
queueMicrotask(() => console.log("microtask"));

// setTimeout(fn, 0) doesn't mean "run immediately"
// It means "run after current stack + microtasks clear"
QueuePriorityExamples
Call StackImmediateSynchronous code
Microtask QueueHigh.then(), queueMicrotask, MutationObserver
Macrotask QueueLowsetTimeout, setInterval, I/O, UI rendering
5.2

Promises — new Promise, then/catch/finally, chaining, states

The foundation of async JS

A Promise represents a future value. Three states: pending, fulfilled, rejected. .then() handles success, .catch() handles errors, .finally() always runs. Promises are immutable once settled — can't go back to pending. Chain .then() for sequential async.

Hindi mein samjhoPromise future value represent karta hai. Teen states: pending, fulfilled, rejected. .then() success handle karta hai, .catch() errors, .finally() hamesha run hota hai. Promises settle hone ke baad change nahi hote.
💻 JavaScript — Promises
// ✅ Creating a Promise
const promise = new Promise((resolve, reject) => {
    const success = true;
    setTimeout(() => {
        success ? resolve("Data loaded!") : reject(new Error("Failed"));
    }, 1000);
});

// Consuming
promise
    .then(data => console.log(data))
    .catch(err => console.error(err))
    .finally(() => console.log("Done"));

// ✅ Chaining — each .then returns a new Promise
fetch("/api/user/1")
    .then(res => res.json())           // Parse JSON
    .then(user => fetch(`/api/posts/${user.id}`))
    .then(res => res.json())           // Parse posts
    .then(posts => console.log(posts))
    .catch(err => console.error(err)); // Catches ANY error

// ✅ Returning values in .then()
Promise.resolve(1)
    .then(x => x + 1)   // 2
    .then(x => x * 3)   // 6
    .then(console.log);  // 6

// ✅ Promise.resolve / Promise.reject — shortcuts
Promise.resolve("instant").then(console.log);
Promise.reject(new Error("fail")).catch(console.error);

// Wrapping callback APIs into Promises
function delay(ms) {
    return new Promise(resolve => setTimeout(resolve, ms));
}
delay(2000).then(() => console.log("2s later"));
5.3

Async/Await — async functions, await, error handling, top-level await

Promises made beautiful

async functions always return a Promise. await pauses execution until the Promise settles — making async code look synchronous. Use try/catch for error handling. Top-level await works in ES modules. await only works inside async functions.

Hindi mein samjhoasync functions hamesha Promise return karte hain. await execution pause karta hai jab tak Promise settle na ho — async code synchronous jaisa dikhta hai. Error handling ke liye try/catch use karo.
💻 JavaScript — Async/Await
// ✅ Basic async/await
async function fetchUser(id) {
    const res = await fetch(`/api/users/${id}`);
    const user = await res.json();
    return user;
}

// Arrow async
const getUser = async (id) => {
    const res = await fetch(`/api/users/${id}`);
    return res.json();
};

// ✅ Error handling with try/catch
async function loadData() {
    try {
        const res = await fetch("/api/data");
        if (!res.ok) throw new Error(`HTTP ${res.status}`);
        return await res.json();
    } catch (err) {
        console.error("Failed:", err.message);
        return null; // Fallback
    } finally {
        console.log("Request complete");
    }
}

// Sequential vs Parallel
async function sequential() {
    const a = await fetch("/api/a"); // Wait...
    const b = await fetch("/api/b"); // Then wait... SLOW!
}

async function parallel() {
    const [a, b] = await Promise.all([
        fetch("/api/a"),
        fetch("/api/b")
    ]); // Both at once! FAST!
}

// async always returns a Promise
async function getValue() { return 42; }
getValue().then(console.log); // 42
Common mistake: Using await in a loop creates sequential execution. Use Promise.all() with .map() for parallel execution instead.
5.4

Fetch API — GET, POST, headers, AbortController, response handling

Modern HTTP requests

fetch() is the modern replacement for XMLHttpRequest. Returns a Promise. Important: fetch only rejects on network errors — HTTP 404/500 are NOT errors! Always check res.ok. Use AbortController to cancel requests and implement timeouts.

Hindi mein samjhofetch() XMLHttpRequest ka modern replacement hai. Important: fetch sirf network errors pe reject hota hai — HTTP 404/500 errors nahi hain! Hamesha res.ok check karo. AbortController se requests cancel kar sakte ho.
💻 JavaScript — Fetch API
// ✅ GET request
async function getUsers() {
    const res = await fetch("https://api.example.com/users");
    if (!res.ok) throw new Error(`HTTP ${res.status}`);
    return res.json();
}

// ✅ POST request with JSON body
async function createUser(userData) {
    const res = await fetch("/api/users", {
        method: "POST",
        headers: { "Content-Type": "application/json" },
        body: JSON.stringify(userData)
    });
    if (!res.ok) throw new Error(`Failed: ${res.status}`);
    return res.json();
}

// ✅ AbortController — cancel requests
const controller = new AbortController();
fetch("/api/data", { signal: controller.signal })
    .then(res => res.json())
    .catch(err => {
        if (err.name === "AbortError") console.log("Cancelled");
    });
controller.abort(); // Cancel!

// ✅ Timeout wrapper
async function fetchWithTimeout(url, ms = 5000) {
    const controller = new AbortController();
    const timeout = setTimeout(() => controller.abort(), ms);
    try {
        const res = await fetch(url, { signal: controller.signal });
        return await res.json();
    } finally {
        clearTimeout(timeout);
    }
}
5.5

Parallel execution — Promise.all, allSettled, race, any

Running things concurrently

Promise.all() waits for ALL (fails fast). Promise.allSettled() waits for ALL (never fails). Promise.race() returns first to settle. Promise.any() returns first to fulfill. Choose based on your failure strategy.

Hindi mein samjhoPromise.all() sab ka wait karta hai (ek fail = sab fail). Promise.allSettled() sab ka wait karta hai (koi fail nahi). Promise.race() pehla settle hone wala return karta hai. Promise.any() pehla fulfill hone wala return karta hai.
💻 JavaScript — Parallel Promises
// ✅ Promise.all — all must succeed
const [users, posts, comments] = await Promise.all([
    fetch("/api/users").then(r => r.json()),
    fetch("/api/posts").then(r => r.json()),
    fetch("/api/comments").then(r => r.json())
]);
// If ANY fails → entire Promise.all rejects!

// ✅ Promise.allSettled — get all results, even failures
const results = await Promise.allSettled([
    fetch("/api/a"),
    fetch("/api/b"),
    Promise.reject("error")
]);
// [
//   { status: "fulfilled", value: Response },
//   { status: "fulfilled", value: Response },
//   { status: "rejected", reason: "error" }
// ]

// ✅ Promise.race — first to settle wins
const fastest = await Promise.race([
    fetch("/api/server1"),
    fetch("/api/server2"),
    new Promise((_, reject) =>
        setTimeout(() => reject("Timeout"), 5000)
    )
]);

// ✅ Promise.any — first to FULFILL wins
const first = await Promise.any([
    fetch("/cdn1/data"),
    fetch("/cdn2/data"),
    fetch("/cdn3/data")
]); // Fastest successful response
MethodResolves whenRejects whenUse case
Promise.all()All fulfillAny rejectsLoad all required data
Promise.allSettled()All settleNeverBest-effort loading
Promise.race()First settlesFirst rejectsTimeout patterns
Promise.any()First fulfillsAll rejectFastest mirror/CDN
5.6

Async error handling — patterns, retry logic, graceful degradation

Production-grade error handling

Wrap fetch calls in reusable error-handling wrappers. Implement retry with exponential backoff for flaky APIs. Use graceful degradation with fallback data. Never let unhandled rejections crash your app.

Hindi mein samjhoFetch calls ko reusable error-handling wrappers me wrap karo. Flaky APIs ke liye retry with exponential backoff implement karo. Graceful degradation se fallback data use karo.
💻 JavaScript — Async Error Patterns
// ✅ Reusable fetch wrapper
async function api(url, options = {}) {
    const res = await fetch(url, options);
    if (!res.ok) {
        const error = new Error(`HTTP ${res.status}`);
        error.status = res.status;
        error.response = await res.json().catch(() => null);
        throw error;
    }
    return res.json();
}

// ✅ Retry with exponential backoff
async function retry(fn, maxRetries = 3, delay = 1000) {
    for (let i = 0; i <= maxRetries; i++) {
        try {
            return await fn();
        } catch (err) {
            if (i === maxRetries) throw err;
            await new Promise(r => setTimeout(r, delay * 2 ** i));
        }
    }
}
// Usage: await retry(() => api("/flaky-endpoint"));

// ✅ Graceful degradation
async function loadWithFallback() {
    try {
        return await api("/api/live-data");
    } catch {
        console.warn("Using cached data");
        return JSON.parse(localStorage.getItem("cache")) ?? [];
    }
}
5.7

Advanced patterns — async generators, for-await-of, debounce/throttle

Real-world async patterns

Async generators (async function*) yield Promises, consumed with for await...of. Debounce delays execution until input stops. Throttle limits execution frequency. These are essential for search inputs, scroll handlers, and API rate limiting.

Hindi mein samjhoAsync generators (async function*) Promises yield karte hain, for await...of se consume hote hain. Debounce execution delay karta hai jab tak input band na ho. Throttle execution frequency limit karta hai.
💻 JavaScript — Advanced Async
// ✅ Async generator — paginated API
async function* fetchPages(url) {
    let page = 1;
    while (true) {
        const res = await fetch(`${url}?page=${page}`);
        const data = await res.json();
        if (data.length === 0) return;
        yield data;
        page++;
    }
}
for await (const page of fetchPages("/api/items")) {
    console.log("Page:", page);
}

// ✅ Debounce — wait until user stops typing
function debounce(fn, delay = 300) {
    let timer;
    return (...args) => {
        clearTimeout(timer);
        timer = setTimeout(() => fn(...args), delay);
    };
}
const search = debounce(query => fetch(`/search?q=${query}`), 300);

// ✅ Throttle — max once per interval
function throttle(fn, limit = 100) {
    let waiting = false;
    return (...args) => {
        if (waiting) return;
        fn(...args);
        waiting = true;
        setTimeout(() => waiting = false, limit);
    };
}
window.addEventListener("scroll", throttle(handleScroll, 100));

Callback to Promise conversion (Promisification)

Many older Node.js APIs use callback patterns (error-first callbacks). Wrap them in Promises to use with async/await. Node.js also provides util.promisify() for automatic conversion.

Hindi mein samjhoPurani Node.js APIs callback patterns (error-first callbacks) use karti hain. Unhe Promises me wrap karo taaki async/await ke saath use kar sako. Node.js me util.promisify() bhi hai automatic conversion ke liye.
💻 JavaScript — Promisification
// ✅ Manual promisification
function readFileAsync(path) {
    return new Promise((resolve, reject) => {
        fs.readFile(path, "utf8", (err, data) => {
            if (err) reject(err);
            else resolve(data);
        });
    });
}
const content = await readFileAsync("./data.json");

// ✅ Generic promisify helper
function promisify(fn) {
    return (...args) => new Promise((resolve, reject) => {
        fn(...args, (err, result) => {
            err ? reject(err) : resolve(result);
        });
    });
}

// ✅ Node.js built-in
import { promisify } from "node:util";
const readFile = promisify(fs.readFile);
const data = await readFile("./config.json", "utf8");

// ✅ Or use fs/promises directly (modern Node.js)
import { readFile } from "node:fs/promises";
const file = await readFile("./data.txt", "utf8");

Concurrency limiter — controlled parallelism

Promise.all() fires ALL requests at once. For 1000 URLs, that overwhelms the server. A concurrency limiter restricts how many run simultaneously. Essential for web scraping, batch processing, and API rate limits.

Hindi mein samjhoPromise.all() sab requests ek saath fire karta hai. 1000 URLs ke liye server overwhelm ho jaata hai. Concurrency limiter restrict karta hai kitne simultaneously run hain.
💻 JavaScript — Concurrency Control
// ✅ Process items with max concurrency
async function pMap(items, fn, concurrency = 5) {
    const results = [];
    const executing = new Set();

    for (const [i, item] of items.entries()) {
        const p = Promise.resolve().then(() => fn(item, i));
        results.push(p);
        executing.add(p);

        const clean = () => executing.delete(p);
        p.then(clean, clean);

        if (executing.size >= concurrency) {
            await Promise.race(executing);
        }
    }
    return Promise.all(results);
}

// Usage: fetch 100 URLs, max 5 at a time
const urls = Array.from({ length: 100 }, (_, i) =>
    `/api/item/${i}`
);
const data = await pMap(urls, url => fetch(url).then(r => r.json()), 5);

Event Loop puzzles — test your understanding

These puzzles test deep understanding of the event loop. The key is remembering: sync first → microtasks (all) → one macrotask → repeat. Microtasks scheduled during microtask processing run in the same cycle.

Hindi mein samjhoYe puzzles event loop ki deep understanding test karte hain. Key yaad rakho: sync pehle → microtasks (sab) → ek macrotask → repeat.
💻 JavaScript — Event Loop Puzzles
// Puzzle 1: What's the output?
console.log("start");
setTimeout(() => console.log("timeout1"), 0);
Promise.resolve()
    .then(() => console.log("promise1"))
    .then(() => console.log("promise2"));
setTimeout(() => console.log("timeout2"), 0);
console.log("end");
// Answer: start, end, promise1, promise2, timeout1, timeout2

// Puzzle 2: async/await ordering
async function foo() {
    console.log("foo start");
    await Promise.resolve();
    console.log("foo end"); // This is a microtask!
}
console.log("script start");
foo();
console.log("script end");
// Answer: script start, foo start, script end, foo end
// Because await pauses foo, rest of script runs first

// Puzzle 3: Nested promises
Promise.resolve().then(() => {
    console.log("1");
    Promise.resolve().then(() => console.log("2"));
}).then(() => console.log("3"));
Promise.resolve().then(() => console.log("4"));
// Answer: 1, 4, 2, 3
// Microtasks: [then1, then4] → run 1, schedule 2 → run 4
// Microtasks: [then2, then3] → run 2, run 3
