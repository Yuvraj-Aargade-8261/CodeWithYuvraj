2.1

Conditionals — if/else, ternary, switch, switch(true)

Making decisions

if/else is the basic conditional. Ternary (? :) is a one-line if/else for expressions. switch matches values with strict equality (===). Pro pattern: switch(true) evaluates conditions like if/else chains — cleaner for range checks.

Hindi mein samjhoif/else basic conditional hai. Ternary (? :) one-line if/else hai expressions ke liye. switch strict equality (===) se match karta hai. Pro pattern: switch(true) se range checks clean hote hain.
💻 JavaScript — Conditionals
// if / else if / else
const score = 85;
if (score >= 90) {
    console.log("A grade");
} else if (score >= 80) {
    console.log("B grade");  // ← This runs
} else if (score >= 70) {
    console.log("C grade");
} else {
    console.log("Below C");
}

// ✅ Ternary — expression (returns a value)
const age = 20;
const status = age >= 18 ? "Adult" : "Minor";
// Nested ternary (use sparingly!)
const tier = score >= 90 ? "A" : score >= 80 ? "B" : "C";

// ✅ switch — strict equality matching
const day = "Monday";
switch (day) {
    case "Saturday":
    case "Sunday":
        console.log("Weekend! 🎉");
        break;
    case "Monday":
        console.log("Start of week");
        break;
    default:
        console.log("Midweek");
}

// ✅ switch(true) — clean range checking
switch (true) {
    case score >= 90: console.log("A"); break;
    case score >= 80: console.log("B"); break;
    case score >= 70: console.log("C"); break;
    default: console.log("F");
}

// Guard clause pattern — return early
function processUser(user) {
    if (!user) return "No user";
    if (!user.active) return "Inactive";
    return `Processing ${user.name}`;
}
Guard clauses eliminate nested if/else. Return early for invalid cases, then handle the "happy path" at the end. This is the #1 pattern for cleaner JS code.
2.2

Loops — for, for...in, for...of, while, do-while, break/continue

Iterating through data

for is the classic counter loop. for...of iterates values (arrays, strings, maps). for...in iterates keys (objects — avoid for arrays!). while/do-while for condition-based loops. break exits, continue skips to next iteration.

Hindi mein samjhofor classic counter loop hai. for...of values iterate karta hai (arrays, strings). for...in keys iterate karta hai (objects ke liye — arrays me avoid karo!). break loop exit karta hai, continue next iteration pe skip karta hai.
💻 JavaScript — Loops
// Classic for loop
for (let i = 0; i < 5; i++) {
    console.log(i); // 0, 1, 2, 3, 4
}

// ✅ for...of — iterate VALUES (arrays, strings, maps, sets)
const fruits = ["apple", "banana", "cherry"];
for (const fruit of fruits) {
    console.log(fruit); // "apple", "banana", "cherry"
}

// for...of with index (using entries())
for (const [i, fruit] of fruits.entries()) {
    console.log(`${i}: ${fruit}`); // "0: apple", etc.
}

// for...of with strings
for (const char of "Hello") {
    console.log(char); // "H", "e", "l", "l", "o"
}

// ✅ for...in — iterate KEYS (objects only!)
const user = { name: "Alice", age: 25, city: "Mumbai" };
for (const key in user) {
    console.log(`${key}: ${user[key]}`);
}
// ❌ Don't use for...in on arrays! (iterates indices as strings)

// while loop
let count = 0;
while (count < 3) {
    console.log(count++); // 0, 1, 2
}

// do-while — runs at least once
let input;
do {
    input = prompt("Enter 'yes':");
} while (input !== "yes");

// break and continue
for (let i = 0; i < 10; i++) {
    if (i === 3) continue; // Skip 3
    if (i === 7) break;    // Stop at 7
    console.log(i); // 0,1,2,4,5,6
}

// Labeled statements (rare but useful)
outer: for (let i = 0; i < 3; i++) {
    for (let j = 0; j < 3; j++) {
        if (i === 1 && j === 1) break outer;
        console.log(i, j);
    }
}

2.3

Functions — declaration, expression, arrow, IIFE, defaults, rest

JavaScript's most powerful feature

Function declarations are hoisted. Function expressions are not. Arrow functions (=>) are concise, don't have their own this, and can't be used as constructors. Use default parameters for fallbacks. Rest parameters (...args) collect extra arguments into an array.

Hindi mein samjhoFunction declarations hoisted hote hain. Arrow functions (=>) concise hain, apna this nahi hota. Default parameters se fallback values de sakte ho. Rest parameters (...args) extra arguments ko array me collect karte hain.
💻 JavaScript — Functions
// ✅ Function Declaration — hoisted!
console.log(greet("Alice")); // Works! (hoisted)
function greet(name) {
    return `Hello, ${name}!`;
}

// Function Expression — NOT hoisted
// sayHi("Bob"); // ❌ ReferenceError
const sayHi = function(name) {
    return `Hi, ${name}!`;
};

// ✅ Arrow Functions (ES6+)
const add = (a, b) => a + b;           // Implicit return
const square = x => x * x;             // Single param: no parens
const log = () => console.log("Hi");   // No params
const multiLine = (a, b) => {          // Multi-line: needs return
    const sum = a + b;
    return sum * 2;
};

// Arrow returning object (wrap in parens!)
const makeUser = (name, age) => ({ name, age });

// ✅ Default Parameters
function createUser(name, role = "viewer", active = true) {
    return { name, role, active };
}
createUser("Alice");              // {name:"Alice", role:"viewer", active:true}
createUser("Bob", "admin");      // {name:"Bob", role:"admin", active:true}

// ✅ Rest Parameters (...args)
function sum(...numbers) {
    return numbers.reduce((a, b) => a + b, 0);
}
sum(1, 2, 3, 4); // 10

function first(a, b, ...rest) {
    console.log(a, b, rest); // 1, 2, [3, 4, 5]
}

// IIFE — Immediately Invoked Function Expression
(function() {
    const secret = "hidden";
    console.log(secret);
})(); // Runs immediately, creates private scope

// Arrow IIFE
(() => {
    console.log("Arrow IIFE!");
})();

// Functions are first-class citizens!
const ops = { add: (a,b) => a+b, sub: (a,b) => a-b };
const calc = (fn, a, b) => fn(a, b);
calc(ops.add, 5, 3); // 8

Arrow function gotcha: Arrow functions don't have their own this — they inherit from the enclosing scope. This is great for callbacks but breaks event handlers and object methods. Use regular functions for methods.
2.4

Scope & Closures — lexical scope, closure pattern, module pattern

The most important concept in JavaScript

Scope determines where variables are accessible. JS uses lexical (static) scoping — scope is determined at write-time, not run-time. A closure is when a function "remembers" variables from its outer scope even after the outer function has returned. This enables data privacy, memoization, and the module pattern.

Hindi mein samjhoScope decide karta hai ki variables kahan accessible hain. JS me lexical scoping hota hai — scope code likhte waqt decide hota hai. Closure tab hota hai jab function outer scope ke variables ko "yaad" rakhta hai even after outer function return ho chuka ho. Ye data privacy aur memoization ke liye use hota hai.
💻 JavaScript — Scope & Closures
// Scope chain: Inner → Outer → Global
const global = "I'm global";

function outer() {
    const outerVar = "I'm outer";

    function inner() {
        const innerVar = "I'm inner";
        console.log(innerVar);  // ✅ Own scope
        console.log(outerVar);  // ✅ Outer scope
        console.log(global);    // ✅ Global scope
    }
    inner();
    // console.log(innerVar); // ❌ Not accessible
}

// ✅ CLOSURE — function remembers its scope
function createCounter() {
    let count = 0; // Private! Only accessible via returned functions
    return {
        increment: () => ++count,
        decrement: () => --count,
        getCount: () => count
    };
}
const counter = createCounter();
counter.increment(); // 1
counter.increment(); // 2
counter.decrement(); // 1
counter.getCount();  // 1
// counter.count → undefined (private!)

// ✅ Closure for data privacy
function createWallet(initial) {
    let balance = initial;
    return {
        deposit: (amt) => { balance += amt; return balance; },
        withdraw: (amt) => {
            if (amt > balance) throw new Error("Insufficient funds");
            balance -= amt; return balance;
        },
        getBalance: () => balance
    };
}

// ✅ Closure with loops — classic interview question
for (var i = 0; i < 3; i++) {
    setTimeout(() => console.log(i), 100); // 3, 3, 3 (var!)  
}
for (let i = 0; i < 3; i++) {
    setTimeout(() => console.log(i), 100); // 0, 1, 2 (let!)
}

// ✅ Memoization via closure
function memoize(fn) {
    const cache = new Map();
    return (...args) => {
        const key = JSON.stringify(args);
        if (cache.has(key)) return cache.get(key);
        const result = fn(...args);
        cache.set(key, result);
        return result;
    };
}
const fastFib = memoize((n) => n <= 1 ? n : fastFib(n-1) + fastFib(n-2));
Interview gold: Closures are asked in 90% of JS interviews. The counter pattern and the var-in-loop bug are the two most common questions.
2.5

Higher-Order Functions — callbacks, map/filter/reduce, composition

Functions that work with functions

A higher-order function (HOF) takes a function as argument OR returns a function. map, filter, reduce are the big three. Function composition chains transformations. This is the foundation of functional programming in JS.

Hindi mein samjhoHigher-order function wo function hai jo function ko argument me leta hai ya function return karta hai. map, filter, reduce sabse important hain. Ye functional programming ka base hai.
💻 JavaScript — Higher-Order Functions
// Callback pattern
function fetchData(url, callback) {
    // Simulate async...
    setTimeout(() => callback({ data: "result" }), 1000);
}
fetchData("/api/users", (res) => console.log(res));

// ✅ Array.map — transform each element
const nums = [1, 2, 3, 4, 5];
const doubled = nums.map(n => n * 2);     // [2, 4, 6, 8, 10]
const names = users.map(u => u.name);     // Extract names

// ✅ Array.filter — keep matching elements
const evens = nums.filter(n => n % 2 === 0); // [2, 4]
const adults = users.filter(u => u.age >= 18);

// ✅ Array.reduce — accumulate into single value
const sum = nums.reduce((acc, n) => acc + n, 0); // 15
const max = nums.reduce((a, b) => a > b ? a : b); // 5

// reduce to build objects
const freq = ["a","b","a","c","b","a"].reduce((acc, ch) => {
    acc[ch] = (acc[ch] || 0) + 1;
    return acc;
}, {}); // { a: 3, b: 2, c: 1 }

// ✅ Chaining — map → filter → reduce
const result = nums
    .filter(n => n % 2 !== 0)    // [1, 3, 5]
    .map(n => n ** 2)             // [1, 9, 25]
    .reduce((a, b) => a + b, 0); // 35

// ✅ Function composition
const compose = (...fns) => x => fns.reduceRight((v, f) => f(v), x);
const pipe = (...fns) => x => fns.reduce((v, f) => f(v), x);

const addOne = x => x + 1;
const double = x => x * 2;
const transform = pipe(addOne, double); // (x+1) * 2
transform(5); // 12

// forEach — side effects only (no return value!)
nums.forEach((n, i) => console.log(`${i}: ${n}`));

2.6

Strings in depth — tagged templates, regex basics, advanced methods

Beyond basic strings

Tagged templates let you process template literal strings with a function — used in libraries like styled-components, graphql, and html literals. Regex basics: /pattern/flags for matching and replacing text. Know .match(), .search(), .matchAll().

Hindi mein samjhoTagged templates se template literal strings ko function se process kar sakte ho — styled-components jaise libraries me use hota hai. Regex pattern matching ke liye hai: /pattern/flags format hota hai.
💻 JavaScript — Advanced Strings
// ✅ Tagged Templates
function highlight(strings, ...values) {
    return strings.reduce((result, str, i) =>
        `${result}${str}<mark>${values[i] || ""}</mark>`
    , "");
}
const name = "Alice", role = "admin";
highlight`User ${name} is ${role}`;
// "User <mark>Alice</mark> is <mark>admin</mark>"

// ✅ Regex basics
const email = "user@example.com";
const emailRegex = /^[\w.-]+@[\w.-]+\.\w{2,}$/;
emailRegex.test(email); // true

// Common regex patterns
/\d+/.test("abc123");     // true (has digits)
/^[A-Z]/.test("Hello");   // true (starts with uppercase)

// .match() — returns matches
"Price: $42.99".match(/\d+\.\d+/); // ["42.99"]

// .replace() with regex
"Hello World".replace(/\w+/g, w => w.toUpperCase()); // "HELLO WORLD"

// .matchAll() — all matches with groups
const text = "dates: 2024-01-15, 2024-06-20";
const dates = [...text.matchAll(/(\d{4})-(\d{2})-(\d{2})/g)];

// String.raw — no escape processing
String.raw`C:\new\test`; // "C:\new\test" (no \n)
2.7

Error Handling — try/catch/finally, throw, custom errors

Handling the unexpected

try/catch/finally catches runtime errors. throw creates custom errors. Always throw Error objects (not strings!). Create custom error classes for domain-specific errors. finally always runs — perfect for cleanup.

Hindi mein samjhotry/catch/finally runtime errors catch karta hai. throw se custom errors banao. Hamesha Error objects throw karo (strings nahi!). Custom error classes domain-specific errors ke liye use karo. finally hamesha run hota hai — cleanup ke liye perfect hai.
💻 JavaScript — Error Handling
// ✅ try / catch / finally
try {
    const data = JSON.parse("invalid json");
} catch (error) {
    console.error(error.message); // "Unexpected token i..."
    console.error(error.name);    // "SyntaxError"
    console.error(error.stack);   // Full stack trace
} finally {
    console.log("Always runs!"); // Cleanup code
}

// ✅ throw — always throw Error objects
function divide(a, b) {
    if (b === 0) throw new Error("Division by zero");
    if (typeof a !== "number") throw new TypeError("Expected number");
    return a / b;
}

// ✅ Custom Error classes
class ValidationError extends Error {
    constructor(field, message) {
        super(message);
        this.name = "ValidationError";
        this.field = field;
    }
}

class NotFoundError extends Error {
    constructor(resource) {
        super(`${resource} not found`);
        this.name = "NotFoundError";
        this.statusCode = 404;
    }
}

// Catching specific error types
try {
    throw new ValidationError("email", "Invalid email");
} catch (e) {
    if (e instanceof ValidationError) {
        console.log(`Field: ${e.field}, Message: ${e.message}`);
    } else {
        throw e; // Re-throw unknown errors
    }
}

// ReferenceError — undefined variable

// RangeError — value out of range
