2.1

Arithmetic & Assignment Operators — +, -, *, /, %, compound assignment, overflow, type promotion

Arithmetic operators — what the CPU actually does

Arithmetic operators perform mathematical calculations, but in C they behave differently from regular math in critical ways. The most important gotcha: integer division truncates toward zero — 7 / 2 gives 3, not 3.5. The fractional part is silently discarded. The modulo operator % gives the remainder and only works with integers. Understanding how the CPU handles these operations at the hardware level — particularly overflow, division by zero, and implicit type promotion — separates beginners from professionals.

Hindi mein samjhoArithmetic operators math calculations karte hain, lekin C me ye regular math se alag behave karte hain. Sabse important gotcha: integer division zero ki taraf truncate hota hai — 7 / 2 = 3, 3.5 nahi. Fractional part silently discard ho jaata hai. Modulo % remainder deta hai aur sirf integers pe kaam karta hai. CPU in operations ko hardware level pe kaise handle karta hai — especially overflow, division by zero, aur implicit type promotion — ye samajhna beginners aur professionals me farak karta hai.
OperatorNameExampleResultCritical Notes

-Subtraction5 - 32Unsigned underflow wraps: 0U - 1 = UINT_MAX

Pre vs post increment — a deep dive

The difference between ++x and x++ matters when the result is used in an expression. Pre-increment (++x): increments first, then returns the new value. Post-increment (x++): returns the current value, then increments. In standalone statements (x++; vs ++x;), there's no difference. The distinction only matters inside expressions like assignments, function arguments, or conditions.

Hindi mein samjho++x aur x++ ka farak tab matter karta hai jab result kisi expression me use ho. Pre-increment (++x): pehle increment, phir naya value return. Post-increment (x++): pehle current value return, phir increment. Akele statement me (x++; vs ++x;) koi farak nahi. Farak sirf expressions ke andar dikhta hai — assignments, function arguments, ya conditions me.
💻 C — Pre vs Post increment explained
int a = 5;

/* Post-increment: use current value (5), THEN increment a to 6 */
int b = a++;   /* b = 5, a = 6 */

/* Pre-increment: increment a to 7 FIRST, then use new value (7) */
int c = ++a;   /* a = 7, c = 7 */

printf("a=%d b=%d c=%d\n", a, b, c);
/* Output: a=7 b=5 c=7 */

/* ═══ Common use case: loop iteration ═══ */
for (int i = 0; i < 10; i++) { }   /* Post: standard, most common */
for (int i = 0; i < 10; ++i) { }   /* Pre: identical here — no difference */

/* ═══ Where it MATTERS: array indexing ═══ */
int arr[5] = {10, 20, 30, 40, 50};
int idx = 0;
int val1 = arr[idx++];  /* val1 = arr[0] = 10, then idx becomes 1 */
int val2 = arr[++idx];  /* idx becomes 2, then val2 = arr[2] = 30 */
Undefined Behavior alert: Never use ++ on the same variable twice in one expression: x = x++ + ++x is UB — the result varies across compilers (GCC, Clang, MSVC may all give different results). The C standard says modifying a variable more than once between sequence points is undefined.

Integer overflow — the silent killer

Signed integer overflow is undefined behavior in C. When INT_MAX + 1 happens, the compiler is allowed to do anything — it might wrap around, crash, or even optimize away your overflow checks. Unsigned integer overflow is well-defined — it wraps around modulo 2^N (e.g., UINT_MAX + 1 = 0). This distinction is critical for writing safe, portable code.

Hindi mein samjhoSigned integer overflow C me undefined behavior hai. Jab INT_MAX + 1 hota hai, compiler kuch bhi kar sakta hai — wrap around, crash, ya overflow checks ko optimize karke hata de. Unsigned integer overflow well-defined hai — ye modulo 2^N wrap around karta hai (e.g., UINT_MAX + 1 = 0). Ye farak safe, portable code likhne ke liye critical hai.
💻 C — Safe overflow checking pattern
#include <stdio.h>
#include <limits.h>
#include <stdbool.h>

/* ❌ DANGEROUS: overflow check AFTER the operation */
/* The compiler may OPTIMIZE THIS AWAY because signed overflow is UB */
int bad_result = a + b;
if (bad_result < a) { /* Too late! UB already happened */ }

/* ✅ SAFE: check BEFORE the operation */
static inline bool safe_add(int a, int b, int *result) {
    if (b > 0 && a > INT_MAX - b) return false;  /* Would overflow */
    if (b < 0 && a < INT_MIN - b) return false;  /* Would underflow */
    *result = a + b;
    return true;
}

/* ✅ ALSO SAFE: use GCC built-in overflow detection */
int result;
if (__builtin_add_overflow(a, b, &result)) {
    fprintf(stderr, "Overflow detected!\n");
}

Assignment & compound assignment operators

Compound assignment operators combine an arithmetic/bitwise operation with assignment in a single step. They're not just shorthand — x += 5 evaluates x only once, while x = x + 5 evaluates it twice. This matters when x is a complex expression like arr[i++].

Hindi mein samjhoCompound assignment operators ek arithmetic/bitwise operation aur assignment ko ek step me combine karte hain. Ye sirf shorthand nahi — x += 5 me x sirf ek baar evaluate hota hai, jabki x = x + 5 me do baar. Ye tab matter karta hai jab x complex expression ho jaise arr[i++].

2.2

Relational & Logical Operators — Comparison, boolean logic, short-circuit evaluation, truthiness

C's truthiness model — everything is an integer

C has no native boolean type in C89. Instead, it uses a simple rule: 0 is false, everything else is true. This applies to all integer types, pointers (NULL = 0 = false), and floating-point values (0.0 = false). C99 added <stdbool.h> with bool, true, false — but these are just _Bool, 1, 0 under the hood. Relational operators always return exactly 1 or 0.

Hindi mein samjhoC89 me native boolean type nahi tha. Simple rule hai: 0 false hai, baaki sab kuch true hai. Ye sab integer types, pointers (NULL = 0 = false), aur floating-point values (0.0 = false) pe apply hota hai. C99 ne <stdbool.h> diya jisme bool, true, false hai — lekin ye internally _Bool, 1, 0 hi hain. Relational operators hamesha exactly 1 ya 0 return karte hain.
💻 C — Truthiness in action
/* In C, ALL of these are "true" in boolean context: */
if (1)     { }  /* true — non-zero integer */
if (-1)    { }  /* true — negative is still non-zero! */
if (42)    { }  /* true — any non-zero value */
if (3.14)  { }  /* true — non-zero float */
if (ptr)   { }  /* true — non-NULL pointer (idiomatic C) */
if ("hello") { }  /* true — string literal = non-NULL pointer */

/* Only these are "false": */
if (0)       { }  /* false */
if (0.0)     { }  /* false */
if (NULL)    { }  /* false — NULL pointer */
if ('\0')   { }  /* false — null character = 0 */

Relational operators (comparison)

Relational operators compare two values and return 1 (true) or 0 (false). The most dangerous bug in C history: if (x = 5) — this is assignment (always true, and changes x!), not comparison. The compiler may warn with -Wall, but many beginners miss this.

Hindi mein samjhoRelational operators do values compare karte hain aur 1 (true) ya 0 (false) return karte hain. C ki sabse khatarnak bug: if (x = 5) — ye assignment hai (hamesha true, aur x change ho jaata hai!), comparison nahi. Compiler -Wall se warn karta hai, lekin beginners miss karte hain.
OperatorMeaningExampleResultCommon pitfall

!=Not equal5 != 31 (true)

>Greater than3 > 50 (false)

The #1 C bug — = vs ==: if (x = 5) assigns 5 to x and evaluates to 5 (truthy) — always enters the if-block AND corrupts x! Defensive technique (Yoda conditions): write if (5 == x) instead — the compiler catches 5 = x as an error. Modern approach: use -Wall -Wextra which warns about assignment in conditions.

Logical operators & short-circuit evaluation

Logical operators combine boolean conditions. The critical feature is short-circuit evaluation — C guarantees left-to-right evaluation and stops as soon as the result is determined. In A && B, if A is false, B is never evaluated. In A || B, if A is true, B is never evaluated. This isn't just an optimization — it's a safety mechanism. You rely on it for null-pointer checks, bounds checking, and resource validation. Without short-circuit, half of C's idiomatic patterns would crash.

Hindi mein samjhoLogical operators boolean conditions combine karte hain. Critical feature hai short-circuit evaluation — C left-to-right evaluate karne ki guarantee deta hai aur jaldi result decide kar leta hai. A && B me agar A false hai toh B evaluate hi nahi hota. A || B me agar A true hai toh B nahi evaluate hota. Ye sirf optimization nahi — ye safety mechanism hai. Null-pointer checks, bounds checking, resource validation — ye sab short-circuit pe depend karte hain. Iske bina aadhe C idioms crash karenge.
OperatorNameShort-circuit ruleExamplePractical use
&&ANDStops if left is false (0)ptr && *ptr > 0Null-check before dereference
||ORStops if left is true (≠0)cached || fetch()Default/fallback values

💻 C — Short-circuit patterns (industry standard)
/* ═══ Pattern 1: Null-pointer guard (most common in C) ═══ */
int *ptr = get_data();
if (ptr != NULL && *ptr > 0) {  /* Safe: *ptr only if ptr is valid */
    printf("Value: %d\n", *ptr);
}

/* ═══ Pattern 2: Bounds check before array access ═══ */
if (idx >= 0 && idx < size && arr[idx] != 0) {
    /* arr[idx] is only accessed if idx is in bounds */
}

/* ═══ Pattern 3: Divisor validation ═══ */
if (divisor != 0 && dividend / divisor > threshold) {
    /* Division only happens if divisor is non-zero */
}

/* ═══ Pattern 4: Lazy resource initialization ═══ */
if (!initialized || needs_refresh()) {
    initialize();  /* Only calls needs_refresh() if initialized is true */
}

/* ═══ DANGER: Side effects in short-circuit ═══ */
int x = 0;
if (0 && (x = 42)) { }  /* x is STILL 0! The (x = 42) was never reached */
Interview question: "What's the output of int x = 0; if (1 || (x = 5)) printf("%d", x);?" Answer: 0 — because || short-circuits when the left side is true (1), so x = 5 never executes.

Bitwise Operators — &, |, ^, ~, <<, >> — hardware-level control, bitmask patterns

Why bitwise matters — it's how hardware works

Bitwise operators manipulate individual bits of integers. Every hardware register, network packet header, file permission, and graphics pixel is controlled through bit manipulation. In embedded C, you'll use these operators in every single function. In systems programming, bitmask flags are the standard pattern for combining multiple options into a single integer (like open(path, O_RDONLY | O_CREAT, 0644)).

Hindi mein samjhoBitwise operators integers ke individual bits pe kaam karte hain. Har hardware register, network packet header, file permission, aur graphics pixel bit manipulation se control hota hai. Embedded C me ye operators har function me use hote hain. Systems programming me bitmask flags standard pattern hai multiple options ko ek integer me combine karne ke liye.

The 4 essential bit manipulation patterns

💻 C — Bit manipulation patterns (must memorize)
uint8_t reg = 0b10110100;  /* 8-bit hardware register */

/* ═══ 1. SET a bit (turn ON) — use OR ═══ */
reg |= (1 << 1);    /* Set bit 1:  reg = 0b10110110 */
/* Pattern: reg |= (1 << bit_number) */

/* ═══ 2. CLEAR a bit (turn OFF) — use AND + NOT ═══ */
reg &= ~(1 << 2);   /* Clear bit 2: reg = 0b10110010 */
/* Pattern: reg &= ~(1 << bit_number) */

/* ═══ 3. TOGGLE a bit (flip) — use XOR ═══ */
reg ^= (1 << 4);    /* Toggle bit 4: reg = 0b10100010 */
/* Pattern: reg ^= (1 << bit_number) */

/* ═══ 4. CHECK a bit (read) — use AND ═══ */
if (reg & (1 << 5)) {
    printf("Bit 5 is ON\n");
}
/* Pattern: if (reg & (1 << bit_number)) */

Bitmask flags — the systems programming pattern

Bitmask flags let you combine multiple options into a single integer. Each option is a power of 2 (one bit). You combine them with | and check them with &. This is the pattern behind open() flags, fcntl() options, SDL_Init(), and thousands of C APIs.

Hindi mein samjhoBitmask flags se multiple options ko ek single integer me combine kar sakte ho. Har option ek power of 2 hai (ek bit). | se combine karo aur & se check karo. Ye pattern open() flags, fcntl(), SDL_Init() aur hazaaron C APIs me use hota hai.
💻 C — Bitmask flags (production pattern)
/* Define flags as powers of 2 (each gets one bit) */
#define PERM_READ    (1 << 0)   /* 0b001 = 1 */
#define PERM_WRITE   (1 << 1)   /* 0b010 = 2 */
#define PERM_EXECUTE (1 << 2)   /* 0b100 = 4 */

/* Combine flags with OR */
unsigned int perms = PERM_READ | PERM_WRITE;  /* 0b011 = 3 */

/* Check flags with AND */
if (perms & PERM_READ)    printf("Can read\n");
if (perms & PERM_WRITE)   printf("Can write\n");
if (perms & PERM_EXECUTE) printf("Can execute\n");  /* Not printed */

/* Add a permission */
perms |= PERM_EXECUTE;  /* Now 0b111 = 7 */

/* Remove a permission */
perms &= ~PERM_WRITE;   /* Now 0b101 = 5 */

/* ═══ Interview classic: bit tricks ═══ */

/* Check even/odd (faster than %) */
if (n & 1) printf("Odd\n");
else       printf("Even\n");

/* Check if power of 2 */
if (n > 0 && (n & (n - 1)) == 0) printf("Power of 2!\n");

/* Swap without temp variable (XOR trick) */
a ^= b; b ^= a; a ^= b;
Shift pitfalls: (1) Left-shifting into the sign bit of a signed integer is UB. Always use unsigned types for bit manipulation. (2) Right-shifting signed negative numbers is implementation-defined — it may fill with 0s (logical) or 1s (arithmetic). Use unsigned to guarantee logical shift.

Type casting — implicit vs explicit

Implicit casting (type promotion) happens automatically when mixing types. Explicit casting uses the cast operator (type). Always cast explicitly to make intent clear and prevent bugs.

Hindi mein samjhoImplicit casting (type promotion) automatically hota hai jab different types mix hote hain. Explicit casting me (type) operator use karte hain. Hamesha explicitly cast karo — intent clear rehta hai.
💻 C — Type casting
/* Implicit promotion (automatic) */
int a = 5;
double b = a;       /* int → double (safe, no data loss) */

/* Implicit truncation (DANGEROUS!) */
double pi = 3.14;
int x = pi;          /* ⚠️ x = 3 (decimal part LOST) */

/* Explicit cast (preferred — shows intent) */
int total = 7, count = 2;
double avg = (double)total / count;  /* 3.5 ✅ */
double wrong = total / count;        /* 3.0 ❌ (int division first!) */

/* Promotion hierarchy: char → int → long → float → double */
2.5

Conditional Statements — if, else-if, switch-case, ternary, dangling else, defensive patterns

if, else-if, else — and the dangling else trap

Conditionals let your program make decisions. if checks a condition; if true (non-zero), the block executes. else if adds alternative checks. else catches everything remaining. The dangling else trap: without braces, else binds to the nearest if. Industry rule: always use braces {} even for single-line if bodies — this prevents bugs when adding new lines later.

Hindi mein samjhoConditionals se program decisions le sakta hai. if condition check karta hai; true (non-zero) ho toh block execute hota hai. Dangling else trap: bina braces ke else nearest if se bind hota hai. Industry rule: hamesha braces {} lagao chahe ek line ka body ho — baad me naye lines add karne pe bugs prevent hote hain.
💻 C — if / else-if / else with defensive patterns
/* ═══ Standard grading system ═══ */
int score = 85;

if (score >= 90) {
    printf("Grade: A\n");
} else if (score >= 80) {
    printf("Grade: B\n");
} else if (score >= 70) {
    printf("Grade: C\n");
} else {
    printf("Grade: F\n");
}

/* ═══ DANGLING ELSE BUG ═══ */
/* This does NOT do what it looks like: */
if (a > 0)
    if (b > 0)
        printf("Both positive\n");
else                   /* ⚠️ THIS else binds to inner if, not outer! */
    printf("a is not positive?\n");  /* WRONG — prints when a>0 and b<=0 */

/* ✅ FIX: Always use braces */
if (a > 0) {
    if (b > 0) {
        printf("Both positive\n");
    }
} else {
    printf("a is not positive\n");  /* Now correct ✅ */
}

switch-case — rules, fall-through, and restrictions

switch compares one value against multiple compile-time integer constants. Key rules: (1) expression must be integer type — no floats, no strings. (2) case labels must be constant expressions (not variables). (3) Without break, execution falls through to the next case — this is sometimes intentional! (4) Always include default for robustness.

Hindi mein samjhoswitch ek value ko multiple compile-time integer constants se compare karta hai. Rules: (1) expression integer type hona chahiye — floats, strings nahi. (2) case labels constant expressions hone chahiye. (3) break ke bina execution next case me fall through karta hai — kabhi kabhi ye intentional hota hai! (4) Hamesha default include karo.
💻 C — switch-case with fall-through patterns
/* ═══ Standard switch with break ═══ */
char op = '+';
int a = 10, b = 3;

switch (op) {
    case '+': printf("%d\n", a + b); break;
    case '-': printf("%d\n", a - b); break;
    case '*': printf("%d\n", a * b); break;
    case '/':
        if (b != 0) printf("%d\n", a / b);
        else printf("Division by zero!\n");
        break;
    default:
        printf("Unknown operator: '%c'\n", op);
}

/* ═══ INTENTIONAL fall-through (grouping cases) ═══ */
switch (grade) {
    case 'A':
    case 'B':
        printf("Excellent!\n");  /* Handles both A and B */
        break;
    case 'C':
        printf("Good\n");
        break;
    case 'F':
        printf("Failed\n");
        break;
    default:
        printf("Invalid grade\n");
}
Fall-through bug: Forgetting break is the #1 switch-case bug. GCC's -Wimplicit-fallthrough flag warns about accidental fall-through. If you intentionally fall through, add a comment /* fall through */ to suppress the warning (GCC recognizes this comment).

Ternary operator — when to use and when NOT to

The ternary operator condition ? value_if_true : value_if_false is a compact if-else for simple value selection. Use it for assignments and return values. Never nest them — it becomes unreadable. If you need more than one ternary, use if-else instead.

Hindi mein samjhoTernary operator condition ? true_value : false_value simple value selection ke liye compact if-else hai. Assignments aur return values ke liye use karo. Kabhi nest mat karo — unreadable ho jaata hai. Agar ek se zyada ternary chahiye toh if-else use karo.
💻 C — Ternary (good vs bad usage)
int age = 18;

/* ✅ Good: simple value selection */
const char *status = (age >= 18) ? "Adult" : "Minor";

/* ✅ Good: inline in printf or return */
printf("Max: %d\n", (a > b) ? a : b);
return (err == 0) ? EXIT_SUCCESS : EXIT_FAILURE;

/* ❌ Bad: nested ternary — use if-else instead */
int result = (x > 0) ? ((x > 100) ? 100 : x) : 0;
/* ✅ Rewrite as: */
int result;
if (x <= 0)        result = 0;
else if (x > 100)  result = 100;
else               result = x;
2.6

Loops — for, while, do-while, break, continue, nested loops

Three types of loops

Loops repeat code blocks. for is best when you know the count. while when you have a condition. do-while when the body must execute at least once. Choose the right loop for readable, bug-free code.

Hindi mein samjhoLoops code blocks repeat karte hain. for jab count pata ho, while jab condition ho, do-while jab body kam se kam ek baar execute hona chahiye.
💻 C — All three loops
/* FOR loop — known iteration count */
for (int i = 0; i < 5; i++) {
    printf("%d ", i);  /* 0 1 2 3 4 */
}

/* WHILE loop — condition-based */
int n = 1;
while (n <= 100) {
    n *= 2;  /* Double until > 100 */
}
printf("n = %d\n", n);  /* 128 */

/* DO-WHILE — executes at least once */
int input;
do {
    printf("Enter 1-10: ");
    scanf("%d", &input);
} while (input < 1 || input > 10);
LoopCheckMin executionsBest for
forBefore each iteration0Known count, arrays
whileBefore each iteration0Unknown count, streams
do-whileAfter each iteration1Input validation, menus

break & continue

break exits the loop entirely. continue skips to the next iteration. Both work inside for, while, and do-while.

Hindi mein samjhobreak loop se bahar nikal jaata hai. continue current iteration skip karke next pe jaata hai.
💻 C — break & continue
/* break — exit loop early */
for (int i = 0; i < 100; i++) {
    if (arr[i] == target) {
        printf("Found at %d\n", i);
        break;  /* Stop searching */
    }
}

/* continue — skip odd numbers */
for (int i = 0; i < 10; i++) {
    if (i % 2 != 0) continue;
    printf("%d ", i);  /* 0 2 4 6 8 */
}

/* Nested loop with break */
for (int i = 1; i <= 5; i++) {
    for (int j = 1; j <= 5; j++) {
        if (j > i) break;
        printf("* ");
    }
    printf("\n");
}
/* Output:
 * 
 * * 
 * * * 
 * * * * 
 * * * * *  */
Infinite loop: while(1) or for(;;) runs forever. Always ensure there's a break condition inside. Used intentionally in embedded systems for main event loops.
2.7

goto, Scope & Storage Classes — auto, static, extern, register

goto — when it's acceptable

goto jumps to a labeled statement. It's generally avoided because it creates spaghetti code. The one acceptable use is for error cleanup in functions with multiple resource allocations (common in Linux kernel code).

Hindi mein samjhogoto labeled statement pe jump karta hai. Generally avoid karo — spaghetti code banta hai. Ek acceptable use: error cleanup jab multiple resources allocate kiye hon (Linux kernel me common hai).
💻 C — goto for error cleanup
int process_file(const char *path) {
    FILE *f = fopen(path, "r");
    if (!f) goto error_file;

    char *buf = malloc(1024);
    if (!buf) goto error_malloc;

    /* ... process data ... */

    free(buf);
    fclose(f);
    return 0;

error_malloc:
    fclose(f);
error_file:
    return -1;
}

Storage classes — lifetime, scope, and linkage

Storage classes determine three properties of every variable: lifetime (how long it exists in memory), scope (where in code it's accessible), and linkage (whether other translation units can reference it). Mastering these is essential for multi-file C projects — getting them wrong causes linker errors, name collisions, and subtle bugs that only appear in large codebases.

Hindi mein samjhoStorage classes har variable ki teen properties decide karte hain: lifetime (kitni der memory me rahega), scope (code me kahan accessible hoga), aur linkage (doosre translation units reference kar sakte hain ya nahi). static — the three meanings (interview favorite)

💻 C — static: three different meanings
/* ═══ Meaning 1: PERSISTENT local variable ═══ */
void counter(void) {
    static int count = 0;  /* Initialized ONCE at program start */
    count++;                  /* Retains value between calls */
    printf("Called %d times\n", count);
}
/* counter() → 1, counter() → 2, counter() → 3 */

/* ═══ Meaning 2: FILE-PRIVATE global variable ═══ */
static int internal_state = 0;  /* Only visible in THIS .c file */
/* Other .c files CANNOT access this — linker won't find it */

/* ═══ Meaning 3: FILE-PRIVATE function ═══ */
static void helper(void) {  /* Only callable from THIS .c file */
    /* Like "private" in OOP — encapsulation in C */
}

extern — sharing across files (multi-file projects)

extern declares that a variable or function exists in another file. It doesn't allocate storage — it tells the compiler "trust me, this symbol exists somewhere, the linker will find it." The standard pattern: define in one .c file, declare extern in a .h header.

Hindi mein samjhoextern declare karta hai ki variable ya function doosri file me exist karta hai. Ye storage allocate nahi karta — compiler ko bolta hai "bharosa karo, ye symbol kahi hai, linker dhundh lega." Standard pattern: ek .c file me define karo, .h header me extern declare karo.
💻 C — Multi-file extern pattern
/* ═══ config.h (header — shared declarations) ═══ */
#ifndef CONFIG_H
#define CONFIG_H

extern int debug_level;            /* Declaration only (no storage) */
extern const char *app_version;   /* Declaration only */
void init_config(void);            /* Function declaration (extern implicit) */

#endif

/* ═══ config.c (source — actual definitions) ═══ */
#include "config.h"

int debug_level = 0;                /* Definition (allocates storage) */
const char *app_version = "2.1.0"; /* Definition */

void init_config(void) {
    debug_level = 1;
}

/* ═══ main.c (uses the shared variables) ═══ */
#include "config.h"

int main(void) {
    init_config();
    printf("Version: %s, Debug: %d\n", app_version, debug_level);
    return 0;
}
The three meanings of static (interview must-know): (1) Local variable → persists between function calls, initialized once. (2) Global variable → private to this .c file (internal linkage). (3) Function → private to this .c file. All three are different! Know them all.
