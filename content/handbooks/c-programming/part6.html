🚀 Advanced Lens — Part 6

In C, YOU are the memory manager. There's no garbage collector — every byte you allocate must be freed. Understanding the stack vs heap distinction, memory allocation patterns, and file I/O is what separates C from all other languages. These skills are critical for embedded systems, OS development, and high-performance computing.

Hindi mein samjhoC me TUM memory manager ho. Koi garbage collector nahi — har byte jo allocate karo woh free karna padega. Stack vs heap, memory allocation patterns, aur file I/O samajhna C ko doosri languages se alag banata hai.
6.1

Stack vs Heap Memory — Two worlds of allocation

Memory regions in a C program

Every C program has 4 memory regions: Text (code), Data (globals), Stack (local variables, function calls), and Heap (dynamic allocation). Understanding which region your data lives in determines its lifetime and how it's managed.

Hindi mein samjhoHar C program me 4 memory regions hain: Text (code), Data (globals), Stack (local variables, function calls), Heap (dynamic allocation). Data kis region me hai ye uski lifetime aur management decide karta hai.

Data/BSSGlobal & static varsEntire programFixedFast

💻 C — Where does data live?
int global = 10;           /* Data segment */
static int s_var = 20;     /* Data segment */

void example(void) {
    int local = 30;          /* Stack — auto-freed when function returns */
    int arr[100];             /* Stack — 400 bytes on stack */

    int *heap = malloc(400);  /* Heap — YOU must free this */
    /* ... use heap ... */
    free(heap);               /* Heap memory returned to OS */
}

/* ⚠️ DON'T return stack pointers! */
int *bad_function(void) {
    int x = 42;
    return &x;  /* ❌ DANGLING POINTER — x is dead after return! */
}

/* ✅ Return heap pointer instead */
int *good_function(void) {
    int *x = malloc(sizeof(int));
    *x = 42;
    return x;  /* ✅ Caller must free this */
}
Stack overflow: Declaring int arr[1000000]; (4MB) on the stack will crash your program. Large arrays MUST go on the heap with malloc. Default stack size: Linux ~8MB, Windows ~1MB.
6.2

malloc & free — Dynamic allocation, sizeof, error checking

malloc — allocate heap memory

malloc(size) allocates size bytes on the heap and returns a void* pointer. It does NOT initialize the memory (contains garbage). Always check if malloc returns NULL (allocation failure). Always free when done.

Hindi mein samjhomalloc(size) heap pe size bytes allocate karta hai aur void* pointer return karta hai. Memory initialize NAHI hoti (garbage hota hai). Hamesha check karo ki NULL toh nahi mila. Kaam ho jaaye toh free karo.
💻 C — malloc & free
#include <stdlib.h>

/* Allocate a single int */
int *p = malloc(sizeof(int));
if (p == NULL) {
    fprintf(stderr, "malloc failed!\n");
    return 1;
}
*p = 42;
free(p);
p = NULL;  /* Prevent dangling pointer */

/* Allocate an array of 100 ints */
int n = 100;
int *arr = malloc(n * sizeof(int));
if (!arr) { perror("malloc"); exit(1); }

for (int i = 0; i < n; i++) {
    arr[i] = i * 10;  /* Use like a normal array */
}
free(arr);
arr = NULL;

/* Allocate a struct */
struct Student *s = malloc(sizeof(struct Student));
strcpy(s->name, "Yuvraj");
s->age = 21;
free(s);
Rule: sizeof(*ptr) is safer than sizeof(type). If the type changes, sizeof(*ptr) adapts automatically: int *p = malloc(sizeof(*p));
6.3

calloc, realloc & Memory Resizing — Zero-init, dynamic arrays

calloc vs malloc

calloc(count, size) allocates count × size bytes and initializes all to zero. This is safer than malloc for arrays and structs because there's no garbage data. Use calloc when you need zeroed memory.

Hindi mein samjhocalloc(count, size) count × size bytes allocate karta hai aur sab zero initialize karta hai. Arrays aur structs ke liye malloc se safe hai kyunki garbage data nahi hota.
💻 C — calloc vs malloc
/* malloc — NOT zeroed (garbage values!) */
int *a = malloc(5 * sizeof(int));
/* a[0..4] = garbage! Must initialize manually */

/* calloc — zeroed automatically */
int *b = calloc(5, sizeof(int));
/* b[0..4] = 0, 0, 0, 0, 0 ✅ */

/* calloc also checks for overflow in count × size */
size_t huge = SIZE_MAX;
int *c = calloc(huge, sizeof(int));  /* Returns NULL safely */

realloc — resize dynamic arrays

realloc(ptr, new_size) resizes a previously allocated block. It may move the data to a new location if needed. Critical: always assign realloc's return to a temp variable — if it returns NULL, the original pointer is still valid.

Hindi mein samjhorealloc(ptr, new_size) pehle se allocated block ka size change karta hai. Zaroorat ho toh data naye location pe move kar sakta hai. Important: realloc ka return temp variable me rakho — NULL mile toh original pointer valid rehta hai.
💻 C — Dynamic array with realloc
/* Growing array pattern */
int capacity = 4;
int size = 0;
int *arr = malloc(capacity * sizeof(int));

void push(int value) {
    if (size == capacity) {
        capacity *= 2;  /* Double capacity (amortized O(1)) */
        int *temp = realloc(arr, capacity * sizeof(int));
        if (!temp) {
            perror("realloc failed");
            free(arr);
            exit(1);
        }
        arr = temp;  /* ✅ Only update after success */
    }
    arr[size++] = value;
}

/* ❌ WRONG — loses original on failure */
arr = realloc(arr, new_size);  /* If NULL, original is LEAKED! */

6.4

Memory Management Patterns — Ownership, RAII in C, memory pools

Ownership rules

In C, every allocated block has an owner — the code responsible for freeing it. Clear ownership prevents leaks and double-frees. Three patterns: (1) caller allocates, caller frees, (2) function allocates, caller frees (document this!), (3) init/destroy pairs.

Hindi mein samjhoC me har allocated block ka ek owner hota hai — woh code jo free karne ke liye responsible hai. Clear ownership se leaks aur double-frees prevent hote hain.
💻 C — Ownership patterns
/* Pattern 1: Init/Destroy pair (most common) */
typedef struct {
    int *data;
    int size, capacity;
} IntVec;

void vec_init(IntVec *v, int cap) {
    v->data = malloc(cap * sizeof(int));
    v->size = 0;
    v->capacity = cap;
}

void vec_push(IntVec *v, int val) {
    if (v->size == v->capacity) {
        v->capacity *= 2;
        v->data = realloc(v->data, v->capacity * sizeof(int));
    }
    v->data[v->size++] = val;
}

void vec_destroy(IntVec *v) {
    free(v->data);
    v->data = NULL;
    v->size = v->capacity = 0;
}

/* Usage: always pair init + destroy */
IntVec nums;
vec_init(&nums, 8);
vec_push(&nums, 42);
vec_push(&nums, 99);
vec_destroy(&nums);  /* ✅ Clean */

/* Pattern 2: Cleanup with goto (Linux kernel style) */
int process(void) {
    char *buf1 = malloc(1024);
    if (!buf1) goto err1;
    char *buf2 = malloc(2048);
    if (!buf2) goto err2;

    /* ... do work ... */

    free(buf2);
    free(buf1);
    return 0;
err2: free(buf1);
err1: return -1;
}
Memory debugging tools: Use valgrind --leak-check=full ./program or gcc -fsanitize=address to catch leaks, use-after-free, and buffer overflows. These are mandatory in professional C development.
6.5

Text File I/O — fopen, fclose, fgets, fprintf, fscanf

File operations workflow

File I/O in C follows: Open → Read/Write → Close. Always check if fopen returns NULL. Always fclose when done. Use fgets (not gets!) for reading lines. Use fprintf for formatted output to files.

Hindi mein samjhoC me file I/O ka workflow: Open → Read/Write → Close. Hamesha check karo ki fopen NULL toh nahi return kiya. Kaam ho jaaye toh fclose karo. Lines padhne ke liye fgets use karo (gets KABHI nahi!).

💻 C — Text file I/O
/* Writing to a file */
FILE *f = fopen("output.txt", "w");
if (!f) { perror("fopen"); return 1; }

fprintf(f, "Name: %s\n", "Yuvraj");
fprintf(f, "Score: %d\n", 95);
fclose(f);

/* Reading from a file */
FILE *in = fopen("output.txt", "r");
if (!in) { perror("fopen"); return 1; }

char line[256];
while (fgets(line, sizeof(line), in)) {
    printf("Read: %s", line);
}
fclose(in);

/* Character-by-character reading */
int ch;
while ((ch = fgetc(in)) != EOF) {
    putchar(ch);
}
6.6

Binary File I/O — fread, fwrite, fseek, ftell, struct serialization

Reading & writing binary data

Binary files store data in raw format — no text conversion. fwrite dumps struct bytes directly to file. fread reads them back. fseek lets you jump to any position. This is how databases, image formats, and save files work.

Hindi mein samjhoBinary files data ko raw format me store karte hain — text conversion nahi. fwrite struct ke bytes seedha file me dalta hai. fread wapas padhta hai. fseek kisi bhi position pe jump kar sakta hai. Databases, images, aur save files aise hi kaam karte hain.
💻 C — Binary file I/O
struct Record {
    char name[50];
    int age;
    double salary;
};

/* Write structs to binary file */
struct Record employees[] = {
    {"Alice", 30, 75000.0},
    {"Bob",   25, 62000.0},
    {"Carol", 35, 88000.0}
};

FILE *f = fopen("data.bin", "wb");
fwrite(employees, sizeof(struct Record), 3, f);
fclose(f);

/* Read back */
FILE *in = fopen("data.bin", "rb");
struct Record r;
while (fread(&r, sizeof(r), 1, in) == 1) {
    printf("%s, %d, %.0f\n", r.name, r.age, r.salary);
}

/* Random access: jump to record #2 */
fseek(in, 1 * sizeof(struct Record), SEEK_SET);
fread(&r, sizeof(r), 1, in);  /* Bob */

/* Get file size */
fseek(in, 0, SEEK_END);
long file_size = ftell(in);
fclose(in);
FunctionPurposeReturns
fwrite(data, size, count, file)Write binary dataItems written
fread(buf, size, count, file)Read binary dataItems read
fseek(file, offset, origin)Move file cursor0 on success

Portability warning: Binary files with structs are NOT portable across platforms (different padding, endianness). For portable formats, use explicit serialization or libraries like Protocol Buffers.
6.7

Error Handling — errno, perror, strerror, return codes, assert

C error handling patterns

C has no exceptions. Errors are handled via return codes (0=success, negative=error) and the global errno variable. perror() prints a human-readable error. assert() catches programmer bugs during development.

Hindi mein samjhoC me exceptions nahi hain. Errors return codes (0=success, negative=error) aur global errno variable se handle hote hain. perror() readable error print karta hai. assert() development me programmer bugs pakadta hai.
💻 C — Error handling
#include <errno.h>
#include <string.h>
#include <assert.h>

/* Pattern 1: perror — prints "message: error description" */
FILE *f = fopen("nonexistent.txt", "r");
if (!f) {
    perror("Failed to open file");
    /* Output: "Failed to open file: No such file or directory" */
}

/* Pattern 2: errno + strerror */
int *p = malloc(SIZE_MAX);  /* Will fail */
if (!p) {
    fprintf(stderr, "Error %d: %s\n", errno, strerror(errno));
}

/* Pattern 3: Return code convention */
int read_config(const char *path, Config *out) {
    FILE *f = fopen(path, "r");
    if (!f) return -1;        /* Error: can't open */
    if (!parse(f, out)) {
        fclose(f);
        return -2;             /* Error: parse failed */
    }
    fclose(f);
    return 0;                 /* Success */
}

/* Pattern 4: assert for debugging */
void process(int *data, int n) {
    assert(data != NULL);    /* Crashes if NULL (debug only) */
    assert(n > 0);           /* Crashes if n ≤ 0 */
    /* Disabled in release: compile with -DNDEBUG */
}

Common interview questions — Memory & Files

These are frequently asked in C/systems programming interviews. Practice explaining each clearly.

Hindi mein samjhoYe C/systems programming interviews me baar baar poochhe jaate hain. Har ek clearly explain karna practice karo.
QuestionKey answer points
Stack vs Heap difference?Stack: auto, fast, limited, LIFO. Heap: manual, unlimited, slower, fragmentation.
What happens if you forget free()?Memory leak — program uses more and more RAM until crash/kill.
malloc vs calloc?calloc zeros memory, checks for overflow in n×size. malloc is raw bytes.
What is a dangling pointer?Pointer to freed memory. Set to NULL after free to catch early.
What is a memory leak?Allocated memory that's unreachable (no pointer to it). Can't be freed.
How to detect memory leaks?Valgrind, AddressSanitizer (gcc -fsanitize=address), or custom malloc wrappers.
"r" vs "rb" in fopen?"rb" disables text-mode newline translation (important on Windows: \r\n → \n).
Why use fgets over gets?gets has NO buffer limit → buffer overflow. fgets takes max size parameter.
✏️ Practice Exercises — Part 6
  1. Write a program that allocates an array with malloc, fills it, prints it, and frees it. Check for NULL.
  2. Implement a dynamic int vector (init, push, get, destroy) using realloc with doubling capacity.
  3. Compare malloc vs calloc: allocate 10 ints with each, print values before initialization.
  4. Write a program that reads a text file line-by-line and counts: lines, words, and characters (like wc).
  5. Create a student database: write 5 student records to a binary file, then read and display record #3 using fseek.
  6. Write a file copy program: read from source, write to destination. Handle all errors with perror.
  7. Build a program with intentional memory bugs. Use Valgrind or AddressSanitizer to detect and fix them.
