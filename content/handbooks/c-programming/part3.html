🚀 Advanced Lens — Part 3

In industry, functions are not just "reusable code blocks" — they're the unit of testing, documentation, and API design. Every function should do ONE thing, have a clear name, handle edge cases, and follow the Single Responsibility Principle. Understanding the call stack, calling conventions, and ABI is what separates someone who writes C from someone who understands it.

3.1

Function Basics — Declaration, definition, calling, return types, call stack

What is a function? — More than reusable code

A function is a named block of code that performs a specific task. It takes inputs (parameters), processes them, and returns an output (return value). But at the hardware level, a function call does much more: the CPU pushes arguments onto the stack, saves the return address, creates a new stack frame, executes the body, then pops the frame and returns to the caller. Understanding this stack mechanics explains why local variables disappear after a function returns, why recursion can overflow the stack, and why returning pointers to local variables is a bug.

Hindi mein samjhoFunction ek named code block hai jo specific kaam karta hai. Hardware level pe function call me CPU stack pe arguments push karta hai, return address save karta hai, naya stack frame banata hai, body execute karta hai, phir frame pop karke caller pe wapas aata hai. Ye samajhne se pata chalta hai kyun local variables function ke baad gayab ho jaate hain, kyun recursion stack overflow karti hai, aur kyun local variables ka pointer return karna bug hai.
💻 C — Function anatomy (declaration → definition → call)
/*  return_type  function_name(parameter_list) { body } */

/* 1. DECLARATION (prototype) — tells compiler the signature */
/*    Usually placed in a header file (.h) or before main() */
int add(int a, int b);    /* Parameter names are optional here */
int add(int, int);        /* Also valid — names omitted */

/* 2. DEFINITION — the actual implementation */
int add(int a, int b) {
    return a + b;          /* Return value goes into CPU register (eax/rax) */
}

/* 3. CALLING — pushes args, jumps to function, gets return */
int result = add(3, 7);  /* result = 10 */

/* ⚠️ Without declaration, calling a function before its definition
   causes "implicit declaration" warning (C89) or error (C99+) */

Return types, void functions, and error return patterns

Functions can return any type — integers, floats, pointers, structs (C99+). void means "no return value." The industry-standard error pattern: return an int status code (0 = success, negative = error) and pass the actual result through a pointer parameter. This is the pattern used in POSIX, Linux kernel, and embedded C APIs. It allows the caller to always check for errors before using the result.

Hindi mein samjhoFunctions koi bhi type return kar sakte hain. void ka matlab "koi return value nahi." Industry-standard error pattern: int status code return karo (0 = success, negative = error) aur actual result pointer parameter se pass karo. POSIX, Linux kernel, aur embedded C APIs me yehi pattern use hota hai.

💻 C — Error code pattern (industry standard)
/* ═══ Industry pattern: error code + output pointer ═══ */
int divide(int a, int b, int *result) {
    if (b == 0) return -1;  /* Error: division by zero */
    if (result == NULL) return -2;  /* Error: null pointer */
    *result = a / b;
    return 0;              /* Success */
}

/* ═══ Caller always checks the return code ═══ */
int quotient;
int err = divide(10, 3, "ient);
if (err != 0) {
    fprintf(stderr, "divide() failed with error %d\n", err);
    return EXIT_FAILURE;
}
printf("Result: %d\n", quotient);

/* ═══ DANGER: never return pointer to local variable ═══ */
int *bad_function(void) {
    int local = 42;
    return &local;  /* ❌ UB! local is destroyed after return */
}
Never return a pointer to a local variable! Local variables live on the stack and are destroyed when the function returns. The returned pointer becomes a dangling pointer — accessing it is undefined behavior. Use malloc() (caller must free()), static local, or pass a buffer from the caller.
3.2

Parameter Passing — Pass by value, simulating pass by reference, const

Pass by value (default in C)

C passes arguments by value — the function receives a copy of the variable. Modifying the parameter inside the function does NOT affect the original. To modify the original, pass a pointer (simulated pass by reference).

Hindi mein samjhoC me arguments by value pass hote hain — function ko variable ki copy milti hai. Function ke andar modify karne se original nahi badalta. Original badalne ke liye pointer pass karo.
💻 C — Pass by value vs pointer
/* ❌ Pass by value — original NOT modified */
void double_bad(int x) {
    x = x * 2;  /* Only modifies the copy! */
}

/* ✅ Pass by pointer — original IS modified */
void double_good(int *x) {
    *x = *x * 2;  /* Modifies the original via pointer */
}

int main(void) {
    int n = 5;

    double_bad(n);
    printf("%d\n", n);   /* Still 5 ❌ */

    double_good(&n);
    printf("%d\n", n);   /* Now 10 ✅ */

    return 0;
}

/* Classic: swap function */
void swap(int *a, int *b) {
    int temp = *a;
    *a = *b;
    *b = temp;
}

const parameters — promise not to modify

const in parameters tells the caller: "I will NOT modify your data." This is a contract that prevents bugs and enables compiler optimizations. Always use const for pointer parameters you don't intend to modify.

Hindi mein samjhoconst parameter me lagana caller ko bolna hai: "main tumhara data modify nahi karunga." Ye contract bugs prevent karta hai. Pointer parameters jo modify nahi karne, unpe hamesha const lagao.
💻 C — const parameters
/* ✅ const pointer — data is read-only */
int sum_array(const int *arr, int n) {
    int total = 0;
    for (int i = 0; i < n; i++) {
        total += arr[i];
        /* arr[i] = 0;  ← Compiler ERROR! const prevents this */
    }
    return total;
}

/* String functions always use const for input */
int str_length(const char *str) {
    int len = 0;
    while (str[len] != '\0') len++;
    return len;
}
3.3

Recursion — Base case, tail recursion, memoization, stack depth, when NOT to recurse

What is recursion? — The call stack perspective

A function that calls itself is recursive. Every recursive call creates a new stack frame (typically 16-64 bytes per call). For factorial(10000), that's ~640 KB of stack — enough to crash on most systems (default stack: 1-8 MB). Every recursive function MUST have: (1) a base case that stops recursion, and (2) a recursive case that moves toward the base case. Missing either → stack overflow.

Hindi mein samjhoJo function khud ko call kare woh recursive hai. Har recursive call ek naya stack frame banata hai (typically 16-64 bytes per call). factorial(10000) ke liye ~640 KB stack lagega — most systems pe crash (default stack: 1-8 MB). Har recursive function me chahiye: (1) base case jo recursion rok de, (2) recursive case jo base case ki taraf jaaye. Koi bhi miss ho → stack overflow crash.
💻 C — Factorial with stack visualization
/* Factorial: n! = n × (n-1)! */
long long factorial(int n) {
    if (n <= 1) return 1;      /* Base case — STOP here */
    return n * factorial(n - 1); /* Recursive case — moves toward base */
}

/* ═══ How the stack grows and unwinds ═══
   CALL PHASE (stack grows ↓):
   ┌─ factorial(4) ──── frame 1: n=4, waiting for factorial(3)
   │ ┌─ factorial(3) ── frame 2: n=3, waiting for factorial(2)
   │ │ ┌─ factorial(2)  frame 3: n=2, waiting for factorial(1)
   │ │ │ ┌─ factorial(1) frame 4: n=1, returns 1 (BASE CASE)
   
   RETURN PHASE (stack shrinks ↑):
   │ │ │ └─ returns 1
   │ │ └─ returns 2 * 1 = 2
   │ └─ returns 3 * 2 = 6
   └─ returns 4 * 6 = 24
   
   Total stack frames: 4 (one per call)
   Total memory: 4 × ~32 bytes = ~128 bytes */

Fibonacci — naive vs optimized (interview classic)

💻 C — Three Fibonacci implementations compared
/* ❌ NAIVE — O(2^n) time, O(n) stack space */
/* fib(40) makes ~330 million calls! */
int fib_slow(int n) {
    if (n <= 1) return n;
    return fib_slow(n - 1) + fib_slow(n - 2);
}

/* ✅ MEMOIZED — O(n) time, O(n) space */
/* Cache results to avoid redundant computation */
int cache[100] = {0};
int fib_memo(int n) {
    if (n <= 1) return n;
    if (cache[n] != 0) return cache[n];  /* Already computed? Return it */
    cache[n] = fib_memo(n - 1) + fib_memo(n - 2);
    return cache[n];
}

/* ✅ ITERATIVE — O(n) time, O(1) space — BEST */
int fib_fast(int n) {
    if (n <= 1) return n;
    int prev = 0, curr = 1;
    for (int i = 2; i <= n; i++) {
        int next = prev + curr;
        prev = curr;
        curr = next;
    }
    return curr;
}

Tower of Hanoi & when recursion IS the right tool

💻 C — Tower of Hanoi
void hanoi(int n, char from, char to, char aux) {
    if (n == 1) {
        printf("Move disk 1: %c → %c\n", from, to);
        return;
    }
    hanoi(n - 1, from, aux, to);
    printf("Move disk %d: %c → %c\n", n, from, to);
    hanoi(n - 1, aux, to, from);
}

/* hanoi(3, 'A', 'C', 'B'); → 7 moves (2^n - 1) */
When to use recursion vs iteration: Use recursion for tree traversals, divide & conquer (merge sort, quick sort), and problems with recursive structure (Hanoi, permutations). Use iteration for simple sequences (Fibonacci, factorial) and performance-critical loops. Rule: if the recursive depth could exceed ~10,000, convert to iteration or increase stack size with ulimit -s.
3.4

Header Files & Multi-File Projects — .h files, #include guards, linking

Why header files?

Real C projects have multiple .c files. Header files (.h) contain declarations (function prototypes, type definitions, macros) shared between files. The .c files contain the definitions (actual code). This separation is how large C projects (Linux kernel: 30,000+ files) stay organized.

Hindi mein samjhoReal projects me multiple .c files hoti hain. Header files (.h) me declarations (prototypes, types, macros) hote hain jo files ke beech share hote hain. .c files me definitions hoti hain. Linux kernel me 30,000+ files hain — tabhi ye separation zaroori hai.
💻 C — math_utils.h (header)
/* math_utils.h — Header file */
#ifndef MATH_UTILS_H    /* Include guard — prevents double inclusion */
#define MATH_UTILS_H

/* Function prototypes */
int add(int a, int b);
int multiply(int a, int b);
double average(const int *arr, int n);

/* Constants */
#define PI 3.14159265358979

#endif /* MATH_UTILS_H */
💻 C — math_utils.c (implementation)
/* math_utils.c — Implementation */
#include "math_utils.h"

int add(int a, int b) { return a + b; }
int multiply(int a, int b) { return a * b; }

double average(const int *arr, int n) {
    int sum = 0;
    for (int i = 0; i < n; i++) sum += arr[i];
    return (double)sum / n;
}
💻 C — main.c (usage)
#include <stdio.h>
#include "math_utils.h"  /* Our custom header */

int main(void) {
    printf("3 + 7 = %d\n", add(3, 7));
    return 0;
}
💻 Terminal — Compiling multi-file
# Compile all .c files together
gcc -Wall main.c math_utils.c -o program

# Or compile separately then link
gcc -c main.c -o main.o
gcc -c math_utils.c -o math_utils.o
gcc main.o math_utils.o -o program
#includeSyntaxSearch path
System headers#include <stdio.h>System include directories
Your headers#include "myfile.h"Current directory first, then system
Modern alternative: Instead of #ifndef guards, use #pragma once at the top of your header. It's non-standard but supported by every major compiler (GCC, Clang, MSVC) and is shorter.
3.5

Scope, Lifetime & Linkage — Local vs global, static across files, extern

Three dimensions of a variable

Every variable has three properties: scope (where it's visible), lifetime (when it exists), and linkage (whether other translation units can access it). Mastering these prevents name collisions and memory bugs in multi-file projects.

Hindi mein samjhoHar variable ki teen properties hain: scope (kahan visible), lifetime (kab tak exist kare), linkage (doosri files access kar sakti hain ya nahi). Multi-file projects me name collisions aur memory bugs rokne ke liye ye samajhna zaroori hai.
Variable typeScopeLifetimeLinkage
Local variableBlock { }Block executionNone
Static localBlock { }Entire programNone
Global variableFile + externEntire programExternal
Static globalFile onlyEntire programInternal (file-private)
Extern variableAll filesEntire programExternal
💻 C — extern across files
/* config.c — DEFINE the global variable */
int debug_mode = 0;  /* Definition (allocates memory) */

/* config.h — DECLARE for other files */
extern int debug_mode; /* Declaration (no memory) */

/* main.c — USE the shared variable */
#include "config.h"
if (debug_mode) printf("DEBUG ON\n");
Avoid globals! Global variables make code hard to test, debug, and parallelize. Use function parameters or structs to pass state. If you must use globals, make them static (file-private) whenever possible.

Practical examples

💻 C — stdlib.h & string.h essentials
#include <stdlib.h>
#include <string.h>
#include <ctype.h>
#include <time.h>

/* String to integer */
int num = atoi("42");       /* 42 */
double pi = atof("3.14");   /* 3.14 */

/* String operations */
char dest[50];
strcpy(dest, "Hello");      /* Copy */
strcat(dest, " World");     /* Concatenate → "Hello World" */
int len = strlen(dest);      /* 11 */
int cmp = strcmp("abc", "def"); /* negative (abc < def) */

/* Random numbers */
srand(time(NULL));         /* Seed with current time */
int dice = rand() % 6 + 1; /* 1-6 */

/* Character classification */
if (isdigit('5')) printf("It's a digit\n");
char upper = toupper('a');  /* 'A' */
Use strncpy not strcpy! strcpy has no bounds checking — buffer overflow risk. Always prefer strncpy(dest, src, sizeof(dest) - 1) in production code.
3.7

Variadic Functions — stdarg.h, va_list, building printf-like functions

What are variadic functions?

Variadic functions accept a variable number of arguments. printf is the most famous example. You create them using <stdarg.h> with va_list, va_start, va_arg, and va_end.

Hindi mein samjhoVariadic functions variable number of arguments accept karte hain. printf sabse famous example hai. <stdarg.h> ke va_list, va_start, va_arg, va_end se banate hain.
💻 C — Custom variadic function
#include <stdio.h>
#include <stdarg.h>

/* Sum any number of integers */
int sum(int count, ...) {
    va_list args;
    va_start(args, count);  /* Initialize after last named param */

    int total = 0;
    for (int i = 0; i < count; i++) {
        total += va_arg(args, int);  /* Get next int argument */
    }

    va_end(args);  /* Cleanup — REQUIRED! */
    return total;
}

int main(void) {
    printf("%d\n", sum(3, 10, 20, 30));  /* 60 */
    printf("%d\n", sum(5, 1, 2, 3, 4, 5));  /* 15 */
    return 0;
}
MacroPurposeMust call?
va_listType for the argument listDeclare it
va_start(args, last_named)Initialize after last named param✅ Always
va_arg(args, type)Get next argument of given typeIn loop
va_end(args)Cleanup resources✅ Always
Real-world use: Variadic functions power logging systems (log_debug("User %s logged in at %d", name, time)), error handlers, and formatted output across every C codebase.
Type safety warning: Variadic functions have NO type checking on the extra arguments. If you pass a double but va_arg reads an int, you get silent corruption. GCC's __attribute__((format(printf, 1, 2))) enables format-string checking for printf-like functions. Always use it for custom loggers.
✏️ Practice Exercises — Part 3 (Difficulty Graded)

🟢 Easy (Do these first)

  1. Write a swap(int *a, int *b) function and test it. Then write swap_bad(int a, int b) — prove that pass-by-value doesn't work for swap.

  4. Create a multi-file project: math_utils.h, math_utils.c, main.c. Add add(), multiply(), power(). Compile with gcc -Wall -Wextra.

🟡 Medium (Apply your knowledge)

  1. Implement three Fibonacci functions: naive recursive, memoized, and iterative. Time each for fib(40) using clock(). Which is fastest?
  2. Write a safe division function using the error-code pattern: int safe_div(int a, int b, int *result). Return 0 for success, -1 for div-by-zero, -2 for NULL result pointer. Test all error paths.
  3. Create a variadic max(int count, ...) function that returns the largest of N integers. Test with 2, 5, and 10 arguments.
  4. Write a static helper function in your utils.c — verify that main.c cannot call it. Explain why.

🔴 Hard (Challenge yourself)

  1. Implement Tower of Hanoi with a move counter. Verify the count equals 2ⁿ-1. Then add a static variable to track total moves across multiple calls.
  2. Write a my_printf(const char *fmt, ...) that supports %d, %s, and %c format specifiers. Don't use printf inside — use putchar() and puts().
  3. Create a function that deliberately returns a pointer to a local variable. Compile with -Wall and observe the warning. Fix it using (a) malloc, (b) static local, and (c) caller-provided buffer.
